# 玩家文案与内容表达

文案帮助玩家做选择：什么时候生效、会发生什么、付出什么、现在是否能用。风格保留书、卷、页、纸、笔、墨、印、批注和标点等意象；功能说明使用日常词语。页面与色彩遵循[开放式 UI](OPEN-UI.md)和[金丝水晶](ART-DIRECTION.md)。

## 名称与少量术语

保留具有辨识度的已有名称，如寒墨之书、千纸夜行、未完待续、无瑕落款。新名字可以有诗意，效果说明必须直白；同一名字在图鉴、奖励、图谱和记录中保持一致。

| 用语 | 玩家可理解的含义 |
| --- | --- |
| 咒典 | 游戏中的指南与内容查阅入口 |
| 词咒 | 道具或敌人头顶漂浮、可输入的单词 |
| 词令 | 菜单中可直接输入的英文操作指令 |
| 连笔 | 连续完成词咒形成的节奏与计数 |
| 共鸣／终式 | 积累共鸣后释放的法书强力技能 |
| 主术 | 亲手完成词咒时释放的主要法术 |
| 复写 | 使用已赚额度再制作一份法术；仍需说明费用和份额 |
| 储备 | 尚未用出的力量，按已有规则用于之后的法术 |

“词咒”是强制统一术语：所有道具、敌人头顶的漂浮单词都使用此称呼，不能在界面或有效设计中混称“咒文”“词牌”。“词令”只用于菜单指令，不与词咒互换。源代码标识、词库原始释义及历史归档不作机械替换。

这些术语在实际需要时通过指南和短提示解释，不要求玩家入场前背完整词表。生命、护盾、伤害、弹反、闪避、保存和回收直接使用常用词。技术文档中的资源类名、加工阶段和回执字段不进入玩家说明。

## 效果说明的颗粒度

默认按“触发条件 → 具体变化 → 代价或限制”表达；简单效果一两句即可。玩家不需要知道函数如何执行，但需要知道同一份力量是否已经用于别处。

| 避免的表达 | 清楚的表达 |
| --- | --- |
| 载体寿命增加 | 保存的法术多停留 3 秒 |
| 接受者满足传导条件 | 附近有带电的存留法术时 |
| 延伸传距 | 连锁距离提高 20% |
| 交付延迟 | 法术晚 1 秒释放 |
| 消耗一次有限场域份额 | 区域少作用一次 |
| 失去能力适配资格 | 当前没有可以保存的法术 |

表中数字只是写法示例，不修改实际内容参数。描述不暗示免费复制、无限回收或保证掉落；当一个效果减少主术直接伤害、延后释放或消耗储备时，应清楚说明。

条件分开表达：购买天赋需要什么、特殊遗物怎样解锁、效果在战斗中何时能用，是三件不同的事。不能用一句“条件不足”遮住所有原因。

## 详情、事件与记录

- 天赋详情只讲当前节点及其真实路径、条件与关联，不重复全局副书设置或整份已点亮清单。
- 遗物说明区分拥有该能力与实际增量；重复入口不会再发整份资源，参数改善应具体写出。
- 事件展示具体对象、实际价格、期限和结果。替换明确移除什么，借阅明确归还什么，抵押明确何时恢复；离开是清楚的行动。
- 战后记录描述实际发生的伤害、防御、回收和期限变化，不把理论可触发能力当作本局成绩。没有覆盖到的来源不伪造成完整统计。
- 技术失败日志可保留 ID 与诊断；玩家看到具体可理解的原因和可以采取的下一步。

## 数值、稀有度与图形

数值描述与正式效果共用事实来源，条件、上限、叠层与百分比口径一致。预览是当前情境估算，不能冒充每次实际扣血；候选升级显示取得后效果，已经持有的内容显示当前效果。精确公式可按需展开，主说明不堆内部计算细节。

普通、稀有、诅咒、觉醒使用明确文字与稳定排序；用途标签不替代稀有度。特殊节点的显著造型来自规则作用，不来自名称华丽程度。图形与说明在图鉴、选择页和图谱共用，禁止以 emoji 或含糊占位符代替独立图案。

## 审查方式

先读实际定义和执行结果，再核对文案；不要只检查句子通顺。重点检查触发条件、收益来源、代价、到期、重复机会和未解锁原因。检查范围按本次变化选择，见[验证说明](TESTING.md)。

候选卡是设计资料，可以包含内部概念和待校准值；进入玩家界面前仍需完成表达与实际效果的一致性审查。当前候选文案的登记不等于所有效果已经可用。
