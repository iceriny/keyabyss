# M2 实施经验与约束

本文整理 M2 单页战斗及其共用界面的实施经验，并保留可复用的评估与状态交接方法，区分产品约束、当前实现取舍和证据边界。**用户于 2026-09-29 确认验收合格，M2 正式结束。** 通用方法不改变该阶段的历史验收范围；实际接入范围见[阶段总结](../STAGE-SUMMARY.md)，代码入口见[实现快照](../TECHNICAL-SNAPSHOT.md)，未完成项只维护在 [TODO](../TODO.md)。

长期视觉要求维护在[金丝水晶](../ART-DIRECTION.md)，交互与布局维护在[开放式 UI](../OPEN-UI.md)。本文解释为什么形成这些约束，具体 UI 实施方法见 [UI 迁移实践](UI-IMPLEMENTATION-LESSONS.md)。数值、像素和时长属于当前实现参数，除非产品另有明确规定，不冻结为后续内容的通用常量。

## 1. 单页是完整体验的验收单元

M2 的经验是：一个页内需要贯通输入、施法、飞行、接触、受击、防御、召唤、死亡和结果，同时呈现战场比例、背景、HUD、声音与连续特效。不能以“规则接通”代替“战斗场景完成”，也不能把基础物理、锁定、蓄能、闪避或纸灵生命周期推迟。完整章节、正式段编排和远征内容按当前[实施方案](PLAN.md)推进；出生区域、冷区入场和位置分布是已有基础。

仅按文档和静态截图制作，曾丢失原版的攻击语义、物理反馈与整体气质。迁移前需要沿旧源码追踪触发、状态、费用、持续过程、中断与结束，再实际运行对应行为。旧 shader、绘制器、CSS、音效和素材调用都是证据，不能只读规则说明。浏览器限制不构成新平台上限；Godot 可以换算法与表现载体，但须保留行为意图和统一风格。更写实、更亮、粒子更多不自动意味着更好。

审美相关的材质、排版、配色和视觉组件由主控亲自设计、实现并看实际画面，不交给 Sol 再由主控返工。非审美任务只有边界独立、授权明确且确实节省工作时才委派。用户指出的“光晕”“金丝”“主脉”等具体对象需先映射到实际绘制层；调整一个层次的亮度，不应顺手扩写其他层的装饰密度。

## 2. 规则只有一个所有者，表现展示已提交事实

`BattleSession` 的固定步持有战斗时间、人工输入领取、资源支出、命中、死亡与页结果。UI 接受输入、显示状态，不能在特效回调或 Tween 结束时补扣伤害、发资源或决定胜败。共享 Resource 保存定义，每局余额和生命周期属于独立运行实例。

人工字符回执按身份领取一次；辅助完成、继承前缀、取消、派生攻击不生成第二笔人工收入。已经支付的法术冻结来源和额度，原目标死亡后按其语义有限收尾或改投，不依赖尸体节点存活。纸灵、连锁、溅射的视觉数量也不能反向制造收益。

词咒更新必须服从命中时序：完词支付后，主术持有被消费词咒；在途期间隐藏该词。主术命中仍存活目标后才分配新词，其他来源的受击不能抢先刷新；主术失效或被阻挡时按已有规则归还原词。入场与新词渐入，不能在输入最后一个字符时立刻换词，让玩家误以为已经命中。具体实现见 `battle_session.gd` 的词咒占用／释放、`battle_page.gd` 的显示时序及 `battle_word.gd` 的词咒组件。

## 3. 防御与四书不能用相似特效替代语义

| 对象 | 必须保留的行为 | 本轮纠偏经验 |
| --- | --- | --- |
| 远程弹反 | 实际来弹被反射，再经飞行和碰撞造成伤害 | 删除来弹后直接调度扣血，会丢掉反射轨迹、时间差与可观察因果 |
| 近战弹反 | 接触分离、即时反击、明显推离与恢复空间 | 只播光圈、只加一点速度或持续重叠，都不能提供弹反手感 |
| 闪避 | 实际位移、沿途残影、落点与无敌状态相符 | 预先把整条路径铺成几何图案不是移动演出；防御窗口按规则判定，不能由残影寿命控制 |
| 寒墨 | 穿刺途中仍保留主目标的追踪与完整主命中 | 前敌不能提前耗尽主目标命中或连续折减主伤害 |
| 灰烬 | 沿途碰撞与阻挡有真实作用 | 原版非冰枪弹道存在阻挡，不能为了“输入谁就打谁”统一改成穿透 |
| 纸灵 | 完词召唤、逐词增员至上限、灵动出击与返航，静默后消散 | 召唤物不能退化为一次性发弹计时器；存续时间与有限攻击额度分别管理，额度耗尽可盘旋，仍然存在不代表可无限攻击 |
| 交叉斩 | 两道锋利、方向明确的实际攻击轨迹 | 交叉形状的闪光不能替代接触判定，装饰分枝也不产生额外命中 |
| 普通／强化／终式 | 同书识别统一，轮廓、节奏和影响范围可区分 | 不只调颜色、放大同一团光；不能让金丝、元素效果和危险预警混为一层 |

取证入口包括旧 `ProjectileSystem`、`DefenseSystem`、`MovementSystem`、`SummonSystem`、纸灵 `behavior/flight` 和对应绘制器；当前实现位于 `game/session/`、`game/combat/`、`game/spells/` 与 `ui/battle_*`。保留玩法意图不要求复制旧轨迹或旧时间步。

近战伤害必须来自可预判的主动动作。靠近后固定攻击原点与方向，预警结束进入有限挥击，再恢复；身体接触只做分离。预警与判定共用扇形半径、夹角和真实单位半径，不能用中心点距离冒充圆形身体与扇形的相交。冻结、硬直和足够的击退中断动作；弹反成功也不应借用雷书电击作为通用收尾。

终式需要完整的持续状态，而非一段更亮的起手动画。当前 `BattleUltimate` 由固定步推进：冰域持续减速并分批发射冰枪，火域周期灼烧并落下陨火，雷暴在主术后追加落雷，纸灵终式补满召唤并缩短攻击间隔；各自的额度、时限和目标规则独立明确。共用入口支付一次、短时保护与近身清弹，持续期间停止共鸣增长；页间暂停并延续在途状态，远征结束再收束。表现节点读取真实中心、半径与寿命；指示器区分蓄能、就绪和剩余秒数，装饰停转不意味着规则暂停。

## 4. 接触、冲量与渲染位置必须讲得通

本轮选择的算法服务于小规模二维圆碰撞战斗，并非引入通用刚体引擎：

| 工具／方法 | 解决的问题 | 边界 |
| --- | --- | --- |
| `CombatGeometry` 相对运动圆扫掠 | 移动目标横穿、高速弹体和不同半径目标的首次表面接触 | 使用双方本步起止位置，候选按接触时间排序，同刻按稳定 ID；不能按敌人数组顺序决定先命中谁 |
| 质量加权冲量与位置约束投影 | 推动、持续接触、重叠与穿体 | 当前四次投影与小规模成对检测是实现选择，不预先增加空间索引或第二套节点物理权威 |
| `DampedMotion` 解析临界阻尼 | 受击形变、角色与镜头回弹 | 位移有上限，只改变表现，减少动态归零；不能用剧烈震屏遮掩接触错误 |
| `MotionTrail` 弧长裁剪与向心曲线 | 纸灵曲线、尾迹长短、头尾折返 | 先替换超前物理头再接插值头；只生成显示采样，不改变碰撞轨迹 |
| `soft_shapes.gdshaderinc` | 柔光、细线像素足迹与边缘抗锯齿 | 元素色、发光预算与画质成本留给调用材质，不将全部效果强行变成同一种形状 |

命中事件同时提供实际表面接触点与方向，光效从接触位置发出，受击回弹与冲量方向相符。不能把敌人中心当作所有撞击起点，也不能只有伤害数字而实体毫无反馈。

单位精灵和词咒抖动时，先检查显示链路：手动插值与 Godot 节点物理插值不能重复叠加；词咒、角色、危险层及镜头偏移读取同一渲染帧，不把文字留在固定步位置。连续运动控件关闭整像素吸附；不得通过模糊文字掩盖跳格。

## 5. 战场边缘是规则区域，不只是滤镜

外围冷区用于弱化 HUD 周边和尚未进入战场的单位。出生位置、目标登记、攻击与受伤资格、词咒显示、渐隐和柔焦应使用同一战场边界，避免未入场敌人“看起来在背景里，却能锁定、攻击和扣血”。当前边界宽度为 108 个设计像素，是可调实现参数。

**位置不能抹掉已经发生的交战。** 旧版 `Targeting` 与 `cold-zone.test.cjs` 保留敌人的有效锁定记录：点击、切换或输入选中有效战场内的敌人后，即使它被击退到边缘，取消锁定或完词也不撤销交战资格。仅按当前位置统一隐藏／禁伤会破坏这项语义。当前以 `combat_locked` 保存至死亡，输入回调收集锁定意图，固定步提交；`enemy_in_combat()` 统一目标登记、攻击与伤害资格，表现保留词咒与锁定标记。

敌人从种子决定的八向扇区及矩形外围分散进入，进入有效区域后才开放词目标。扩大窗口或换宽高比不会扩大规则战场，也不会把出生点改成紧贴玩家或随机覆盖 HUD。玩家闪避落点保持在有效区域。低画质保留冷区语义，不能只在高画质隐藏不可交互的外围信息。

冷区柔化作用于外围场景与实体，交战词咒、HUD 和危险信息保持清晰。战场中央不放与决策无关的长句事件播报；命中数字与短防御反馈就近出现，避免互相重叠、换行或推动常驻 HUD。

头顶释义不是把中文拼到英文下方即可。旧版 `WordLabelLayout` 与 `OverlayRenderer` 包含实际字宽测量、两行省略、选中排序、柔和阅读阴影、刻线、游标与释义色阶；旧设置还区分底部释义与头顶释义。当前 `BattleWord` 场景独立组织英文、中文与阅读材质，整块测量、渐入和避让；设置的 `show_meaning` 明确只控制头顶释义，底部施法提示独立。保留边缘词咒时还须检查其与 HUD 的关系，不能修复隐藏后又盖住生命读数。

## 6. 视觉问题先定位合成层，再选材质手段

- **矩形边界复发：** 首页修好的低频背景接缝曾在战场重现。共用无缝 `NoiseTexture2D` 与采样策略，检查整幅背景；不复制问题 shader 后分别调色掩盖。不把尚未证实的 GPU 精度或驱动猜测写成根因。
- **黑线与断层：** 飞行物实体、透明边缘、柔光、尾迹和屏幕折射是不同层。本轮全屏热畸变曾扭曲已合成的实体和柔光，形成断层；收束其受效范围才是修正方向。还需核对透明采样与 alpha 混合，不能遇到黑边就加大一圈圆形辉光。
- **尾迹与轮廓：** 连续收尖尾迹、横向柔化和克制粒子共同表达运动；原生 MSAA、shader 内部导数过滤、SVG mipmap 分别处理不同采样问题。多段粗线会出现梳齿，光芯必须为抗锯齿留边。
- **弹头、HDR与流体：** 清晰轮廓、光学尾迹与流体运动分别承担识别、发光和物质运动。光感不足先核对视口、混合与输出链，独立开关各层确认效果仍在；稳定空间长度的尾迹按位移保留历史，带状网格明确连接相邻截面并保持UV连续。方法与验证边界见[敌人与飞行物开发通用经验](../ENEMY-AND-BARRAGE-RESEARCH.md#12-敌人与飞行物开发通用经验)。
- **预警与光环：** 远程发射时的“半截线”来自明确绘制的短预警线，不是泛泛的渲染故障。预警形态应表达方向与时机；弹反使用柔和径向光环，不能拿锐利实心圆边冒充柔光。
- **材质层次：** 锁定角标、输入进度、蓄能、杖尖光、发射、命中与消退分别对应状态。增强单层必须复查整体层级，保持简约、干净、柔和且有细节；避免过度写实的烟团、噪声、浓重热扰动破坏统一语言。

金丝与水晶的经验单独落实在 [UI 迁移实践](UI-IMPLEMENTATION-LESSONS.md)：光晕的亮度与流转、金丝主脉、短淡分叉和错峰慢流光是不同调节对象。光晕太淡时应重塑光晕，不能删除它，也不能改成整页长枝和集中的高亮点。

## 7. 原生场景与共用工具按职责抽取

固定的页面、HUD 锚点、角色图形、投射物、纸灵、粒子及材质组合落为可编辑 `.tscn`；时序明确的入场用 AnimationPlayer。动态列表、数据绑定、生成与轨迹仍由脚本驱动。目标是在编辑器中能找到和调整视觉结构，不是机械地把每个变量变成节点。

复用工具从实际重复问题中提炼：接触几何、尾迹、阻尼、柔光、按键标记、页面壳、平滑滚动和晶面材质各自承担单一职责。材质预设 `.tres` 与引用的 shader 都是交付的一部分；运行时独立复制后写入参数，避免一个按钮改色或脉冲影响其他实例。查看具体资源名时仍需追踪真正的绘制来源，不能只改同名资源却漏掉页面层。

根工程文件是权威结果；编辑器未保存修改、MCP 运行时调参和生成预览副本都不等于交付。清理遵循仓库 `.delete/` 规则，保留用户 SVG 原稿和已有改动。

暂停、战败与胜利不是同一张提示框换标题。参考旧版的信息层级，原生场景分别承载即时状态、分组操作、结算读数和气氛；未接入数据使用空位，未实现操作禁用，不填造假的成长或错词记录。出征过场具有遮盖、建立战场、揭幕、开放规则与输入的明确交接；离开时取消待执行交接，书名不能在首页仍可见时抢先叠上。

原生下拉应保留 PopupMenu 的选择、滚动和输入处理。短列表通过不能证明长列表正确：Godot 4.7 的弹出最小尺寸在 `about_to_popup` 前计算，窗口最大尺寸需要两个维度有效，约束时还需收敛已有最小尺寸和当前尺寸。必须观察长分辨率列表实际窗口及滚动条，不能只检查 `max_size` 赋值。领域材质同样要核对场景合成顺序；负 `z_index` 可能把效果放到全屏背景背后，即便节点和 shader 都正常运行。

## 8. 输出分辨率与设置属于完整体验

1920×1080 是设计基准，1280×800 是旧项目参照；实际输出必须可调。设置统一管理自动模式、常见桌面分辨率、窗口／全屏与独立 UI 缩放。设计坐标、实际缓冲区、字体采样和鼠标命中变换分别核对，正文与 HDR 场景保持同一输出密度。

高分辨率不能只把低分辨率离屏画面放大；超宽屏扩展背景和留白，HUD 与有效战场保持合理中央范围。改音量等无关选项不重置手调窗口，暂停内改缩放不推进战斗或丢失词咒尺寸。代表性桌面比例的验证入口和现有预设见 [TESTING](../TESTING.md) 与实现快照，不新增移动端适配要求。

## 9. 警告、运行检查与视觉验收各有证据

调试器警告是需要处理的工程反馈。整数除法应明确截断／取整语义，不能一律改浮点而改变规则账；枚举变量保留枚举类型，外部整数转换在边界显式完成；局部命名避开 `Node.owner`、`name`、`CanvasItem.material`、`Control.scale` 等属性；三元分支保持兼容类型。不通过关闭警告或去掉类型标注获得“干净”输出。

`--check-only` 成功证明当前脚本可解析，**CLI 没有输出警告不等于编辑器静态诊断为空**。前一轮空诊断也不证明后续新增代码无警告。本轮最后两处对齐枚举和 `owner` 遮蔽已改源码并通过 CLI 解析；这项证据不扩写为新一轮编辑器零诊断。完整规则报告即使显示通过，也必须单独检查运行错误、退出资源在用与测试清理信息。

实际视觉以独立 Forward+ 窗口和正确转换的 HDR 图像判断；连续动作观察过程与中断，不能仅看静态截图。嵌入编辑器的显示缩放可能引入额外锯齿，缓冲区正确不等于最终窗口正确。测试、视觉与真人手感分别报告，失败记录不拼接成一次全通过；审美验收不能用“26 项通过”等数字代替。

## 10. 周期卡顿只按证据归因

目标机报告来自未运行 Godot 编辑器的独立 EXE，症状跨所有场景，约每秒一次；不能先归因于战斗或编辑器。已发现隐藏首页仍推进动画和 HDR 绘制，并修复可见性生命周期；这一发现不等于确认目标机周期卡顿根因。

## 11. 声音按事件身份与混音预算组织

旧音频文档、查询工具、原始素材和切片边界共同提供来源；不能只按文件名随意换声音。原件详情及有效切片 CSV 由工具生成，来源、时长和实际使用路径可追踪，入口见[音频索引](../audio/README.md)。同类变体避免连续重复，选择使用独立随机源，不改变战斗种子与规则轨迹。

落笔、普通／强化施法、命中、挥击预警、弹反共鸣和召唤须有可辨的事件层级；重要威胁有并发优先权，密集命中限频，结束声部短淡出，不靠叠更多长尾制造丰富感。峰值与声部数只证明没有超过当前混音预算，不能代替主观音色、疲劳感及跨设备响度评价。当前 14 声部上限和素材变体数量属于实现选择，不冻结为产品规则。

## 12. 模型评估、状态交接与验证方法

### 12.1 先明确目标，再选择调整手段

把目标写成可观察的行为，同时保留需要共同成立的条件。平均指标可能掩盖某一类输入、初始状态或使用路径完全失效，因此应按影响决策的条件分别评价。

区分产品规则、模型假设和可调参数。退出条件、状态保留、资源取得方式会改变结果的含义，应作为方案决策明确处理。参数调整则围绕已经确定的行为目标展开，避免为改善一个指标而悄悄改变业务语义。

### 12.2 对齐任务、单位与成本口径

外部研究或历史数据的端到端指标，通常已经包含识别、等待、切换、错误处理等成本。建立内部模型时，先识别指标覆盖的过程，再分配各项成本；已经计入的部分只计算一次。能够重叠发生的过程也不能一律按串行相加。

有效工作时间、真实经过时间和模拟时间应分别定义。产出率、工作量、等待、错误与恢复使用一致的分母，避免把调度能力当成实际吞吐。任务条件不同的数据，只能在说明转换依据后比较。

模型实现自检与来源有效性验证回答不同问题。先用可解释的简单场景检查实现尺度、输入输出归属和成本结算，再进入复杂流程；同时明确哪些参数来自证据、哪些属于尚未验证的假设。

### 12.3 调整数值前，先追踪状态与成本

当某个方案表现较弱时，沿完整生命周期拆分启动投入、稳态产出、切换损耗、等待、恢复和退出。局部效果成立，并不代表跨边界后仍能兑现；重复初始化或过早回收可能使系统反复支付启动成本。

先确认有效工作是否真正完成、状态是否在正确时机保留或消耗，再决定调整机制、数值还是使用策略。修正状态损耗后重新评价，避免用持续加大数值补偿生命周期错误。

评价同时保留结果和代价。达到目标但耗时过长、恢复成本过高或依赖很窄的条件，仍然包含需要判断的体验与可靠性问题。

### 12.4 将状态交接视为所有权迁移

宿主、页面或阶段结束时，分别决定哪些业务完成、哪些暂停、哪些继续、哪些明确取消。已经提交并支付的操作应按自己的完成条件收束，不能仅因展示宿主结束而自动失效。

| 交接维度 | 通用要求 |
| --- | --- |
| 身份 | 区分业务身份与容器内序号，避免接收端重新使用局部编号而误认旧对象；恢复路径应保持所需身份稳定 |
| 所有权与来源 | 交接处更新当前所有者，保留来源、已支付额度和幂等记录，防止拒绝合法结算或重复执行 |
| 时钟 | 明确绝对时钟、局部计时和暂停时间；保留到期依据，局部统计使用交接起点计算增量 |
| 容器与对象 | 容器快照与业务实体采用不同复制策略；共享容器可能被初始化清空，复制实体则可能产生第二份工作 |
| 宿主生命周期 | 接收端不依赖已销毁宿主；同时覆盖新建接收端和复用同一实例两种路径 |
| 持久化 | 明确运行内交接与重启恢复各自保证的内容，不能用内存引用的延续证明数据已经持久保存 |

交接验证应观察实际结果：原宿主销毁后工作仍能完成、既有投入只结算一次、初始化不会破坏快照，并且正常业务流程中的复制、保存和切换没有丢失状态。对象数量相同不足以证明这些条件成立。

### 12.5 回调重入需要明确的集合修改时机

遍历中的调用可能经事件、派生行为或回调重新修改同一集合。倒序遍历只能处理本循环自身的删除；其他调用删除多个元素、压缩或重排集合，仍可能使索引和待处理成员失效。

先追清调用链和集合的修改者，再选择统一提交、标记后移除或具有明确成员有效性规则的稳定快照。所选方式应保留即时失效、执行顺序和只处理一次的业务语义。单纯复制遍历容器，并不能自动解决成员已经失效的问题。

越界检查或捕获异常不能替代处理语义。优先用少量对象构造回调重入，在当前处理位置前后都放置受影响成员，验证真实副作用和执行次数，再补充必要的完整流程检查。

### 12.6 对照实验明确版本与覆盖范围

比较前固定会影响结果的模型、输入分布、策略和随机条件，保留源码版本、配置、命令与原始输出。一次改变多个因素只能解释组合效果；需要归因时，增加能够分辨原因的对照。

相同随机种子不保证相同动作轨迹。参数变化可能影响阈值决策，进而改变后续输入、资源取得和事件顺序；单条结果反转不足以推导普遍因果。独立留出的条件用于检查结论是否过度依赖已有样本。

区分独立样本、重复运行与共享前缀。不要把重复轨迹当成更多独立证据，也不要把异常运行的片段拼成一次完整通过。最后改动只由局部检查覆盖时，应明确检查了哪些分支，保留早期记录的真实版本归属。

### 12.7 联合判定验证结果

断言结果、进程退出、运行时诊断和退出清理分别检查。任何一项出现未解释的错误，都不能仅凭测试结尾或零退出码宣称通过。隔离场景、正式流程、实际体验和目标设备性能也应分别提供证据。

测试失败先判断来自产品实现、夹具假设、数据资格还是运行环境。定位问题发生的边界，避免为满足不成立的夹具而修改正确的业务规则。替代检查要说明实际覆盖，不能扩大成未执行入口的通过结论。

验证范围随真实风险和不确定性展开。优先运行最小而充分的现有检查；只在新改动、新失败或未解释现象出现时扩大或重复。异常退出保留首次条件与日志，复跑由具体疑点驱动，不无限重试直到出现成功结果。

### 12.8 工具链保留可诊断性与数据完整性

无人值守进程应有明确的错误退出和日志保存策略，避免停在交互式提示后持续消耗资源。停止前确认进程归属，保留首次错误及触发上下文；重复输出不能淹没真正原因。

文本跨进程、Shell和编辑工具时，显式约定编码、参数边界与转义方式。生成内容后先检查完整性，再提交编辑；生成失败、乱码或截断输出不能继续进入写入步骤。普通文本修改仍使用能够保留差异和撤销记录的编辑工具。

术语维护按语义划定作用范围，分别考虑用户语言、代码标识、持久化兼容和历史证据。批量替换前核对同形词与非目标含义，保留原始证据的可追溯性。长期结论进入维护文档，原始输出作为复查资料保存，二者职责分开。
