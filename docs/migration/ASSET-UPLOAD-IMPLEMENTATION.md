## 工具与日常操作

`tools/assets/assets.mjs` 处理固定提交、范围下载、离线核对、本地修改保护和批量安装回滚。源码与导入资源不修改；缓存不上传。LFS include 去重后按 12,000 字符分批，避免 Windows 命令行长度上限；所有下载完成才安装。

`tools/dev.mjs setup/pull/push` 把两个仓库的日常交接收敛为单命令。push 先上传资产及 LFS，再更新代码版本锁并提交推送；pull fast-forward 拉取代码并沿用准备范围。`capture.mjs` 从明确目录收集新增／变动文件，保护共享哈希别名；词库工具改为原生快照为默认输入。

真实双仓回归发现并修正两个问题：

- 新设备同步到新的 detached 资产提交后，本地 main 仍旧；直接 checkout main 再发布会产生分叉。发布前先 fast-forward 到已检查的 origin/main，并拒绝另有未发布资产提交。
- LFS 指针还原为实际字节时，工作区可能暂时报变化，但 clean 后暂存内容相同。是否建立提交改为检查 `git add` 之后的暂存差异，避免无变化交接失败。

初始测试夹具还暴露 no-checkout 的删除状态及 autocrlf 不一致；仅修正夹具准备方式。各失败及最终回归证据保留在 `.delete/dev-tests/`，没有通过放宽断言掩盖失败。
