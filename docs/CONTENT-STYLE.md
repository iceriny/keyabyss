# 玩家文案与内容表达

文案帮助玩家做选择：什么时候生效、会发生什么、付出什么、现在是否能用。风格保留书、卷、页、纸、笔、墨、印、批注和标点等意象；功能说明使用日常词语。页面与色彩遵循[开放式 UI](OPEN-UI.md)和[金丝水晶](ART-DIRECTION.md)。

## 名称与少量术语

保留具有辨识度的已有名称，如寒墨之书、千纸夜行、未完待续、无瑕落款。新名字可以有诗意，效果说明必须直白；同一名字在图鉴、奖励和记录中保持一致。

| 用语 | 玩家可理解的含义 |
| --- | --- |
| 咒典 | 游戏中的指南与内容查阅入口 |
| 词咒 | 道具或敌人头顶漂浮、可输入的单词 |
| 词令 | 菜单中可直接输入的英文操作指令 |
| 连笔 | 连续完成词咒形成的节奏与计数 |
| 共鸣／终式 | 积累共鸣后释放的法书强力技能 |
| 主术 | 亲手完成词咒时释放的主要法术 |
| 御术 | 把握来袭时机防御；成功免伤，完美防御还可反弹敌弹 |
| 章／页／段 | 远征的三级结构；每章三页，普通页内按段迎敌，章末页迎战守关者 |

“词咒”是强制统一术语：所有道具、敌人头顶的漂浮单词都使用此称呼，不能在界面或有效设计中混称“咒文”“词牌”。“词令”只用于菜单指令，不与词咒互换。源代码标识、词库原始释义及历史归档不作机械替换。

远征层级统一称“章／页／段”。界面、指南、资源说明和有效文档使用同一套名称；代码中既有`chapter`／`room`／`wave`标识及存档字段维持兼容。描述波形、冲击波、波动等非远征层级时沿用原意。

这些术语在实际需要时通过指南和短提示解释，不要求玩家入场前背完整词表。主动防御统一称“御术”，区分成功与完美防御；生命、护盾、伤害和闪避直接使用常用词。技术文档中的资源类名、加工阶段和回执字段不进入玩家说明。

## 效果说明的颗粒度

默认按“触发条件 → 具体变化 → 代价或限制”表达；简单效果一两句即可。玩家需要知道这件遗物怎样帮助当前战斗，不需要理解内部材料与加工账户。

| 避免的表达 | 清楚的表达 |
| --- | --- |
| 强化主术输出 | 直接施法伤害提高 25% |
| 延伸传距 | 连锁距离提高 20% |
| 获得复写加工能力 | 每完成 3 个词咒，向另一敌人复制一次法术 |
| 当前构筑资格不足 | 需要先取得指定的两件遗物 |
| 跨阶段资产连续性 | 保留当前遗物，进入下一难度 |

表中数字只是写法示例，不修改实际内容参数。描述不能暗示无限触发或保证掉落；真实存在的次数、持续时间、前置和代价需说清，不给直接增益虚构资源消耗。

区分遗物当前是否能获得、觉醒需要哪些局内前置，以及效果何时触发；不能用一句“条件不足”遮住所有原因。

## 详情、事件与记录

- 遗物详情说明当前效果、下一层增量与实际局内前置，不混入旧天赋许可。
- 路线展示付出的生命、恢复量、遗物机会或挑战；离开是清楚的行动。
- 成长说明只展示进度与自动增益；继续挑战说明下一难度和保留遗物，普通重开说明清空本局遗物。
- 战后记录描述实际输入、伤害和防御，不把理论可触发能力当作本局成绩。没有覆盖到的来源不伪造成完整统计。
- 技术失败日志可保留 ID 与诊断；玩家看到具体可理解的原因和可以采取的下一步。

## 数值、稀有度与图形

数值描述与正式效果共用事实来源，条件、上限、叠层与百分比口径一致。预览是当前情境估算，不能冒充每次实际扣血；候选升级显示取得后效果，已经持有的内容显示当前效果。精确公式可按需展开，主说明不堆内部计算细节。

普通、稀有、诅咒、觉醒使用明确文字与稳定排序；用途标签不替代稀有度。遗物图形表达实际作用，不靠名称华丽程度区分。图形与说明在图鉴、选择页和记录共用，禁止以 emoji 或含糊占位符代替独立图案。

## 审查方式

所有玩家文案在落笔前，先确定玩家此刻想知道什么、需要做什么，以及画面是否已经给出了答案。没有帮助当前操作或判断的信息就删去，不用文字复述明显的按钮、动画或进度。除词咒、御术、共鸣、终式及法书核心机制等必要名称外，使用日常词语；不要为了风格另造操作别名。

教程每次只教一个当前能尝试的动作，配一个能在场上操作的例子，再用简短结果说明效果。共用操作只在基础课教，法书课讲自身机制；精确公式、阈值和次要限制放入按需查看的详情。主说明解释为什么，当前目标说明做什么，两者不重复。虚线术语的悬浮入口只介绍一次，不在每步附相同说明。

同一动作内的提示随真实操作更新，不要求额外点击。进入另一种机制时由玩家选择下一步，避免限时阅读；等待只用于尚未发生的实际效果，期间允许操作、暂停、退出和重试，不加用于播放说明的强制延迟。提示放在动作附近或固定侧边，避开目标、词咒与危险区域；按钮表达行动，不再另写一遍操作说明。文案审阅要同时检查流程、场景与点击数量，不能只改句子。

先读实际定义和执行结果，再核对文案；不要只检查句子通顺。重点检查触发条件、收益来源、代价、重复机会和前置条件。检查范围按本次变化选择，见[验证说明](TESTING.md)。

基线原文用于核对玩法，进入玩家界面前仍需统一词咒术语、数值与实际效果。不能用旧名称下的新规则冒充已经恢复基线行为。
