# Godot 实施方案

目标是 Windows 原生打字肉鸽：四书、主动防御、重构前 Web 程度的局内遗物、简单路线、三章九页、五档及保留遗物的连续挑战，场外仅有少量线性成长。有效产品规则见[产品设计](../PRODUCT-DESIGN.md)，接手从[交接文档](AGENT-HANDOFF.md)开始；实际状态和未完成项分别维护在[阶段总结](../STAGE-SUMMARY.md)与 [TODO](../TODO.md)。

## 范围与实现基准

玩法基线为 Git 提交 `b713c6eea472f6c01d608710434e7daee407247f`。当前 `legacy/web/` 含后续构筑重构，不是整份恢复目标。旧代码用于核对内容定义、触发、状态、声音与体验，不移植 React、DOM、WebGL 或浏览器循环。

继续使用根目录 Godot、类型化 GDScript、原生 2D、Forward+／HDR 2D、现有字体和素材。主工程是活动定义的唯一来源；外部词库和音频按明确生成关系导入，不双维护 TS／JSON／TRES 规则。

取消大型天赋图、专属遗物许可、副书和形状配置、复杂加工网络、借还抵押与期限事件。旧 M3／M4 计划及完整记录见[归档](../archive/2026-10-08-build-system/README.md)，不继续其内容补全、全图与平衡义务。既有有用底座随保留玩法复用，不整仓回滚。

## 敌人与弹幕扩充

研究依据及已实装细则见[敌人专题](../ENEMY-AND-BARRAGE-RESEARCH.md)。首个可玩批次包含狙笔手、复诵者、护卷使及正式首见组合：保留既有输入、固定步、弹体扫掠与伤害入口，以精确威胁、两拍节奏和单目标护卫增加取舍。开场计入有限配额，入场后留出展示时间；混编按支援、区域和精确远程职责限制并发。

实施出口依次为规则／控制边界、四书真实输入与伤害、正式资源可达性、Forward+ 高低画质与减少动态，再结合真人正式遭遇评估难度与识别。尾迹批量绘制、Boss 主招重排与三个复杂候选属于后续选择，先证明瓶颈或新增决策价值。实际状态与剩余范围只维护在阶段总结及 TODO。

## 遗物玩法改造

目标：奖励同时具备内容广度、易懂收益与改变打法的机制。正式池扩充至97件：按实际效果统计，纯数值及手感参数31件（约32%），触发收益／防御资源14件、行为机制／跨书45件、觉醒7件。条件增伤、范围、速度、生命与闪避容量仍计入数值类，不用改标签虚增机制比例；不恢复同用途低收益的重复项。旧定义保留读取与既有实例编译能力。

实施顺序与验收：

1. 审计196件定义及真实消费链，保留复制、聚怪、传播、主动防御、长短词和四书特色，删除正式池内同用途低收益重复项。保留少量明确、足量的基础增益作为易懂选择。
2. 改造现有物件身份：行距尺奖励长短词交替；初版书奖励主动转火；复写纸让人工转火留下追击；双色合订本消耗状态换群体效果。寒墨提供主动破冰与雾中施法，灰烬提供集中引爆与转火传燃，雷鸣提供电链收束与闪避接续，纸灵提供印记接力与纸鹤协作。跨书感电来源须能独立产生收益。
3. 普通机制拿到即用，不先购买微小数值；觉醒保留明确分支，但前置缩为两件有独立用途的遗物。新派生限制触发来源、次数与传播深度，不伪造人工输入、不自动递归触发、不靠停笔无限输出。
4. 三选一在原有资格、稀有度及确定性随机基础上提供不同用途；优先保证一个改变行为的选项，避免同屏全是叠层和同用途加数值。正式获取继续遵循既有报价身份与保存事务。
5. 沿取得→编译→真实完词→接触→结算验证机制、无目标／孤立首领、复制与派生边界、跨页保存。检查受影响脚本；运行遗物目录、效果与必要的正式远征回归，统一进行有限场景收益对照。自动化不能代替真人乐趣与完整难度验收。

内容扩充按以下次序实施：先补12件有分量且不重复的数值／手感选项（护盾容量、终式时长、寒气、冰锥飞行、火雾范围、闪避火场、火浪、电爆伤害与范围、纸灵飞行与攻击等待、纸鹤拦截范围），再接回8件不同触发的收益（御术护盾、道具恢复、击杀共鸣、终式护盾、冻结护盾与共鸣、电链充能护盾、标记护盾、纸灵附加感电）。最后重做8件机制：强化冰锥首次命中分裂、御术留下寒气场、消耗火雾引爆、御术留下火雾、电链回击起点、御术引出电链、长词在目标处召纸鹤、纸鹤拦截后唤醒纸灵。沿用现有物件ID和图案，前置只保留真实需要的来源；长词纸鹤须词库包含长词。

新反应均有真实接触或输入前提；一次分裂、一次电链收尾和单只纸鹤拦截只结算一次，辅助输入不补造人工触发，派生不再次分裂或收尾。统一验证正式获取、数值上限的有效增量、真实效果和典型组合；不为每件遗物另写平衡脚本。

工作边界：本任务负责遗物定义、获取策略、构筑与战斗规则、对应测试及遗物文档；不修改其他Agent正在处理的页面、材质、交互式教程和其测试。表现复用已经存在的法术、状态、领域与事件，保持金丝水晶的物件身份。

参考：Supergiant的[Blood Price更新](https://www.supergiantgames.com/blog/hades-dive-into-the-blood-price-update/)将跨能力组合与武器改造并列提供；本项目借鉴“改变动作关系”的方向，具体触发仍围绕人工完词、目标选择和防御，不移植其操作系统。

### 定义与阅读共用边界

正式池按机制价值与实际用途维护；原有ID和跨书寒气、电链、纸灵等能力来源继续保留。退池内容仅承担旧实例、已发报价与历史读取，不以目录规模作为玩法完成指标。

定义、资格、编译与说明共用只读Resource。基础法书和已取得遗物提供能力，强化内容必须有可达来源；具体遗物前置支持多项与层数，分支支持互斥。拓扑从基础能力和无前置遗物展开，编译与正式获取共用规则，不以全部遗物的最终能力集合绕过自依赖。稀有度、法书偏好与构筑偏好仅调整合格候选权重。

新增收益采用有单位的原生参数与有限触发，沿当前固定步、命中、状态、防御和终式兑现，不另建规则解释器。常驻与条件增伤分别合并，持续控制、护盾、治疗和派生次数有共同上限；觉醒依赖成型分支，不能只靠一次幸运抽取完成构筑。无新增遗物时保留现有四书基础行为。

动态说明从同一参数和层数生成；奖励比较取得前后，图鉴和持有列表使用同一说明入口。正文术语悬浮解释是此次明确授权的UI行为，按住Alt展开奖励详情；固定标题和操作，正文滚动。颜色与文字共同表示稀有度，觉醒装饰对应本书元素，正文保持清晰并尊重减少动态。

性能独立验证机制与视觉等价，优先去掉重复编译、身份扫描和重复测量。目录覆盖、实际兑现、组合收益、画面与交互分开验收；不以目录数量或自动化通过替代真人整体均衡结论。

## 状态所有权与原生边界

| 边界 | 继续保留的职责 |
| --- | --- |
| `app/` | 服务组装、页面、出征、奖励和结果入口 |
| `game/input/` | 菜单／文本编辑／战斗归属、词进度、人工输入事实 |
| `game/session/` | RunSession 管页章、难度和连续远征；BattleSession 管唯一固定步与战斗结果 |
| `game/combat/`、`game/spells/` | 接触、伤害、状态、四书和有限派生；简化加工分支，不另建第二执行器 |
| `game/build/`、`game/content/` | 主书与遗物 Resource、构筑快照；共享定义不存局内次数或余额 |
| `game/progression/` | 局内奖励、简单路线支付、线性成长与一次结算 |
| `game/persistence/` | 原子保存、版本、失败恢复、普通／God 隔离 |
| `game/vocabulary/` | 词表解析、规范化、索引与用户词库；不加载外部可执行 Resource |
| `ui/`、`audio/` | 消费已提交状态，原生场景、材质、粒子与音频表现 |

人工输入只能记录一次，自动效果不能伪造输入；规则仍需要有限次数、持续时间、有效目标和页清理。额外增伤、周期复制与控制可直接依输入触发，不以共享守恒预算代替遗物收益。已有固定点数值可保留，只有取消系统不再需要的部分才随实施收缩。

## 时间、空间与表现

- 60 Hz 固定步负责规则，渲染与插值独立。Unicode 字符排除 echo；动作通过原生输入路由，单独 Shift 与 Shift+Tab 分开。
- 暂停停止战斗，界面保持响应；时缓期间输入、防御恢复和世界运动按实际效果分别处理，不误把所有时间一起缩慢。
- 实体使用稳定身份，创建／复用／瞬移重置插值。碰撞、反射和近战伤害不由视觉节点或信号顺序决定。
- 1920×1080 为设计基准，设置统一管理窗口、全屏和 UI 缩放；有效战场不随窗口宽高比改变。保持桌面键鼠目标。
- 金丝水晶、开放 UI、正文清晰层和减少动态继续有效。复用已有流体／光照工具，不把本次玩法收缩扩展成特效框架重写。
- 不预置通用 ECS、规则虚拟机、多线程战斗、云同步、录像或任意时刻续玩。

## 基于打字动力学研究的整体难度调整

本节使用[动态随机英文单词打字研究报告](../Research/typing_dynamics_research/report/research_report.md)，指导正式输入、遭遇、四书与连续挑战的难度调整。2026-10-15已接入研究驱动的探针并实施普通页并发、段进度及灭世补怪／伤害调整；采用参数与三轮证据见[收益与难度评估](../COMBAT-BALANCE-DESIGN.md)。研究作为已有输入使用，不重新开展文献核验或研究验证。未完成范围只维护在[TODO](../TODO.md#s3轻量成长与整体难度)。

普通页为两段，段按全灭推进，压力峰值由段内编排决定。段间保留飞行物，页／章结束清场并结清支付；章首与普通页采用不同强度的入场提示。研究探针沿用有限输入、固定取奖与真实积累路径，按新规则重新评估，当前参数与证据统一见[收益与难度评估](../COMBAT-BALANCE-DESIGN.md)。

目标是让玩家能持续完成“读词—输入—防御—再输入”，以输入投入、威胁组合与构筑收益形成五档差异。保持同类敌人的运动、弹速、攻击周期和完整预警一致；先调整遭遇供给与压力重叠，再调整耐久和容错。最高档继续要求积累，前四档不增加场外成长门槛。

### 研究如何映射到键渊

报告第4、15、16、17、22节给出本轮主要依据：预视改变可用吞吐；低速可预测运动的影响不等于持续阅读惩罚；词长会使标准WPM与完词次数朝不同方向变化；密度、遮挡和重新定位需要与输入同时考虑。

| 报告条件或结论 | 当前游戏的对应事实 | 调整含义 |
| --- | --- | --- |
| 动态任务允许预视下一词，空间移动可与当前输入重叠 | 多敌词咒同时可见，首字母互异；玩家还要选择威胁和道具 | 保留预读与转火空间；不能把所有可见敌人都当成纯干扰，也不能视为报告中有明确提示的单一目标 |
| 完词后才出现下一词时，吞吐明显下降 | 主术发出后原词进入等待，命中或结束后才恢复词目标；孤立Boss缺少替代目标 | 普通群战和单体Boss使用不同输入预算，记录飞行等待；不让四书的弹道差异变成未计价的额外难度 |
| 研究以空格提交，默认词尾退格修复 | 游戏末字自动施法，Space用于御术；错字不前进，Backspace放弃整词 | 采用游戏自己的有效人工字符与完词计分；不把研究CPM中的提交空格或退格成本直接加入游戏 |
| 长词摊薄词边界成本，但降低完词频率 | 每字符基础威力与每三次施法强化并存，状态、纸灵及遗物还有按词收益 | 按真实词长分布比较清场、强化、状态和防御；不能按同一WPM推算四书同等输出 |
| 识别后可以依靠记忆继续输入 | 输入中目标死亡仍可完成，已锁定目标退出边缘也保留交战资格 | 保留已有连续性，优先避免遮挡、突然跳位与无目标等待；不把减慢全部敌人作为主要解法 |
| 高能力情景更容易暴露视觉等待，疲劳项没有统一实证时刻 | 高档混编、远程预警与词咒争夺注意；九页与连续升档存在长时投入 | 高档增加可理解的战术组合，保留段间／页喘息；不设置“第八分钟起统一衰减”等规则 |

研究的无预视结果只作为另一种任务情景参考，不是游戏吞吐的严格下界；有预视结果也不是战斗中的保证速度。

### 曲线参数与调整依据

源码入口是`game/session/battle_session.gd`、`game/session/run_session.gd`、`game/content/encounters/`与`game/content/enemies/`。五档对玩家显示为启程、冒险、深渊、噩梦、灭世；既有评估中的故事／普通／困难／梦魇分别对应前四档。

| 参数 | 启程 | 冒险 | 深渊 | 噩梦 | 灭世 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通敌人基础生命倍率 | 0.72 | 0.90 | 1.24 | 1.42 | 5.30 |
| 基础伤害倍率 | 0.55 | 0.85 | 1.10 | 1.30 | 2.40 |
| 基础补怪间隔／世界秒 | 4.30 | 3.25 | 2.25 | 1.80 | 1.20 |
| 普通页在场绝对上限 | 6 | 8 | 8 | 12 | 14 |
| 无成长初始生命 | 155 | 125 | 110 | 100 | 90 |
| 基础闪避恢复／秒 | 3.60 | 4.20 | 4.80 | 5.30 | 5.80 |
| 受伤保护／秒 | 1.00 | 0.85 | 0.72 | 0.62 | 0.54 |

这些是公式基础值，实际还受章节、已完成段、补怪批量、遗物与周目影响，不能把间隔倒数直接当实际来敌速率。

1. **输入预算。** 报告初学者动态任务约1.56正确字母／秒，普通用户约3.91。探针以五种能力、有／无预视、词间停顿、错字和有限防御替代恒速无误输入；游戏中实际吞吐另行记录。
2. **积累门槛。** 基线灭世伤害6.0、补怪0.55秒，使四书普通输入的真实继承路径全部失败。降低失误代价和补充速度，保留5.3生命倍率形成处理需求；场外成长仍只增加最多20生命。
3. **并发边界。** 启程／冒险普通页封顶6／8，孵生与死亡分裂也受约束；上限限制阅读与威胁并发，不削减主页配额。
4. **页内进度。** 用完成段推进代替55世界秒内自动增压，清得慢不再额外触发这一层增长；不按实时WPM或玩家生命动态追涨。
5. **Boss与后期密度。** Boss采用独立生命、增援与主弹幕。此次完整路径覆盖Boss，但没有重编主招；后期弹体驻留和真人读词仍需专门观察，不能以自动通关替代体验结论。

### 输入与压力的共同度量

首先替换评估中的输入假设，不向正式游戏接入眼动／十指模拟器，也不增加强制打字测验或实时追涨难度。

| 能力情景 | 报告D条件正确字母／秒 | 有预视完整词／分 | 无预视完整词／分 | 游戏评估用途 |
| --- | ---: | ---: | ---: | --- |
| 初学者 | 1.56 | 15.5 | 13.6 | 启程与首章的低速覆盖 |
| 普通用户 | 3.91 | 38.7 | 28.7 | 冒险，以及积累后挑战高档 |
| 熟练者 | 5.19 | 51.5 | 36.4 | 深渊与中高档过渡 |
| 高水平高手 | 6.77 | 67.2 | 44.6 | 噩梦冷开与灭世门槛 |
| 顶尖情景 | 8.54 | 84.5 | 54.4 | 最高档快速输入压力检查，不作为普通玩家目标 |

数值由报告第15／16节直接引用或将字母／分除以60得到，属于模型能力情景的完成吞吐，不是现实人群均值或可直接配置的恒定击键间隔。`difficulty_probe_actor.gd`从端到端吞吐扣一次词间成本，派生词内按键间隔，再加入波动、错误后的重新按键、单词预视及有限防御。十个180秒纯输入夹具检查实现尺度，战斗通过正式输入路由；不把端到端速度当纯手速再重复叠加全部识别与纠错延迟。

当前探针提供3字符短词、7字符长词和25个3～7字符的混合词库；主矩阵使用混合词库，词长专项单列。保留合法候选等概率与首字母唯一规则，不按研究词频重排玩家词库。正式大词库、渐进分布与更长自定义词尚不能由这些小词库结果外推。

统一记录四类量：

- **输入投入：** 每分钟有效人工字符、完整人工词咒、错误、放弃损失、主动补全与道具输入；不能用辅助字符冒充手打。
- **输入机会：** 连续输入段长度、转火停顿、无合法词目标等待、防御前后恢复，以及这些时间在页中的位置。用能否完成当前词、是否需要保留进度来解释，不要求每个攻击间隔都足够从零输入一个长词。
- **战斗工作量：** 各敌种与Boss阶段的完词投入、页总字符、真实清页时间、实际生命损失和已抵扣护盾；完整页统计包含持续伤害、控制和群体收益。
- **威胁重叠：** 同时可读词咒、实际敌人数、威胁到达时刻、区域覆盖与弹体驻留；总弹数仅作辅助，不把一圈不会命中的弹当作同等数量的必防攻击。

输入与清页耗时按允许操作的真实时间计算，敌人行动和补怪仍按世界时间；暂停、奖励阅读剔除，完美防御产生的慢时间保留在真实战斗收益中。不能将世界秒里的补怪速率直接与真实秒里的输入速率相除。

初筛可用“来敌率×平均处理词数”估计需求词数／分，与相同构筑、场景的持续完成能力比较。普通持续段的首轮设计目标是留下约20%～35%的处理余量，短暂峰值可以更高，但其后必须有回落；这只是游戏候选目标，不是人体常数。群攻、治疗、孵生及控制使敌人处理成本不可简单相加，最终以真实遭遇的积压、清场和输入中断为准。已经使用包含防御的持续能力时，不再重复扣除同一份“防御折损”。

### 五档与九页的调整方向

五档不与报告五个人群档机械一一对应。灭世考察积累与打法，不能简单定义成“第五档必须达到顶尖手速”。

| 难度 | 主要服务情景与目标 | 采用规则 |
| --- | --- | --- |
| 启程 | 初学者能够读词、打完并逐步学会防御 | 普通页上限6，按段推进；保留首页单敌和现有预警，容许错误后继续完成词咒 |
| 冒险 | 普通输入水平可以体验完整九页和局内构筑 | 普通页上限8，逐章增加组合，后期不再由时间进度增至12个阅读对象 |
| 深渊 | 熟练输入加主动转火、防御与构筑选择 | 普通页上限8，按段推进；普通生命与完整配额保留 |
| 噩梦 | 高水平玩家可从初始成长空遗物开局，靠局内取得完成挑战 | 普通页上限10，按段推进；不引入强制刷取 |
| 灭世 | 快手空积累不能直接通关；普通／中等输入在合理积累后有机会 | 普通页上限14、生命5.3、伤害2.0、补怪1.5世界秒；以持续处理需求和构筑收益承担门槛 |

上限不是目标可见词数或每页必须填满的配额。五档召唤与分裂已纳入相同边界，Boss仍使用独立编排。

普通页分为两段，总配额按原公式的三分之二向上取整，每次击杀仍使用原定义经验，使用完成段对应的预定台阶；不依据实时WPM、生命或表现追涨。灭世放慢基础补充，让清除危险角色换来更长空位时间；普通页总量与段出口由规则检查保护。

九页按三次“入口—深处—Boss”形成锯齿曲线：入口给新组合的辨认空间，深处形成当章持续压力，Boss以阶段招式形成峰谷；下一章入口允许相对上一章Boss短暂回落。已有首见展示继续使用，后章通过职责组合升级，而非同步拉高敌人数、词长、血量和防御频率。词长保持玩家设置与既有渐进规则，不额外按章节强制拉长。

初次研究接入曾按三个冻结批次比较：基线、段进度／低档上限及灭世补怪1.2秒／伤害3.2、灭世伤害2.4及留出种子／词长专项。后续两段、首击追踪、反制概率与页章清场按自身冻结批次重新评估，当前补怪1.5秒的结果不能与早期未执行的同值候选混同。组合调整只能说明组合效果，不声称分离每个参数的因果贡献；具体范围见[收益与难度评估](../COMBAT-BALANCE-DESIGN.md)。

三轮均保留普通页主配额、普通敌人耐久及经验。低档实际页字符与耗时也受群攻、召唤和分裂影响，因此“保留配额”不等于所有战斗工作量严格相同。

### 四书、Boss与连续挑战

四书按相同输入情景、合法获取机会和遭遇比较，不统一成木桩DPS。纸灵检查低速下是否能启动、维持以及从段间回来；寒墨把控制换来的真实输入时间计入收益；灰烬观察延迟击杀与转火是否能减少后续威胁；雷鸣同时保留密集传播和孤立Boss的差异。减并发后需重看群攻价值，不能沿用旧密度下的每词收益。

Boss本体生命、帮手、主招完整预警与固定动作节奏保持；此次灭世伤害倍率也作用于Boss。完整路径记录Boss实际结果，但没有改造主招／区域技能的重叠或输入契约。若真人观察确认孤立Boss换词等待或后期弹幕影响读词，再按该具体问题处理。

最高档分别评价三条实际路径：初始成长空遗物直接开局、已有线性成长空遗物开局、从低档保留遗物升入。三者都允许沿途正常取得奖励；“空遗物冷开”不能误写成整局禁用遗物。前者使用高手与顶尖输入情景检验积累门槛，后者使用普通／中等输入与四书适配取奖检验可达性。采用预先声明的种子组与合法获取策略，报告成功、战败、耗时及失败原因，不只挑一条幸运路径。

线性成长先保留每1000字符增加4生命、最多20生命，只承担容错。升档保持一次性机会消费状态与成长快照，不重复发奖；当前最高档后每周目生命乘1.18、伤害因子为`1 + 0.08×loop`，后续根据成熟组合、满层后供给与实际耗时调整。升档与周目分别比较，不把二者重复叠加，也不靠无限血量把后期变成耐久消耗。无法同时实现冷开门槛与中速积累可达时，先定位缺少的有效构筑收益或遭遇压力，不扩大场外成长。

## 渲染准备与原生资源实施方案

2026-10-09 确定：在首屏等待期间集中完成着色器／场景准备，显示真实阶段与完成数量，出征等待实际战场准备完成后再开放输入。入口为轻量 `app/bootstrap.tscn`，复用 `DepartureRitual` 展示启动等待，准备完成后进入原有 `ArchiveGate` 欢迎与书库。出征使用同一等待反馈组件。用户自行体验流畅度，不做前后性能对比；工程验收限于相关脚本、资源、导出和必要运行路径。完成状态只维护在 [TODO](../TODO.md)，实际证据写阶段总结。

### 技术依据与范围

- 锁定 Godot 4.7.2、Forward+、HDR 2D 与 4× MSAA。官方 [管线指南](https://docs.godotengine.org/en/4.7/tutorials/performance/pipeline_compilations.html) 明确 2D Canvas 仍需首次真实绘制；`preload()`、隐藏节点和仅开启 Shader Baker 不能代替绘制准备。
- Shader Baker 将中间代码装入 PCK，最终驱动管线在玩家机器创建；需要有图形设备的导出，不能使用 `--headless`。检查正式资源可被烘焙插件发现，动态固定材质提取为实际使用的原生资源，不另维护烘焙专用副本。
- 原生化检查覆盖 `app/`、`ui/` 的固定节点、材质、粒子和动画配置：稳定声明迁入 `.tscn`／`.tres`；交互、状态绑定、程序化几何、固定步规则与 RenderingDevice 调度保留 GDScript，不机械迁移或改写玩法。
- 四条计算管线为流体、燃烧、冰晶生长与冰膜。提前在同一渲染设备创建，复用 shader／pipeline RID；实例独占纹理、缓冲区和 uniform set，不共享冰面生长状态。
- 引擎 shader／pipeline 缓存保持默认开启，不另造磁盘缓存，不保存永久“已预热”标志。每次进程按当前配置准备，缓存命中由引擎处理。

### 实施次序与接口

1. 盘点固定表现配置及动态创建入口，先提取正式共用场景／材质／粒子原型。参数随实例设置，禁止修改共享原型。
2. 建立原生等待反馈组件：阶段名称、已完成／总量、简洁进度；减少动态仍显示进展。重工作前先呈现状态，按批次跨帧处理，不用虚假计时进度掩盖未完成工作。
3. 首屏分阶段加载正式资源，在与正式渲染特征匹配的离屏视口真实绘制：通用 UI、战场基础、四书效果、道具爆发、粒子、屏幕采样与光照。视口强制更新，对象正常可见且位于视口内；不能仅把对象隐藏。资源和绘制任务均完成才放行首页。代表性粒子需实际发射。
4. 提前准备四条计算管线并复用，保留实例数据生命周期。通过渲染线程执行、完成回执回到主线程；不在主渲染设备调用 local RenderingDevice 的 `submit()`／`sync()`。
5. `DepartureRitual` 到交接点后等待实际 BattlePage 和必要补充准备，完成才揭幕、恢复物理步和打字输入；正常、减少动态、继续远征路径一致。预热不得推进真实战斗、消费道具、写记录或发出效果音。
6. 开启 Shader Baker，导出步骤使用真实图形设备；保留资源导入、成品 Boss 数据检查与许可复制。实测烘焙输出，不能以导出退出码单独证明全部管线覆盖。
7. 更新实现快照、工具链、验证说明、阶段总结和 TODO。收尾保留必要证据，临时废弃产物按根规则移入 `.delete/`。

## 全面性能优化

2026-10-15：针对当前高压低帧、反制长帧及冰霜终式反馈开展全面调查。本轮只交付研究与方案；新测量、源码成本地图和具体场景见[全面性能研究](../PERFORMANCE-RESEARCH.md)。旧算法优化章节继续解释已实施规则路径，其“不修改视觉”边界属于旧专项，不限制这次覆盖CPU、GPU、表现、UI、生命周期与跨设备表现的全面优化。工作状态只维护在[TODO](../TODO.md#全面性能优化)。

### 目标与不变量

优先在相同画面与玩法下消除浪费，使当前机器高压保持60FPS以上，并让中低档桌面设备有可验证的运行预算。研究建议常规场景争取120FPS，高压p95≤16.67ms；各设备档、事件尖峰和长时指标以研究报告的验收表为起点，第一阶段固定可访问设备和代表场景。

保留60Hz规则、扫掠接触、输入归属、事件顺序、伤害／资源／RNG、遗物与跨页状态、慢时／暂停语义。画面保持当前金丝水晶、冰晶弧面与连膜、火焰、柔光、尾迹及九类敌弹的识别语言。允许优化承载方式和装饰成本分配，不以少生成敌人、删弹、减伤、减少预测范围或隐藏危险信息达标。关闭视觉层只作诊断，不能交付为高画质优化。

## 战斗算法优化

2026-10-10：先在 GDScript 内减少历史对象扫描、重复集合构造和不必要的排序；自动闪避作为独立热点，按实测决定是否引入 .NET 纯计算核。空间索引留到低成本优化后评估，不整体重写战斗系统。

本节规定碰撞、索敌、命中、范围查询及自动闪避的 CPU 优化边界；实际取舍和验证见[实施记录](COMBAT-ALGORITHM-IMPLEMENTATION.md)。视觉效果、资源、渲染质量、固定步频率及玩法参数保持现状。不修改 `ui/`、shader、粒子、流体／冰火求解、尾迹采样或词咒布局；规则输出仍提供相同的轨迹、事件、接触位置和时钟。

### 判断依据

- `BattleSession.step()` 是规则推进的唯一入口；状态与法术、敌人移动及实体分离、己方弹道及纸灵、敌人攻击及敌弹按现有顺序执行。优化不能把不同阶段的状态合成一份整步不变的快照。
- `CombatGeometry.sweep_discs()` 已使用相对运动的连续圆扫掠和数值稳定的首次接触解，不以端点重叠检测替换。投射物按接触时刻、再按目标 ID 决定命中次序。
- 正式遭遇的常规刷怪上限最多为 24，但这不是全局硬上限：Boss 增援、孵化和死亡分裂通过 `_spawn_enemy()` 直接追加；`enemies` 还保留整页死亡对象。因此必须分别测量存活数 N 与整页累计数 M，不能把所有扫描都当成最多 24 次。
- 自动闪避已有预测预计算与非负评分剪枝，历史本机 256 弹选点中位 18.74ms、最大 21.73ms，32／128 弹分别为 1.51／9.00ms。原始记录为 [2026-10-09 研究](../../.temp/feedback-20261009/dodge-optimization-review.md)及[原始样本](../../.temp/feedback-20261009/dodge-optimization-raw.log)：Ryzen 7 3800X、headless、每组预热 5 次／采样 10 次、3 敌人和 3 危险区，另有 288 例选点一致性对照。这些只作为研究证据，不能据此报告当前 p95／p99 或固定步总成本；正式实施已重新采样。历史版本含冰场速度查询，当前 `_safe_direction()` 与 `_advance_threats()` 的 `pace` 都是 1.0，实施基准取开工时的源码，不恢复历史预测规则。

源码入口：[会话与推进](../../game/session/battle_session.gd)、[法术运行](../../game/spells/spell_runtime.gd)、[连续碰撞](../../game/combat/combat_geometry.gd)、[场范围](../../game/spells/spell_field.gd)、[危险区](../../game/combat/battle_hazard.gd)。下述复杂度分析来自静态代码，不是已测瓶颈占比。记 P 为己方弹数、R 为反射弹数、T 为敌弹数、F 为场数；普通敌弹主要对玩家及拦截物检测，并非全部执行 T×N 敌人配对。

### 源码核对与优先级

| 路径 | 当前成本与语义 | 优先处理 |
| --- | --- | --- |
| `enemy_by_id()`／`_living()` | 前者扫描累计 M，后者扫描并分配新数组；死亡对象仍可被表现与已付效果查询 | 页内 ID 索引保留死亡对象；纯存在／计数查询直接扫描短路，不全局替换快照语义 |
| `_advance_enemy_motion()` | 每个存活敌人再次调用 `_living()` 找加速光环；前面敌人已经移动，后面尚未移动 | 先去掉重复集合构造，保留顺序读实时位置；不能统一缓存整步距离 |
| `_resolve_bodies()` | N(N−1)/2 次扫掠，加四轮位置投影；轮间逆转遍历并处理玩家／边界 | 保留全配对与四轮；按当前端点做保守粗筛、投影先比较平方距离 |
| `_advance_projectiles()` | 每弹扫描 M，命中候选为 Dictionary，按时间／ID 全排序 | 单命中弹选最早接触；贯穿保留有序候选与逐次结算 |
| `_advance_threats()` | 普通弹对玩家、纸鹤／纸灵检测；反射弹额外找最近接触敌人 | 保留每弹推进、反射和拦截顺序；减少重复查找与无关场遍历 |
| `_nearby()`／`arc_targets()`／`retarget()` | 范围筛选、距离／ID 排序，多个调用者最终只取一个目标 | 单目标查询线性择优；范围连锁仍保留有序快照 |
| `_advance_states()`／`obscures()` | 敌人×场区域检测；烧伤可以同阶段致死并连锁，后续法术命中还会新增／合并场 | 优先按类型整理候选；场增删必须立即反映，不能缓存整步遮蔽结论 |
| `_safe_direction()` | 24 方向×最多 14 段×非反射敌弹数；评分带远距非零项 | 保留评分，优化数据布局与段级保守跳过；独立评估 .NET 批处理 |
| `clear_radius()` | `duplicate()` 后逐项 `erase()`，密集清弹可能形成二次成本 | 无回调的清弹入口可稳定线性压缩；不能顺手改写带连锁的敌弹推进循环 |

### 实施约束

查询结果的顺序就是部分规则：`_nearby()` 为距离平方／字符串 ID；普通投射物为接触时间／字符串 ID；反射弹、`_nearest_living()` 与纸灵择优则在相同时保留原遍历中的第一个。不能统一改为同一种 tie-break，也不能把 `enemy_10` 与 `enemy_2` 的字符串顺序改成数字顺序。

死亡连锁、塔盾解除和分裂生成在伤害提交时同步发生。带伤害的范围查询继续在原调用点形成结果快照，之后顺序提交；不会把这一步后续生成的对象补进原快照，也不会把全部伤害推迟到步尾。寒墨终式从已排序目标中随机取索引，改变集合顺序即使概率分布相同也会改变同一种子的结果。

自动闪避候选算法必须保留原评分和相同输入下的选点。真实时间与世界时间的分工、暂停及慢时间语义不动；命中仍在原固定步同步提交，不以降低更新频率换性能。

### 第一批：减少查询与临时集合

1. **ID 查找**：在 `BattleSession` 内增加 `Dictionary[StringName, BattleEnemy]`，由 `_spawn_enemy()` 同步登记，页初始化时清空；`enemy_by_id()` 从 O(M) 变为平均 O(1)。继续保留原 `enemies` 数组及其生成顺序、死亡对象和 `enemy_%d` 身份，不压缩历史数组，不在死亡时移除 ID 映射。已付效果、危险来源和表现层对死亡对象的查询不变。现有部分测试直接 `enemies.append/clear`，实施时同步改相关夹具的登记入口；不加“查不到就全表搜索”的永久兜底掩盖索引失配。
2. **存在／计数**：把 `_living().is_empty()`、`.size()`、`.filter(...).size()`、`.any(...)` 的只读调用分别改为早停、计数或匹配查询。刷怪批次内每次生成后立即更新本次批次的总数及类型数，保持相同 allowed 列表顺序与随机调用次数。Boss 受伤时的塔盾检查仍读当时存活与入场状态，不能只在固定步开头算一次。
3. **单目标索敌**：`retarget()`、`_periodic_copy()`、`_chain()` 每跳及普通电链的下一跳改为边过滤边取最优，O(M + K log K) 降为 O(M)，K 为范围候选数，不构造全量有序数组。保留各自半径、排除／visited 条件及原 tie-break。电链候选先保留原 3000px 外层约束，再按感电 >30 扩程、>60 绕过局部距离限制；每跳读取当前感电，不跨跳缓存可达目标。
4. **保留有序范围查询**：`_burst()`、`disarm_burst()`、寒墨终式随机目标及死亡传播仍按距离平方／字符串 ID 返回快照。先消除 `_nearby()` 内多余 `_living()` 中间数组；排序键是否预存，以实测抵消额外结构分配后再定。传播的少量 top-k 可后续采用有界插入，但当前规模小，首批不另建堆或通用查询框架。治疗按生命比例排序没有显式并列契约，首批保留原排序，不擅自规定新顺序。
5. **循环内不变量**：坐标缩放、查询半径平方、同一次循环使用的构筑值移出内循环。纸灵 `distance / (1 + vulnerability / 32)` 的权重保持原样，不为省一次开方改写评分导致近似并列变化。`CompiledBuild` 的遗物层数已有字典，不再全局增加一套构筑缓存。
6. **清弹**：`clear_radius()` 当前复制数组后逐项查找、搬移；该入口不结算伤害或发送回调，可按原序读写游标压缩 survivors，最后一次 `resize`，从最坏 O(T²) 降为 O(T)。保留对象身份、反射弹、边界包含条件及数组相对顺序。`_advance_threats()` 会反射、引发死亡和追加弹，`ongoing`／`fields` 的推进也可能连锁，不能机械套用相同压缩方法。

**存活集合不做整步缓存。** 首批保留需要快照的 `_living()` 调用，逐个处理纯只读热点。若测得后期 M 扫描仍占主要成本，再维护按生成顺序排列的活动引用数组：生成时加入，死亡提交时移除；需要快照的调用仍复制活动数组。遍历过程中生成是否本阶段可见、死亡后本轮是否继续处理，须与原入口逐一对照后迁移，不能让一个共享数组在嵌套死亡回调中被删除、重排。该结构只索引对象，不持有第二份生命／位置。

### 第二批：碰撞候选与命中选择

**先保留当前精确几何，缩小进入精算的集合。** 对每次正在处理的两条运动段，取起止端点包围盒，并按半径扩张；只有包围盒严格分离才跳过原 `sweep_discs()`。边界相切保留，粗筛可多放行、不能漏候选。优先验证投射物和反射弹；原 sweep 已有重叠、零运动、背离与判别式早退，新增粗筛若在小规模或密集场景反而变慢则不采用。

- **单命中弹**：当本次 `remaining_hits == 1` 时，单次扫描取最小 `(time, 字符串ID)`，之后在原位置调用同一命中流程；不分配候选 Dictionary、不排序。原算法 O(M + C log C) 变为 O(M)，C 为实际接触数。反射弹本来已单次择优，保留其“相同时取原数组第一项”的规则。
- **贯穿弹**：保持本弹本步几何候选先收集、按 `(time, ID)` 排序、再逐项提交；第一击会解除追踪、释放词咒，后续命中会消费次数和有限伤害。即便连锁使后续候选死亡，也不能顺手改变原来消耗次数的时机。可在测量后用类型化平行数组替代字典；不要在每次命中后重新查找候选，把新生敌人加入同一步贯穿。
- **实体分离**：保留原 `bodies` 快照、双循环顺序、四轮约束、每轮 `reverse()`、玩家分离及边界钳制。平方距离仅作宽松粗筛：显著超过完整分离半径 `a.radius + b.radius + 4.0` 才跳过；接近边界时仍调用原 `length()` 并判断 `overlap <= 0.15`，不直接把带容差的开方比较改成平方比较，以免浮点舍入改变投影。扫掠和每轮投影的前一个配对会改变后一个配对的端点，粗筛使用当时的实时位置，不能整轮只生成一次固定配对列表。碰撞伤害、质量、恢复系数和高速阈值不动。稀疏与拥挤场景均须对照；增加一次平方计算后没有净收益，就保留原循环。
- **拦截与危险区**：纸灵只命中已选目标，无需空间树。纸鹤按原 fields 顺序消耗首个有效场，不能改为最近纸鹤。玩家敌弹扫掠、御术额外 0.06 秒预测、普通／完美御术及 0.30 秒连续反弹窗口保持原执行位置。激光／爆圈继续各自的范围规则，不把所有检测统一为圆。

命中输出必须保留 `at`（敌人中心）、`contact`（表面接触点）、`direction`、`from`、`source`、`empowered`、伤害字段及发出顺序；投射物最终位置和尾迹末点仍截到实际首次／最后耗尽次数的接触时刻。算法调整不能造成反馈错位、少发／合并视觉事件或改变受击位移。

### 范围、光环与空间索引的取舍

首选小数组线性扫描，减少无关对象和类型筛选：加速光环、塔、冰雾、纸鹤可按实际热点单独组织候选。敌人移动是按数组依次提交的，加速源的位置必须即时读取；保留 `alive()` 与 `enemy_in_combat()` 各自要求，不能把 `_living()` 一律替换为“已入场敌人”。场为圆或胶囊（`center` 到 `endpoint`），粗筛之后继续调用原 contains／线段距离语义，不只检查中心格。

分类集合如需跨调用复用，其更新由现有生成／到期／消费／同类合并入口负责：法术命中可新增或合并场，纸鹤会在敌弹循环中被消耗；烧伤死亡则会改变存活集合并产生后续效果。首批不把“场数没变”作为缓存有效依据，不缓存一整步的可见性、距离或塔盾状态；处理所有增删入口的成本若超过收益，就保留本地筛选。

**均匀网格只作为后续有条件选择。** 在第一、二批完成后，若 `(P+R)×N` 或 `N×F` 的候选扫描仍主导固定步，才对照线性版试验；不因为看到双循环就启用。优先有界 2D 均匀网格，不引入四叉树、BVH、导航寻路、PhysicsServer/Area2D 状态迁移或 GPU 碰撞。

网格若采用，遵守以下范围：

- 先只供只读弹道／范围查询。运动物体按整个扫掠 AABB 覆盖的格子登记，静态场按圆／胶囊 AABB 登记，不能只登记当前位置或固定九邻格；高速运动、大半径和边界对象仍须完整收集。
- 以稳定查询序号去重，恢复原查询要求的顺序，再做精算。全场电链及大范围领域直接线性扫描，避免遍历大量格；小集合继续线性路径。格边长先比较 96／160／240 设计像素，只作为实验参数；阈值由构建、更新、查询、去重和排序的总成本决定，不写死一个未经测量的敌人数阈值。
- 敌人移动／实体分离之后的索引不能沿用到任意阶段：敌人攻击会生成新实体、近战完美迎击会分离位置、死亡会分裂。需要在这些变化处更新或在对应查询批次前重建；纯冲量变化不等于当前位置变化。不得把整帧位置快照用于后续所有查询。
- 实体四轮投影首轮不接网格。若以后真成为热点，必须每次修正后更新并确保后续配对不漏检，仍保留原访问次序；无法以简单结构证明等价就继续全配对。

### 自动闪避：保留评分，优化计算方式

`_safe_direction()` 仅在有效 `dodge_auto` 操作时同步执行，是一次操作的长帧风险，不是每帧固定成本。保留从正上方开始的 24 候选顺序、240px 位移、0.17 秒运动、1 秒保护、1.4 秒预测及最多 14 个 0.1 秒段；不降低候选数、不跨帧延后落点、不用上次搜索结果。

第一轮继续 GDScript：把每条 trajectory 的字典／嵌套数组改为连续点缓冲与起点索引、段数、半径的类型化数组；候选缓动起止点复用缓冲。固定方向、权重和缓动系数用原表达式初始化一次。坐标仍保持原 Vector2 精度，评分／半径等标量不降为 Float32；只减少数据访问与分配，先不同时改公式。

进一步的段级剪枝必须保守：原风险是每条弹轨迹各段风险的最大值，再把各条弹风险依原顺序累加。用点到段 AABB 的最短距离下界给该段风险建立上界；只有上界不可能超过当前该弹风险、且前两段玩家移动扫掠的 100 分风险也不可能提高它时，才能跳过精算。上界向宽松方向留数值余量，不确定的段照常计算。该优化单独 A/B，若边界计算成本更高就舍弃。

不能按“距离较远”直接删除弹或敌人：当前评分具有随距离衰减但非零的尾项；不能把段权重的最大值直接当实际风险，不能改评分加法顺序或更换候选评估顺序。曲率、加速、短寿命、反射标记、近战扇区、冲锋预测、区域激活时间、边缘与中心惩罚全部保留。已有非负下界剪枝及并列选择规则继续作为基线。

### .NET 的引入条件与边界

采用范围为**自动闪避批量评分核，不迁移伤害、实体状态或逐对碰撞**。工程锁定 Godot 4.7.2 mono、SDK 9.0.201，`Keyabyss.csproj` 只编译 `game/algorithms/*.cs`。采用依据、剩余操作开销和交付链验证分别记在[实施记录](COMBAT-ALGORITHM-IMPLEMENTATION.md)，不能把 mono 引擎或一次编译通过等同于零接入成本。

Godot 官方说明 C# 操作 `Godot.Collections` 会经过互操作，集合转换也有逐元素封送／复制成本；PackedArray 在 C# 对应受支持的 `System.Array`。因此采用“GDScript 读取对象并打包 → 一次调用 → 托管数组纯运算 → 返回候选索引”，而不是把循环搬入 C# 后继续逐个 `Get()`／`Call()` 访问 GDScript 对象。依据：[C# 集合](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/c_sharp_collections.html)。

窄接口为 `DodgeScorer.Choose(...) -> int`，只迁移敌弹轨迹评分。GDScript 按原表达式生成预测轨迹、24 个候选及前两段玩家运动轨迹，并生成敌人评分和危险区／边缘／中心尾项；按原顺序打包为 PackedVector2Array、PackedFloat64Array 和 PackedInt32Array，一次传入 C#。C# 执行候选×敌弹×轨迹段的纯数组循环，按原顺序累加并剪枝；返回 0～23，由 GDScript 使用原方向表继续提交闪避和事件。内循环不调用 Geometry2D 服务，不传 BattleSession、BattleEnemy、SpellField 或回调。

首个接口保留原预测积分及三角函数的语言环境，减少数值对照范围。必须分别测量预测打包、跨语言调用和评分：如果预测打包仍使总成本超预算，才考虑把轨迹积分一起迁移。敌人／危险区部分不能预先合并为一个总分后改变原加法顺序；单独保存原来在敌弹评分之后累加的尾项。无需维持两套常驻战斗状态，也不扩展为跨语言战斗框架。

浮点语义需单独验证：GDScript 标量 float 为 64 位，标准 Vector2 分量为 32 位；C# 不能将全部改为 float，也不能全部升级为 double 后声称等价。保持原向量中间值舍入、标量累加顺序、边界比较和候选 tie-break；三角函数、距离与积分的跨语言差异通过接近相切／相同分值样本验证。离散选择必须一致，不能以误差阈值接受不同方向。依据：[GDScript 数值类型](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/gdscript_basics.html#built-in-types)。

成本按完整调用计算：`T_total = 读取与打包 + 封送/复制 + 预测评分 + 返回/应用`。记录第一次实例化／首次调用、稳定运行分配量与 GC 停顿、包体及启动影响。内部复用缓冲不代表跨语言传递零分配；未证实前不引入对象池、SIMD、多线程或后台提前预测。同步核只持有本次输入，没有线程调度或过期状态的额外问题。

采用门槛是以下工程目标，而非已测结论：在相同目标 CPU 上，对照第一轮优化后的 GDScript，128／256 弹端到端 p95 至少降低 30% 且节省至少 1ms；0～32 弹的 p95 增量不超过 `max(0.1ms, 基线5%)`；一致性样本零选点差异，首次调用及 GC 不引入新的显著长帧。目标为 256 弹同步选点 p95 ≤4ms、p99 ≤6ms；若实际达不到，如实报告残余开销，不改候选或画面来通过。若 GDScript 已满足预算且 C# 增益不足，不引入 .NET。

接入交付包含与锁定引擎匹配的 `Godot.NET.Sdk`／目标框架、SDK 锁与可重复构建；`tools/godot/toolchain.json` 的预览复制清单已纳入 `.sln`、`.csproj`、`global.json` 和分配置依赖锁，并在预览副本构建；Windows Debug／Release 同时携带托管依赖。独立启动与受限 SDK 搜索环境的实测边界见实施记录。Godot 允许 GDScript 实例化已编译的 C# Godot 对象，但类名、基类和项目编译必须正确，见[跨语言调用](https://docs.godotengine.org/en/stable/tutorials/scripting/cross_language_scripting.html#instantiating-c-nodes-from-gdscript)与[C# 构建前提](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/c_sharp_basics.html#prerequisites)。这些通用文档不代替锁定 4.7.2 的实际兼容检查；编译通过不等于预览和导出链已经完成。

### 实施次序与验收出口

| 批次 | 交付范围 | 进入下一批的依据 |
| --- | --- | --- |
| A：建立当前基线 | 固定源码、随机种子、输入／操作序列、实体／场数量；记录查询次数、候选数与耗时 | 能区分自动闪避操作峰值、固定步 CPU 和渲染成本 |
| B：GDScript 局部优化 | ID 索引、纯计数／存在查询、单目标择优、清弹稳定压缩、循环不变量 | 相关行为一致，常见规模无可辨识回退；分项耗时与总耗时同报 |
| C：几何与闪避数据布局 | 单命中择优、保守粗筛／投影平方距离、闪避连续缓冲；各项单独对照 | 保留有净收益的项目，移除无收益复杂度；不强求所有候选均落地 |
| D：条件分支 | 剩余扫描主导时试空间网格；自动闪避仍超预算时试 .NET | 分别满足全成本收益、一致性和维护／交付要求；可两者都不做 |
| E：收束 | 同配置 Forward+ 实际窗口观察、相关规则回归、文档和必要发行验证 | 没有视觉数据变化或新的操作长帧；C# 如采用必须通过独立包启动 |

性能采样复用现有 `DebugLog` 的 `battle.step`、`battle.spells`、`battle.motion_collision`、`battle.attacks_encounter` 与 `app/frame_capture.gd`；现有分组不足以定位子算法，实施时才在相关入口增加可关闭的轻量计数／分段计时，按样本结束汇总，不逐对打印。`tests/godot/profile_frames.gd` 是窗口空闲采样，不当作密集战斗基准。自动闪避另计端到端操作耗时，不能藏在整局均值里。

样本至少覆盖 N=8／24 的常见及拥挤分布、相同 N 下 M≈N／M≈100 的长页历史、召唤／分裂造成 N>24 的场景、T=0／32／128／256 的直线及弯曲加速弹、少量／密集反射、四书与多场叠加。记录实际 P／R／F 和作用范围；先取正式遭遇分布，人工放大量明确标为压力测试，不冒充玩家常态。

每个性能组合先预热，A/B 交替运行相同输入快照，每组至少 200 次、重复 3 组，记录中位、p95、p99、最大值及分配；首次冷调用单列。窗口固定相同分辨率／画质／减少动态、相同输入与事件，排除截图读回与初次 shader 编译；使用原有效果完整运行。对比统计来自同机同构建，最终确认目标设备 CPU，不能由 Quadro P620 显卡型号推断 CPU。固定步 60Hz 的 16.67ms 是整帧参考，不是算法独占预算；若减少 CPU 后仍为 GPU 瓶颈，如实记录，不据此扩大到视觉优化。

正确性以开工时源码为参考，在隔离会话运行相同快照／种子／输入。比较目标 ID 与顺序、命中／死亡／派生事件序列、整数资源和实际伤害、实体与弹道状态、词咒释放、RNG 后续状态；浮点结果按既有精度逐项核对，任何命中或选点分歧不能用“数值接近”放行。只改查询的部分应保持原数学路径；新增平方距离早退与粗筛重点测相切、阈值两侧及重叠零位移。

按改动复用最小现有案例，不默认全量：

- `test_battle_session.gd` 中连续扫掠、高速交叉、相切／初始重叠、首击阻挡、贯穿、接触点／尾迹截断和质量分离案例；该旧综合脚本有既有失败记录，先记录基线，只对相关有效案例形成回归，不顺手修旧预算断言。
- `test_s2_rules.gd -- --four-books` 覆盖四书目标与传播机制；补足同距离 `enemy_10/2`、塔与 Boss 同范围死亡、分裂后下一弹可见／原范围快照不可见、同一纸鹤拦截多弹中的首次消费、清弹与新增弹同一步等真实缺口。
- `test_defense_movement.gd` 覆盖御术预测、冲锋、防御窗口与自动闪避；历史 288 例只作场景参考，针对当前函数重建对照，加入无威胁／对称／边缘、极短寿命、近并列评分和冷／慢时间状态。
- 改 GDScript 后按锁定引擎逐受影响脚本运行 `--debug --check-only --script`。采用 C# 时增加 Debug／Release 编译及跨语言实调；否则不运行 dotnet build。最终小范围窗口确认四书实际命中与御术的反馈位置、尾迹、事件时序一致，不以截图代替规则比较，也不修改视觉来适配错误的算法输出。

## 连续远征与存档

基线只有保留遗物继续更强周目。本次目标增加通关后递进五档难度：保留主书、遗物层数和一次性效果已使用状态，推进新一轮章节；最高档之后继续更强周目。难度档与周目压力分别记录，不用旧 stage 公式暗中把升一档重复算成多次增压。

页奖励和路线支付保存成功后生效；重复提交不重复扣费或领奖。阶段胜利与继续挑战只结算新增事实，结束连续远征后普通重开清空局内遗物。

保留当前 Godot 设置、词库、有效人工字符和记录；由字符计算轻量成长，不将旧天赋节点兑换成遗物或新能力。旧进行中远征若与新规则不兼容，在明确保存边界结束并保留原档。普通／God 隔离，不建设浏览器档案转换。线性成长阈值与幅度在 S3 定案，S1／S2 不沿用旧 60 点曲线。
