# 天赋、战斗与打字核心评审

评审日期：2026-09-30。

当前实施从 [M4 天赋图基础](../migration/M4-TALENT-GRAPH-PLAN.md)开始，再结合图上的真实路径与 M5 遭遇检验构筑体验；整体平衡留到 M6。以下保留评审时的发现与判断依据，不作为阻塞 M4 的平衡验收要求。

现有架构有能力承载丰富的天赋，但当前实现还不足以证明，它已经能支撑一个好用、有深度的天赋系统。M3 有明确的功能遗漏；规则的复杂程度也已经走在战斗设计和玩家理解之前。后续工作的重点应是让这些规则产生实际效果，并改变玩家的选择。

本评审依据有效设计、Godot 源码、现有检查代码和相关旧实现，未进行新一轮试玩、性能或收益测试。下文将源码事实、已确认方向和设计建议分别说明。源码事实对应评审时的状态，后续具体改法见[功能修正方案](../migration/M3-REPAIR-PLAN.md)，修复后的实际进度以[阶段总结](../STAGE-SUMMARY.md)为准；未完成工作统一维护在 [TODO](../TODO.md)，本文件保留判断依据。

## 已确认的方向

**打字始终是主要进攻来源。** 弹反和闪避负责保命、争取输入时间；强反击主要消耗打字积累的力量。反击构筑可以改变这些力量的释放时机和方式，但不能让持续防御取代打字，成为主要的进攻供给。

这个方向不要求每一下伤害都紧跟一次按键。完成一词之后，保存、分裂、运输和持续攻击可以自动完成一段有限过程。玩家继续输入，才有新的主要进攻力量；停笔后已经支付的过程可以收尾。

基础弹反和闪避仍应在没有储备时正常保护玩家。普通反击保留多少伤害、强化反击如何取用储备，以及如何显示可用力量，需要进一步设计和验证，本评审不指定未经验证的比例。

有效规则见[产品设计](../PRODUCT-DESIGN.md)和[系统框架](04-SYSTEM-FRAMEWORK.md)。以下遭遇、成长和交互建议用于指导后续设计，不等同于全部已经定案。

## 实现缺口及依据

### 部分效果已经登记，却没有完整生效

| 内容 | 源码事实 | 影响与修正目标 |
| --- | --- | --- |
| R017／R131 辅助补全 | [TypingSession](../../game/input/typing_session.gd) 提供 `complete_assisted()`，会话也接入了授权函数，但[输入路由](../../game/input/input_router.gd)和实际战斗流程没有调用它；当前调用来自机制测试 | 玩家装备后用不到。需要先明确触发方式，再接通真实输入流程；只补一个调用不足以解决体验问题 |
| R037 折返墨涡、R041 停笔沙漏 | [SpellRuntime](../../game/spells/spell_runtime.gd) 的 `on_dodge()` 从制作储备支付效果，但收入方向的 `bank` 条件没有包含 `dodge-pull` 和 `dodge-window` | 单独装备且没有其他供给入口时，效果没有所需额度。应只带必要前置，验证输入能供给、闪避能支付并产生描述中的效果 |
| R073 重墨底本 | 同一文件的 `_make_copy()` 没有集中强化处理；`copy-concentrate` 只在 `_shell_units()` 增加占位。[资源定义](../../game/content/build/R073.tres)承诺把同份制作额集中成一张强纸页 | 当前付出占位代价，却没有对应收益。应验证相同投入下，纸页数量、单张力量和容量占用的变化 |
| T03 棱面 | 同一文件的 `_configure_shape()` 先设置 `pierce` 的接触次数和主目标份额，随后被寒墨默认分支覆盖 | 对寒墨主术的调整没有保留下来。应明确基础形状、天赋和独卷形状的组合顺序，验证主目标与沿途份额；不能简单依靠代码出现顺序决定结果 |

这些问题说明，定义、编译索引、效果分支和实际输入入口必须一起核对。一个机制有消费代码，却没有收入方向，或有结算函数却没有玩家入口，都不能算作功能完成。

### 当前目录检查不能证明每件内容有用

[目录检查](../../tests/godot/test_m3_catalog.gd)为每项内容预先配置了一大组能力，再检查编译、来源索引、人工输入、产生伤害和房间清理。即使被检查的那件遗物没有起作用，其他能力也可能使这些断言通过。测试中的敌人还被设置为长时间冻结、高生命和延后攻击，不能据此判断真实战斗中的防御价值和选择压力。

已有 1508 项断言仍然是有效的编译和生命周期证据，但不能证明 377 项内容的效果全部兑现。机制检查已经覆盖一部分具体情境，也不能由此推断其他内容都已生效。

建议继续使用统一检查入口，按机制族准备情境。每件内容只带使其合法、可工作的必要前置，对比装备前后发生的具体变化：是否多挡了一次攻击、是否改变份额、是否提前作用、是否支付了正确成本。没有发生变化时，应能区分条件未满足、资源不足和效果遗漏。普通数值节点可以参数化检查，无需为每件遗物新建一套平衡工具。具体检查职责见[验证范围](../TESTING.md)。

### 正式获取需要更细的资产身份

[BuildSelection](../../game/build/build_selection.gd)按内容 ID 保存层数，并为每种内容保存一个实例标识；[CombatAssetService](../../game/build/combat_asset_service.gd)也沿用这个结构。它能支持现有试验场操作和部分使用回执，但难以自然表达“同一种遗物，一份永久拥有，一份临时借来”，更难按份区分到期、返还和已用机会。

建议正式资产逐份保存实例 ID、内容 ID、来源、期限和使用记录，再为编译器汇总有效层数。返还和演化操作针对具体实例；汇总不能丢掉身份。这属于接入 M4 前需要补齐的契约，尚不能把当前接口视作完整借还流程已经就绪。

### 伤害总数会掩盖浪费

[SpellRuntime](../../game/spells/spell_runtime.gd) 的 `_commit_damage()` 在目标扣血前，把抗性计算后的整份伤害计入 `actual_damage_q`；[BattleSession](../../game/session/battle_session.gd) 的 `commit_damage()` 再把生命截到零。目标只剩 5 点生命，受到 100 点伤害，当前记录仍增加 100。

这个数字可以表示抗性计算后的伤害量，却不能直接表示实际削减的生命或构筑贡献。建议区分实际扣血、超出剩余生命的伤害，以及尚未兑现便失去用途的份额；最后一种不是过量伤害。控制、防御和治疗也应有各自可解释的结果，不能全部用伤害总数替代。

## 天赋应该改变玩家的选择

保存、复制、受热、运输、传导和回收能够形成复杂结果。但如果换了构筑之后，玩家仍然总是找最近的词、持续输入、危险来了按空格，那么很多深度只存在于后台计算中。

自动处理法术是合适的方向，玩家不需要逐张管理纸页或逐份分配材料。判断机制是否有价值，更应观察它是否改变以下选择：先处理哪个目标，是否继续完成手上的长词，何时防御，哪些敌人可以交给已经部署的攻击处理。

普通数值节点可以只提供数值提升，不必强迫每一个节点都创造新操作。机制节点和深层组合则应有能说明用途的情境，否则需要重新考虑效果，或补足承载它的战斗设计。

### 基础机制先有用，组合再把它变好

保存本身应有可感知的用途；得到护页后，保存又能帮助防御；再得到遗响，才出现挡完以后继续攻击的变化。玩家不应先凑齐三四件东西，前面的投入才突然开始有价值。

“马上有用”不等于忽略合法前置。专门强化某种机制的内容，可以要求该机制已经存在；要求应该明确、合理。应避免把偶然提供收入的无关遗物变成隐藏前置。

### 共享预算的代价要说清楚

共同制作预算能产生取舍，也会让新增效果分走原有辅助收入。例如当前治疗方向在缺血时参与分配，可能减少纸页的制作。若描述只写“完词回血”，玩家会觉得输出莫名其妙下降。

选取时应能理解：“缺血时，会把一部分原本用于辅助攻击的力量拿来治疗。”分配仍由系统完成，不需要让玩家调一排百分比。涉及互相竞争的效果，详情应说明竞争的对象；战斗反馈应帮助玩家理解这次力量用在了哪里。

### 资源有限，仍然要有成长回报

一份资源只能使用一次，并不意味着天赋只能重新分配和损耗。投入可以带来更高效率、更少浪费、更好的时机、更可靠的命中，或足以改变目标顺序的控制与防御。

如果一条长组合只是不断分走伤害、延迟并折损，最后还不如直接打出去，它就只有复杂，没有回报。评价这种组合时既要看输出，也要看它是否帮助玩家完成更多输入、应对原本难处理的威胁。具体收益仍由统一模型和正式场景验证。

## 战斗如何发挥构筑深度

当前 [BattleSession](../../game/session/battle_session.gd) 中敌人的主要行为是接近、保持距离和射击。试验场的密集、分散、耐久等配置适合检查规则，但位置、血量和攻击频率的变化还不足以证明战斗已经有丰富的选择。

建议先用少量可复现的房间检验下面这些问题，再扩展正式敌人和章节。这里列的是设计用途，不是已经实现的遭遇。

| 战场情境 | 玩家需要判断什么 | 能体现的能力 |
| --- | --- | --- |
| 近处敌人逼近，远处敌人正在蓄力 | 先解决眼前危险，还是抢先处理后排 | 控制、护页、自动攻击 |
| 一群弱敌围着一个重要目标 | 先清出空间，还是集中消灭威胁 | 分裂、连锁、集中、穿透 |
| 敌人移动使队形不断变化 | 现在出手能覆盖谁，是否值得换目标 | 区域、牵引、击退、运输 |
| 几波敌人连续到来 | 立即用尽力量，还是保留后手 | 储备、回收、跨波持续 |
| Boss 与少量支援敌人共同施压 | 何时持续输出，何时打断或转火 | 持续伤害、爆发、控制、目标选择 |

每种问题应有几种解法。面对后排蓄力者，玩家可以集中伤害快速消灭它，也可以先控制近敌以争取输入时间，或让已部署的自动攻击清理近敌，自己转向后排。天赋改变解法，不应成为某个房间唯一可用的钥匙。

普通小怪仍应能迅速死亡。保存、转交和回收要把已经取得的后效带向下一个目标；少量精英、Boss 和连续波次承载较长过程。不宜为了展示复杂组合，普遍把小怪变成需要反复输入的耐久目标。

元素抗性也应服务选择。只让冰书遇到某类敌人时多打几个词，提供的深度有限。更值得检验的是抗性是否改变优先目标、异质伤害的用途和处理支援的顺序。普通敌人大多中性、没有元素免疫的既定方向继续保留；不把副书变成强制通行条件。

## 怎样把核心放在打字上

打字同时承担投入和选择：输入积累主要进攻力量，目标与完词时机决定首先把它用在哪里；构筑改变后续处理方式，防御和控制帮助玩家获得输入时间。

### 字符决定投入，完词决定交付

短词出手快、转目标灵活；长词投入更大，也需要更长的安全时间。完词奖励可以形成节奏，但要防止固定的逐词奖励使最短词库稳定占尽便宜。比较时应区分字符投入、完成次数和实际耗时，不能仅用完成次数代表打字贡献。

选词应成为战斗选择。手上有一个接近完成的长词，另一个敌人却即将制造危险，继续输入和改换目标都应该在某些构筑与情境下有道理。已有的前缀换目标、错字保留进度和死亡续写，是支持连续输入的重要基础。

### 防御保护输入，强化反击释放输入所得

当前 `SpellRuntime.counter()` 按敌方攻击强度生成反击威力，基础值为来袭伤害的两倍，再计入相关增幅；此前没有打字也能生成。它有真实敌方攻击作为来源，并做了重复领取限制，但“来源合法”并不自动保证打字仍是主要进攻来源。

按已确认方向，后续需要分清基础防御和强化反击。没有储备时仍能可靠弹反、分离和闪避；反击构筑的主要进攻收益应来自先前打字积累的力量。远程反射飞行、近战即时反馈继续有价值，无需因此重写运动和接触系统。具体基础反击强度与取用规则尚待设计，不能只改一个倍率就视为完成。

控制和护盾的价值还应包括“让我多打完一个词”。它们可以帮助输入较慢的玩家获得稳定机会，而不只是减少生命损失。相应地，敌人的预警和进攻间隔需要给玩家可以读懂、能够利用的窗口。

### 辅助补全需要先明确用途

已确认的补全语义只按真实输入部分施法，辅助字母不产生收入、成长或完整手打奖励。因此，它更接近“提前交付已经输入的力量”，不能按完整手打的收益宣传。

[旧版羽毛笔定义](../../legacy/web/src/content/relics/feather/definition.ts)是在完成若干次手动输入后，让下一词输入前两个字母就自动补全。这个触发方式若直接沿用，可能截断玩家原本想完成的长词，尤其在收益只按人工前缀计算之后。

补入口前需要回答：玩家何时希望提前交付，怎样保留继续输入的选择，所得便利是否值得消耗补全机会。建议围绕这些问题选择触发方式，不直接恢复旧版自动截断。具体采用何种交互尚未确认。

### 连续输入不能被表现阻断

当前目标新词等对应主术命中后才出现，这让词咒与法术的关系清楚，但在单体战中可能形成等待弹道的空档。应在 Boss 和耐久目标中观察实际空等是否过长，再决定是否需要调整。该问题尚无新一轮试玩证据，不据此撤销已验收的 M2 时序。

错字已经损失时间。准确奖励可以保留，不宜让一次失误同时清空进度、收益和整套构筑；也不需要为了强调打字而增加强制节拍或逐字小游戏。词咒、危险预警和当前输入进度，应比法术特效更容易辨认。

## 成长与说明如何让系统好用

玩家选择天赋时，应能回答：现在拿它有什么用，它会占用什么或使我放弃什么，哪些后续内容能让它更好。说明不能只罗列内部材料名，也不能把尚未生效的效果写成已拥有的能力。

战后或试验场检查应解释实际结果，例如护页挡了几次攻击、持续伤害处理了哪些目标、多少力量因为目标先死而没有用上。开发用来源账仍然有价值，但材料余额和原始事件列表不适合直接承担玩家的理解成本。

206 项天赋和 171 件遗物是当前候选规模，不是必须维持的数量目标。普通数值节点可以服务成长和路径；作用重复、难以察觉、只有代价却没有独特用途的内容，应允许在说明理由后合并或移除。此次评审没有决定删除具体内容。

后两档难度体现成长价值的目标可以保留，同时普通难度的早期体验也要有完整、好玩的选择。不能让玩家先累计大量字符，才获得第一次有意思的玩法变化。长路径沿途应有用；奖励和教学应帮助理解兼容关系，不替玩家补齐预设毕业配方。

## 对架构和实施顺序的建议

现有 Resource、构筑编译、快照、固定步、来源账和统一接触结算值得继续使用。发现遗漏并不意味着需要推倒重写，或再增加通用规则解释器。更直接的改进是把每种操作的触发条件、供给方向、费用和实际结果一起核对，避免新增消费分支时漏掉供给与入口。

建议按以下顺序推进，具体未完成项仍以 [TODO](../TODO.md)为准：

1. **补齐 M3 的真实遗漏。** 先处理已知效果缺口、描述与执行不符、真实输入入口和验证方法；落实打字与强化反击的关系。不能把这些问题归为单纯的数值或手感调整。
2. **用代表性构筑面对不同战场问题。** 同时包含无投资、早期机制和深层组合，检验最小可用搭配及不同来源替换。样例用于验证系统，不限定玩家路线，也不替代全部保留内容的功能证据。
3. **观察选择是否变化。** 在相近输入水平下，记录目标顺序、继续输入或改换目标的时机、防御时机和实际结果；规则正确性、画面观察与手感反馈分别记录。
4. **把有实际用途的内容接入正式成长与获取。** 接入前补清资产实例、期限和使用记录，配套条件说明与结果解释。完整远征和统一收益验收继续按 M4–M6 推进，不在 M3 宣称完成。

少量遭遇验证可以在试验场完成，不必等完整章节上线。反过来，只有基础伤害更高、测试不报错或特效更多，也不足以证明构筑更好用。更有说服力的结果是：玩家因构筑获得了新的可行选择，能更从容地完成输入，并把每个词用在更合适的地方。
