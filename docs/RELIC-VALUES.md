# 遗物数值与公式

## 单一来源

- 遗物的可计算数值放在各自 `src/content/relics/<id>/values.ts`，由 `definition.ts` 的 `values` 引用；描述使用 `description.template` 的 `{公式键}` 占位符。增加遗物不增加 UI 的 ID 分支。
- 通用施法基值在 `src/content/combat-values.ts`；咒典的普通/强化倍率及基础召唤、跳跃数量来自咒典定义。原有 `damageModifiers`、`hooks` 继续是相应系数的唯一来源。
- 装配层注入基础公式与遗物定义。模拟构造时合并公式，`combatValue()` 调用 `shared/ValueRules.ts` 求值；描述使用同一份表达式求值或生成公式文字。不能再单独手写公式字符串或在 UI 复制系数。
- 表达式仅支持数值、属性、输入、引用、加法、乘法、幂、最小值和条件选择。没有 `eval`、脚本执行或对游戏状态的写入。新增机制仍使用内容行为与受限能力接口。
- 内容验证拒绝重复键、丢失引用、循环引用、非法属性、无穷常量与不存在的描述占位符；求值拒绝缺失输入和非有限结果。

## 本次公式审查

保留现有战斗数值，没有借显示重构调整平衡。不同遗物原本采用不同叠层规则，不应统一套用复利公式。

| 效果 | 现行叠层结果 | 解释 |
| --- | --- | --- |
| 爆墨瓶 | 命中基值 × 0.35 × 层数 | 一层35%，二层70%；翻倍的是溅射，主目标被排除。周围每个目标独立结算，范围内目标越多，收益越高。 |
| 锋利笔尖 | 1.25^层数 | 乘法叠层，一至三层为1.25、1.5625、1.953125。 |
| 护甲 | 0.75^层数，再乘玻璃书封受伤倍率 | 乘法减伤，不是每层减去25个百分点。 |
| 短咒／长句 | 1＋0.6×层数／1＋0.75×层数 | 同类加法叠层；词长门槛来自内容定义。 |
| 无瑕落款 | 1.08＋0.35×层数 | 已包含无错字基础倍率。 |
| 余烬墨水 | 6×构筑倍率×(1＋0.3×层数) | 第二层的倍率为1.6，不是1.3²；每层灼烧状态独立参与结算。 |
| 腐蚀 | 8×遗物层数×腐蚀状态层数 | 遗物层数和敌人的状态层数是不同变量。 |
| 护页结界／回复钩子 | 钩子中的amount×持有层数 | 次数门槛、护盾上限、最大生命和获取效果沿用钩子数据。 |

爆墨瓶使用 `strike` 中经过冻结、处决等命中修饰后的伤害基值；主目标的护甲、镜盾及Boss阶段保护在随后各自的 `damage` 结算中处理，不能把主目标最终扣除的生命当作溅射基值。预览计算排除目标状态，不能保证每次实战扣血都等于预览。

候选预览只在副本上增加一层，并处理获取时的最大生命、充能和血契扣血；已满层不重复应用获取效果。已持有详情使用现有构筑。词长、无错字和普通施法的预览基准仅在技术文档记录，卡片不追加解释性尾注。

## 验证

`tests/relic-values.test.cjs` 检查实际命中与溅射、配置系数变更联动、新遗物无需代码分支、公式引用校验、生命阈值与层数。`tests/relic-values-browser.py` 检查图鉴、候选、详情、按键松开/失焦以及桌面布局。`npm test` 覆盖迁移涉及的施法、火焰、纸灵、防御与觉醒行为。
