# M3 功能修正与战斗验证方案

本方案落实[天赋、战斗与打字核心评审](../build-system-design/08-TYPING-AND-BUILD-REVIEW.md)，先修正可确认的功能与接口问题，再用不同战场问题检验构筑价值。实际进度见[阶段总结](../STAGE-SUMMARY.md)，未完成事项只维护在 [TODO](../TODO.md)。

当前优先推进 [M4 天赋图基础](M4-TALENT-GRAPH-PLAN.md)。本方案的功能要求继续有效，构筑体验结合真实购买路径和 M5 遭遇判断；整体平衡放到 M5 完成后的 M6，不以提前完成平衡阻塞图谱工作。

## 运行架构与改动边界

保留 Resource 定义、BuildCompiler、构筑快照、BattleSession 固定步、SpellRuntime 和来源账。输入只提交意图；费用与效果在固定步内一起处理。运动、连续碰撞、反射飞行和纸灵返航继续使用原生实现。

工作分成四部分：补齐具体规则；补全输入与反击关系；修正资产和结果记录；让试验场及检查能够解释实际变化。前三部分通过后，再观察代表性构筑如何应对不同威胁。完整成长、事件调度和正式章节仍按 M4／M5 接入。

## 具体规则

| 问题 | 改法 | 验收重点 |
| --- | --- | --- |
| R037／R041 无供给 | 取得对应能力就把制作储备加入共享分配；多个同类来源只开一个方向 | 仅装备必要内容，输入后闪避确实牵引或延长防御；没有额度则不产生附加效果 |
| T03 被寒墨基础设置覆盖 | 先确定基础与独卷形状，再增加一次穿透；主目标份额降为加工前的四分之三，其余沿实际路径支付 | 寒墨和其他可飞行主术有实际变化；总份额不增加；目标不足时仍按正常结束规则收尾 |
| R073 只有占位代价 | 同样制作费用下，将允许保留的主术比例上限翻倍，最高为主术本身；输出仍不能超过已支付的兑换结果。复写页多占一格，普通保存页不受影响 | 同投入下单页可保留更多力量；不足和满位不扣费；普通保存不额外占位 |
| R072 与 R073 同时存在 | 先计算提高后的总保留量，再由分栏分成两页，每页支付集中后的占位 | 两者组合仍共用一份预算；说明不再把重墨底本写成强制单页 |

这些比例是功能起值，进入统一参数版本，不作为收益已经平衡的结论。

## 辅助补全与反击

用户已确认采用 **Ctrl 主动补全**。取得能力、有可用制作额度且已经输入部分词咒时，按 Ctrl 提前交付；不按就继续输入。辅助后缀没有字符收入、成长、完整手打奖励或停用词数推进。

输入路由提交补全意图，记录当时的词尝试和目标；固定步只作用于仍然对应的输入，不能补全取消后或换词后的另一词。机会不足时不扣费、不结束输入，并给出可理解的提示。暂停、菜单和文本编辑不触发战斗补全。HUD 在相关能力存在时说明 Ctrl 的用途和是否可用，不增加材料仪表。

弹反保留无储备时的挡伤、推离、慢放与反射飞行。基础反击采用很小的固定上限，不随敌方伤害和天赋倍率膨胀；强化部分从打字赚到的制作储备和合法回收储备支付。返咒类能力开放相应制作分配，数值提升作用于支付后的转换效率。一次敌方攻击只处理一次，借势和后续附着从同一份反击预算中分出。

先用基础反击最多 1 点、强化反击每次最多消耗 6 单位制作额度、基础兑换率为 4 的参数验证规则。无输入反复弹反不积累强化力量；有输入时，反击与其他辅助用途竞争同一预算。实际手感再通过正常速度试玩判断，不能用加速检查代替。

## 资产与结果记录

正式配置按每一份资产记录实例 ID、内容 ID、来源、期限和演化关系；编译时汇总有效层数，并保留实例身份供一次性效果领取。移除、演化和返还针对具体实例，同种其他资产不受影响。使用回执由跨房状态持有，返还原实例不能刷新。

试验场继续允许按种类和层数快捷选择，但它只是显式的开发适配；同一请求不能混用正式实例和快捷资产两套来源。正式奖励报价、期限推进和本游戏成长存档属于 M4。

伤害记录区分抗性计算后的伤害、实际削减的生命和过量伤害；结束时尚未使用的力量另外记录。防御与治疗显示实际挡住或恢复的数量。试验场先给出可读的效果汇总，再提供开发用来源账，避免把清理损耗或材料支出称为有效伤害。

## 验证与战场情境

目录检查移除无关的预配能力，仅加入明示前置、许可和机制实际需要的基础能力。登记、编译参数变化、生命周期和行为证据分别报告；没有具体行为证明的规则明确标为待验证。总伤害大于零只说明战斗链在运行。

新增或扩展的情境检查应比较有无该内容时的实际变化，复用机制族入口。重点覆盖补全真实按键、取消与同帧换词、无储备及有储备反击、实例并存和返还、最后一击的过量伤害，以及本轮规则修正。保留原有输入归属、碰撞和清房回归。

试验场增加有明确问题的配置：近敌逼近与后排蓄力同时出现；弱敌围绕重要目标；连续波次检验保留与回收。仍使用正式会话和敌人行为，试验场只负责配置，不直接制造伤害。观察不同构筑是否改变目标顺序、继续输入或改换目标的时机、防御时机；完整 Boss 与章节设计留到正式遭遇阶段。

敌人的移动必须保证玩家始终有可交战的目标：未锁定远程敌人不能在入场冷区按理想射程停住。先引导进入有效战场，内侧保留少量余量，再使用正常距离策略；不靠提前授予锁定资格或在冷区开放攻击解决。这一边界用靠边玩家、远程入场、词咒持续可见和锁定后击退检查。

## 实施与验收顺序

1. 独立修正规则及检查，同时补齐资产模型与目录证据。主控负责公共语义、输入和战斗接线，避免多人改同一职责。
2. 集成 Ctrl 补全、反击供给、逐份回执和结果记录，统一内容说明与参数版本。
3. 运行对应原生检查；审阅每项失败、引擎错误和清理告警，修正真实问题。
4. 在实际窗口检查输入提示、补全、反射、暂停、结果汇总及试验场情境。画面与规则分别记录，不宣称替代真人手感或完整收益验收。
5. 更新实际状态和剩余工作。已经补齐的具体缺口从 TODO 移除，尚无行为证据的内容继续明确保留。
