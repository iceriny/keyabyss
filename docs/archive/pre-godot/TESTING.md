# 验证范围与证据

验证与修改的风险、不确定性和影响范围相称。优先使用能够充分确认正确性的最低成本方法；连续相关修改在有意义的边界统一检查。已有证据足够时停止加验，无关失败只记录，不扩展修复范围。

本页说明如何选择检查，不是每次工作都要执行的清单。当前实际结果见[阶段总结](STAGE-SUMMARY.md)，旧日志见[归档](../README.md)。

## 选择检查

| 改动 | 足够的起点 | 何时扩大 |
| --- | --- | --- |
| 文档、明确的局部或机械修改 | 内容审阅、差异、链接与直接结果 | 出现未解决的引用、事实或行为疑问时 |
| 局部逻辑 | 最小相关现有测试文件 | 影响共享状态、核心规则或发现跨模块回归时 |
| 类型、定义、模块接口 | 对应类型、内容或依赖检查 | 接口使用面广或存在集成疑问时 |
| 页面与交互 | 相关页面与实际操作 | 共享布局、输入、渲染生命周期受影响时 |
| 资源、配置、交易、存档 | 不变量及关键边界组合 | 跨流程接入或内容完整阶段 |
| 难度与收益 | 功能与内容完整后统一评估 | 评估发现具体失败后，补相称范围 |

不为每次验证习惯性新建临时脚本，不为每件遗物另建平衡脚本，不因存在全套测试就默认全跑。新增长期回归应保护真实规则或失败边界，而不是逐行复述实现。

## 覆盖职责

| 验证域 | 要回答的问题 | 现有入口示例 |
| --- | --- | --- |
| 定义与编译 | 单位、条件、许可、模式与规则是否合法 | `tests/build-rules.test.cjs` |
| 资源与对象 | 单份归属、原子失败、重复回执、生命周期是否正确 | `resource-ledger.test.cjs`、`spell-resource-runtime.test.cjs` |
| 阶段与正式战斗 | 真实输入、伤害、后效、房章边界是否贯通 | `spell-execution.test.cjs`、`native-spells.test.cjs`、`manual-spell-income.test.cjs`、`letter-opportunities.test.cjs` |
| 内容展示 | ID、说明、条件与目录是否对应 | `build-presentation.test.cjs`、`game-text.test.cjs`、`codex.test.cjs` |
| 图、配置与资产 | 几何、合法路径、预算、借还、迁移及 God 隔离 | 现有图谱、天赋、事件和记录检查；全候选覆盖尚未完成 |
| 视觉与交互 | 层级、阅读、固定详情、键鼠与实际运行表现 | 与受影响页面对应的浏览器入口及人工观察 |
| 完整收益与难度 | 合法获取、成长、好运和不同操作水平的结果 | 通用 `tools/build-balance.mjs`，见[收益模型](../../COMBAT-BALANCE-DESIGN.md) |

相同机制优先用共享场景表覆盖多种内容。两个入口若只有转调关系，不重复运行；有独有边界断言的测试不能仅因名称接近就删除。本次不改动测试文件或工具。

## 现有仓库命令参考

以下仅是当前工具的使用方式，不构成下一阶段技术约束：

- 指定行为检查：`node --test tests/相关文件.test.cjs`。
- 类型：`npm run typecheck`；内容：`npm run validate:content`；依赖：`npm run check:architecture`。
- 全单元集合：`npm test`；仅在影响范围确实需要时使用。
- 发行构建：`npm run build`，会生成内容、图谱及发行产物，包含架构和类型检查，不是纯只读验证。
- 页面入口：`npm run test:ui`；其他现有专项以 `package.json` 为准。
- 渲染综合检查：`npm run test:visual`；仅性能：`npm run test:performance`。前者已经包含同组性能采样，同一阶段不要连续重复。
- 数值入口：`npm run balance:builds`；当前分阶段、分片命令见[历史评估说明](../COMBAT-ACCEPTANCE.md#复现)。执行前核对内容与场景覆盖，不直接沿用历史结论。

浏览器展示使用内置浏览器，自动化使用 Python Playwright，不使用 computer use。图谱几何脚本通过不代表外观合格；短时 CPU 提交耗时不是 GPU 耗时，也不等于所有设备的帧率。

## 证据如何记录

记录代码／内容状态、命令、范围、结果、失败原因、未覆盖部分与完整输出位置。修复测试输入与修复运行行为要分开说明；不能为通过检查改变既定语义。

通过数量不能跨批次累加成覆盖率。展示数量、注册数量、实际可获取数量、正式执行范围、数值样本数量分别报告。没有执行的项目明确写未执行，旧构建或旧浏览器结果不用于覆盖后续改动。

完整日志和截图可保存在已忽略的 `.temp/`；文档保留必要结论与路径。历史细节进入归档，当前清单只留下未完成或未通过的事项。待清理文件按项目规则移入 `.delete/`，由用户手动删除。
