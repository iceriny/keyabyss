# Magic UI 音效与切片工具

原件在 `art/Magic UI Designed/`：144 个 96kHz / 24-bit 立体声 WAV，介绍来自 `00_Magic_UI_DS_Metadata.xlsx`。原件与工作簿均未修改。

自动识别 575 段；`SELECT-Enter` 有一处仅约 0.44 秒的间隔，已单独校正，最终覆盖 **576 个变体**。目前游戏引用 **41 个语义音效、37 个源文件、112 个切片**，音效发布文件 39,793,324 bytes（37.95MiB），完整离线游戏约 53.30MiB。未引用的文件和变体不进入发行包。

## 切片台

开发服务器运行时打开 <http://127.0.0.1:4318/tools/audio-preview.html>，或运行 `npm run audio:preview`。端口已占用时以终端显示的实际地址为准。

1. 搜索分类、文件名或介绍中的英文关键词。
2. 彩色波形区域对应独立变体；点击「试听」只播放该片段。
3. 修改开始、结束秒数，可新增或删除片段；点击「保存切片标记」。服务端拒绝空列表、重叠、倒序、非有限值和越界。
4. 运行 `npm run audio:build` 更新开发资源。正式构建也会自动执行按需导出。

编号从 **0** 开始。删除、重排后需同步检查配置中的 `variants`；不存在的引用会使构建报错。

编辑器按需把当前 BWF/WAV 转为浏览器兼容的完整 FLAC，支持 Range 定位，缓存最近 3 个试听文件。转换临时文件立即删除。编辑器及写入接口只用于开发，不进入发行包。

## 命令行

需要 Node.js ≥22.18、Python 3、FFmpeg、ffprobe（本机已有）。工作簿提取只依赖 Python 标准库。

```powershell
# 新增或更换素材后扫描；不会覆盖手工修正
npm run audio:scan

# 查询介绍和时间边界
npm run audio:query -- "shimmer"

# 独立 WAV 导出：原采样率、24-bit、立体声
# 目标不能已存在，也不能位于原始音效包内
npm run audio:export -- "UIClick_FOCUS-Hover_B00M_MUIDS.wav" 0 "hover-0.wav"

# 仅构建实际引用片段
npm run audio:build
```

FFmpeg 静音检测阈值 -60dB、最短间隔 0.6 秒，保留 15ms 前导和 120ms 尾音余量。检测针对原始立体声，避免先混成单声道时相位抵消误切；低采样率波形仅用于总览。相连或长尾片段可在工具内校正。

`Next` 的 a/b 两个 WAV 在原表中共用一个文件名记录，索引保留这一来源，没有伪造单独介绍。

## 数据与职责

| 文件 | 职责 |
| --- | --- |
| `data/audio-catalog.json` | 全包描述、分类、原表字段、源规格、自动边界和波形 |
| `data/audio-overrides.json` | 手工边界，重新扫描不会覆盖 |
| `src/content/sound-cues.ts` | 事件到文件、变体、音量、空间属性、冷却、优先级、并发上限的映射 |
| `src/generated/audio-manifest.ts` | 自动生成的切片 ID、URL、时长和大小 |
| `data/audio-build.json` | 引用与体积统计 |
| `tools/audio.ts` | 扫描、查询、独立导出和按需构建 |
| `src/combat/Sound.ts` | 将模拟层语义反馈转换成音效调用 |
| `src/platform/ThreeAudioSystem.ts` | Three 原生声音、空间定位、混音和声源池 |

## 空间音效与性能

- 世界声音使用 `THREE.PositionalAudio`、`AudioListener` 和 HRTF。听者位于玩家上方，按 `x / 160, -y / 160` 映射游戏坐标。命中、击杀、冲锋、激光、道具使用实际事件位置；画面缩放和震动不改变音效距离。
- UI、受伤、终式就绪、奖励、结算使用 `THREE.Audio` 居中播放。四本法书的施法、命中和终式分别配置。
- 固定 48kHz / interactive 上下文，避免高采样率声卡放大解码内存。首屏创建空空间声源，预热浏览器 HRTF 数据。
- 上限 48 个世界声源、16 个非空间声源，合计 64 路音效，背景音乐另计。上限集中于 `src/content/audio-policy.ts`；声源按需创建并复用，高优先级声音可替换低优先级声音。空间音效默认每类 6 路，四法书命中及两类打字各 8 路；普通 UI 每类 3 路，入场 1 路、焦点 2 路。同类触发间隔继续保留。诊断的 `voiceLimits` 显示池上限，`voices` 显示活动音效数。
- 最多 4 路并发解码，LRU 解码缓存上限 64MiB。此限制指缓存，活动声源和临时解码另占内存；不会整体载入原始 1.45GB 素材。
- 首屏预热 25 个 UI 片段；出征预热公共音效及所选法书的首个变体，其余按需解码。变体不连续重复，音效随机数独立于游戏种子。
- 首次点击或按键解锁音频。过期声音不补播：世界声音等待超过 180ms、UI 超过 450ms 即丢弃。加载失败退避 5 秒，音效故障不阻塞战场。
- 暂停清理世界声源，保留菜单声音；隐藏页面停止音效并静音。音效和音乐开关独立，主音量即时生效；独立的音效音量 sfxVolume 只调节音效总线，旧设置默认 100%。卸载取消加载并释放节点，共享上下文不会因 React 重挂载被关闭。
- 包中没有背景音乐，原有安静氛围底音单独保留，以 Three.Audio 播放。

## 按需发布

发布片段重采样为 48kHz，保留 24-bit 精度，用 FLAC 无损编码；空间声源混为单声道交给 HRTF，UI 保留立体声。这里的无损指 FLAC 编码，发布资源经过重采样和混音，并非原 WAV 的逐位复制。切口有 3ms / 5ms 淡入淡出，独立 WAV 导出则保留原规格。

切片 ID 由源文件身份、边界、声道和处理版本决定，可供多个事件复用。构建仅导出引用列表，清理工具生成的过期片段，拒绝 `public/audio` 中额外的未登记文件。

为保留 `file://` 离线双击能力，FLAC 由独立经典脚本携带 Base64 数据，按需加载，解码后移除载荷。发布必须同时保留 **`assets/`、`word/`、`audio/`**；首屏 HTML 不内联音频包。

## 入场、输入与弹反反馈

首屏继续时播放 `ui.enter`，用 1.6 秒符印扩散与渐隐揭开主菜单；过渡期间菜单不可操作，重复按键不会穿透。开启减少动态时缩短至 240ms，并关闭装饰动画。

有效词令字符播放 `ui.type`，战斗施法字符播放 `key`，包括输入错误的字符。两者使用 110ms 短音和末尾淡出，每类最多 8 声部、18ms 内置间隔，支持连续打字且避免长尾堆积。音效配置的可选 `duration` 单位为秒，按播放速率换算实际结束时间。

空格弹反起手播放克制的 `parry.activate`；成功时叠加 `parry` 撞击与 `parry.ring` 共鸣。一次窗口即使反射多枚弹道，也只触发一次成功反馈。成功特效由 `CounterPulse` 复用原生实例批次绘制：接触闪光、双层冲击环、放射碎片和位移环，配合 45ms 命中停顿与轻微震动。低、中、高档递增装饰，减少动态关闭位移。

## 本次验证

正式构建、应用与工具 TypeScript 检查、16 项音频/防御单元检查，以及真实 Chrome 的音频 7 组、首屏 6 组、反馈 3 组检查通过。覆盖全部 112 个片段的解码、并发和缓存上限、真实 PCM 左右声道、暂停/静音/隐藏/释放、离线启动、切片试听与保存，以及入场期间输入隔离、连续打字、弹反多弹道反馈去重和三级前景特效。报告和 1080P 截图位于 `docs/test-output-audio/`、`docs/test-output-startup/` 和 `docs/test-output-feedback/`。

偏左声源的左声道 RMS 约为右侧 4.4 倍，偏右时右声道约为左侧 5.4 倍。短战斗检查中缓存约 23.6MiB，这是检查场景记录，不代表所有战斗的峰值。原架构检查仍有 TypeScript 7 兼容性提示，独立 TypeScript 编译检查已通过。
