# M4 天赋图基础建设方案

本方案把 M4 的第一项工作确定为天赋图的数据、购买规则和程序化生成。实际状态见[阶段总结](../STAGE-SUMMARY.md)，未完成事项只维护在 [TODO](../TODO.md)。这里记录实现方法和验收要求，不把计划写成已经完成。

## 1. 阶段安排

- Godot 按新游戏建立成长与存档，不建设旧浏览器数据的导入、导出或转换。旧源码与内容去向表继续用于理解设计，不用于搬运账号进度。
- M4 先完成天赋图基础，再接正式配置、成长保存、获取与事件资产。现有 M3 编译器、逐份资产和战斗接口作为接入基础；具体功能缺证继续保留，不伪称 M3 已全部验收，也不让整体平衡成为 M4 开工条件。
- 构筑体验要结合真实图上的进入顺序、路径费用和选择空间判断。图可用后再做配置与战斗联动观察，避免只凭试验场任意勾选的结果判断成长路线。
- 整体收益、完整构筑强弱、成长曲线和难度平衡放到 M5 完成后的 M6。M4 仍及时检查购买、撤点、编译、保存和规则的正确性。

## 2. 参考图真正值得采用的部分

用户提供的两张图展示了三种尺度：远看是连接各处的大路线，中间是圆环、多边形、弧线和短分支组成的局部群，近看是作用与重要程度不同的节点。图形主要由真实节点和连线形成；不需要在散点图下面画几个装饰圆，假装已经形成结构。

参考原图已保存：[图一：圆环、分支与金色路线](../build-system-design/references/talent-graph-reference-01.png)、[图二：不同规模的几何节点群](../build-system-design/references/talent-graph-reference-02.png)。它们只用于结构和阅读层次参考，不进入游戏素材。

本项目采用这个组织方式，沿用自己的金丝水晶材质和四书位置。次要节点用于明确的属性改善，主要节点引入或明显加强机制，质变节点改写玩法并承担明确代价。三者同时通过尺寸、外轮廓、图标细节和文字层级区分，不能只靠颜色。

必须保留的区别：

1. **效果定义**回答节点做什么、费用多少、需要哪些天赋。
2. **成长连线**回答从当前已分配区域还能买到哪里。
3. **几何布局**回答节点放在哪里、连线怎么走、何时显示名字。
4. **玩家配置**回答当前买了什么、还剩多少点、这次修改影响什么。

布局不得为了好看改变效果前置、悄悄增加收费节点，或在每次打开页面时换一张图。图上的普通连线只表达可扩展的成长路线；组合关联、许可、互斥和演化放在详情里解释，不全画成横跨地图的线。

## 3. 生成方法的选择

推荐采用**先组织局部图形，再安排整张图，最后生成和检查连接**的分层方法。几何图形是一组可重复使用的构造规则，不是一套手绘坐标，也不规定每个机制必须有相同数量的节点。

旧方案从语义散点直接挑选平面近邻边，可以减少交叉，却不会自动形成参考图中可识别的圆环、分支和路线。它还容易把“几何上连得过去”误当成“玩家能按合理顺序买过去”。本方案保留语义接近、确定生成和严格几何检查，改用局部结构来控制阅读节奏和路径用途。

内容作者只维护有业务含义的信息：节点类别、概念、机制依赖、数值系列、哪些方向适合互通，以及少数确实需要保留的成长关系。程序负责节点归组、局部形状、朝向、间距、整体位置和候选连接。不得给 206 个节点逐个填写 x/y；不得靠节点 ID 的散列制造位置扰动来伪装自然分布。

生成发生在开发期。结果作为带版本的图资源进入游戏；玩家打开、拖动、缩放、购买时只读取这份图，不重新求布局。所有生成阶段使用稳定排序和固定的选择顺序，同一输入产生同一结果。

旧 Web 实现的复查也支持这一选择：`legacy/web/src/content/talents.ts` 先用固定分支与桥接配方定义成长边，`legacy/web/src/shared/graph-layout.ts` 再用整体弹簧布局摆放多书主图。旧寻路对交叉只增加代价，失败时仍可退回直线；`legacy/web/tests/graph-layout.test.cjs` 允许交叉数不超过成长边的 12%。历史记录中的 14 处交叉不是本轮重测结果，也不能证明旧拓扑本身无解；它说明过去的“生成和测试通过”不满足当前目标。节点占位还必须按实际层级计算，不能布局时所有节点一样大、绘制时再单独放大质变节点。

## 4. 当前源码能用什么，必须补什么

当前目录实际包含 4 个书根、60 个机制节点、20 个质变节点和 122 个数值实例。数值实例来自 30 个系列，各有独立 ID；不能把它们折成 30 个可重复点击升级的点，那会丢掉空间与路径选择。候选文档的 `B-frost` 等只是书根说明，运行 ID 沿用 `frost`、`flame`、`storm`、`spirit`，不再造一套别名。

`TalentDefinition` 已有点数成本、前置、模式槽及规则，`BuildCompiler` 已检查内容和模式并生成战斗快照。但它没有图连通、购买预算、合法购买顺序或撤点处理。开发试验场直接勾选能力的合法性，不能代替正式天赋分配。

采用独立的 `TalentAllocationService` 处理图上分配，再将合法结果交给现有 `BuildCompiler`。编译器继续负责战斗规则，不读 UI 坐标；图生成器和页面不能各自实现另一份购买判断。

## 5. 数据结构和文件职责

以 Godot Resource 作为正式定义与生成产物，纯计算状态使用 RefCounted。先在下列职责内实施，只有文件确实过大再拆分，不提前建设通用图框架。

| 数据／模块 | 主要字段或接口 | 职责 |
| --- | --- | --- |
| `TalentDefinition`／书根定义 | 现有 ID、规则、成本、前置 | 原生效果的权威来源；不保存位置，不因补图数据而重写 |
| `TalentNodeProfile` | `definition_id`、`node_kind`、数值 `family_id`、语义 profile 引用 | 图的附属定义；通过 ID 引用效果，不复制规则或成本 |
| `TalentSemanticProfile` | 概念整数权重、规则涉及的对象／操作、输入／输出、代价类型；规则可用条件的查询引用 | 解释亲近性和当前用途；不用中文名字猜关系 |
| `TalentGraphSpec` | 稳定图 ID、书根锚点、局部图形规则、允许／禁止邻接、少数必须保留的成长关系、统一几何参数 | 图生成的业务输入；无逐节点坐标 |
| `TalentGraphDefinition` | 节点 ID、无向成长边、邻接索引、根 ID、拓扑版本与哈希 | 正式购买网络；不含账号状态 |
| `TalentAtlasLayout` | 同一组节点坐标、节点群、折线／圆弧采样、轮廓、标签候选位置、图边界、布局版本与验证摘要 | 静态显示产物，与拓扑一同发布 |
| `TalentAllocation` | 主书、已分配节点集合、模式／副书／独卷形状／K19 材料选择、修订号、图版本 | 一份出征配置；不含本局遗物 |
| `TalentProgress` | 累计有效字符、已领取结算记录、普通／God 模式、各主书配置 | 本游戏成长；点数由统一政策计算，不从 UI 累加 |
| `TalentAllocationService` | `inspect_node`、`preview_add`、`preview_remove`、`validate`、`commit` | 购买、撤点、整份合法性和一次提交 |
| `TalentRoutePlanner` | 输入图／配置快照及目标，返回合法顺序、费用、模式选择与搜索状态 | 预览路线；不直接分配或扣点 |
| `TalentGraphGenerator` | 读取正式目录与图规则，生成拓扑、布局、验证报告 | 开发期工具，不在玩家打开页面时运行 |

建议路径：定义在 `game/content/talents/`，分配与成长在 `game/progression/`，生成工具在 `tools/graphs/`，生成产物在 `game/content/generated/`，页面与绘图在 `ui/talents/`，开发观察入口在 `development/talent_atlas_lab.tscn`。这些是待实施的目标路径，不表示文件已存在。

### 5.1 必须分开的关系

| 关系 | 表达与用途 | 是否默认画线 |
| --- | --- | --- |
| 成长邻接 | 无向边；从已分配网络扩展一个节点 | 是，唯一普通路线 |
| 购买前置 | 现有 `requires_all`／`requires_any`；例如 K07 要求 T09 和 T29 | 否，详情列出并可定位 |
| 使用条件 | 当前配置是否产生所需材料、对象或事件 | 否，详情说明当前缺什么，不自动变成硬购买前置 |
| 模式冲突 | 同一模式槽及既有明确互斥 | 否，选择和撤换时解释 |
| 内容亲近性 | 对象、操作与概念权重 | 否，用于归组、位置和候选邻接 |
| 特殊遗物许可 | 从实际分配天赋生成 | 否，详情列出机会，不保证掉落 |
| 资产演化／事件引用 | 获取与事件规则 | 天赋图不画，后续遗物图分别表达 |

固定 ID 负责身份，节点类型负责表现，二者分开。`N`／`T`／`K` 前缀可以在首次生成附属图定义时帮助填充类型，正式运行时不靠字符串前缀判断玩法。图生成所需的语义在正式资源中补齐；不能每次运行时解析候选 Markdown，也不能维护另一份伤害公式。

使用条件的查询复用编译后的能力、材料与形状信息，并为少数缺少表达的操作补具名查询。它只用于说明与路径审查，不开放任意表达式解释器，也不伪称仅凭静态查询证明战斗收益。

### 5.2 版本与保存

`content_version` 管效果与前置，`graph_version` 管成长边，`layout_version` 管坐标和显示。纯布局变化不重置配置；成长边或前置变化才重新验证配置。无效时保留已赚成长并提供重配。保存已分配 ID 与模式，不保存从 UI 推算的花费或可反向修改资源的脚本。

生成输出使用内容、语义、拓扑、布局算法和字体测量版本的哈希。游戏加载时检查版本对应；缺失或不匹配的开发产物明确报错，不能静默退回旧布局或现场随机生成。发布时只带验证通过的正式产物，失败候选留在开发证据目录。

### 5.3 可以直接落到代码的记录与调用约定

| 记录 | 最少需要的字段 |
| --- | --- |
| 节点索引 | 稳定 `definition_id`、连续 `index`、类别、系列、根身份；`index` 仅供当前产物计算，存档只用稳定 ID |
| 成长边 | `edge_id`、两个端点 ID；端点按固定顺序规范化，同一无向边只存一次 |
| 节点群 | `group_id`、成员 ID、构造类型、入口／出口节点、局部连接；不包含账号状态 |
| 节点布局 | 节点 ID、量化坐标、实际外轮廓、各文字显示档的标签位置与占位 |
| 边布局 | 同一 `edge_id`、实际绘制的采样点列、包围盒；不另造一份显示专用连接关系 |
| 分配预览 | 原配置／进度修订、内容／拓扑版本、拟提交配置、点数变化、连带移除、待选模式、许可变化、诊断、合法顺序 |
| 路线结果 | `found / proven_optimal / unknown / infeasible`、新增顺序与选择、费用、适用快照；`proven_optimal` 必须有完整搜索依据 |
| 生成报告 | 输入哈希、每阶段计数与耗时、失败条件与涉及 ID、几何指标、逐目标合法顺序及费用；验证报告不参与战斗 |

公开接口接收明确上下文：`AllocationContext` 包含只读目录、正式图、点数预算和普通／God 模式；`preview_add(allocation, node_id, choices, context)` 与 `preview_remove(allocation, node_id, context)` 都无副作用。`validate` 可输出一次合法顺序；`commit` 才负责保存和替换状态。多节点路线先整体预览、一次确认后提交，任一步失败都不留下半条路线。

分配服务内部将前置、邻接和模式整理成按节点索引查询的数据，购买入口、撤点和路线搜索共用同一个判断函数。搜索每扩展一个状态不重新加载目录或编译整套战斗；找到候选路线后，才用完整编译检查和分配重放确认结果。校验集中在内容装载、公开请求和提交处，不给每个私有循环再加一层兜底。

`choices` 明确包含具名模式、副书、独卷形状和 K19 的 `calibrated_materials`，不能只存一个模式 ID。配置、预览、路线状态、保存和转为 `BuildSelection` 共用这份选择结构。合法选项保留；来源消失的选项在预览里标明并要求重新选择，不擅自换成另一种材料。

数据流为：**内容与图规则 → 开发期生成／检查 → 静态图资源 → 分配预览 → 保存合法配置 → 转为 BuildSelection → 现有编译器 → 战斗**。页面只能提交分配请求；材质、高亮和节点距离不能决定购买资格。Resource 在装载后按只读使用，玩家变更写入独立配置副本，不修改共享定义。

## 6. 正式购买、撤点和路线

### 6.1 一次购买

免费主书根始终属于配置。当前起值沿用其他书根 2 点、数值 1 点、机制 2 点、质变 4 点；普通 60 点上限和成长曲线暂作功能标尺，M6 才整体校准。

`preview_add` 按以下顺序返回具体结果：ID 与版本有效 → 尚未分配 → 与已分配节点相邻 → 主书限制和显式前置满足 → 没有模式冲突 → 有足够点数 → 所需模式选项完整 → `BuildCompiler` 能编译。需要选择副书或独卷形状时，预览返回待选择项，不能先扣点再打开选择框。

`commit` 检查预览对应的配置与进度修订号，重新应用同一份正式分配规则，再保存并替换内存配置。沿用项目临时写入、验证和有效备份的保存方式；保存失败时保留原配置并显示具体原因。选中节点只打开详情，购买有明确操作；不把鼠标第一次点击同时当成阅读和花点。

当前主书决定原生主术和终式；买到其他书根仅开放既定材料和加工入口，不能切换主书。切主书在出征配置中进行，各主书配置独立保存。

书根仍使用 `BookDefinition`，不把它伪装成另一份 `TalentDefinition`。图成本服务统一计算“本书 0、其他书 2”；分配上下文始终包含主书根，转换为 `BuildSelection` 时由适配函数规范化，保证根前置可识别、主书规则只编译一次。该适配不夹带本局遗物或临时能力作为购买条件。

### 6.2 合法顺序与撤点

验证保存的配置时，从免费根开始，反复加入“已与加入集合接通、前置已满足”的节点，最后调用同一编译器检查模式。输出实际加入顺序；剩余节点如果互相依赖却没有第一步，判为无效，不能只检查最终集合是否连通。

撤点先移除指定节点，再从免费根重新构建剩余配置：每轮只加入与已加入集合相邻、且前置已满足的剩余节点，直到不能继续。最终没能加入的节点全部进入连带撤点预览。这里复用完整配置验证的正向过程，不只检查剩余节点能否互相提供条件。存在另一条已购买路径时保留仍合法的节点。

一个必须覆盖的例子：A 需要 B 或 C，B 需要 A，三者都与根相连；原来按 C → A → B 买入合法。撤掉 C 后，A 与 B 虽然互相满足最终条件，却买不出第一步，因此也要退回。这是分配契约的测试用例，不表示现有候选已经发现这个循环。

随后清理失去来源的选择并编译：失去 T58 则清理独卷形状；仍保留 K19 但其所选材料已无供给，则返回待重选材料，而不是自动删掉 K19。比如寒主书、炎副书与 T13 曾允许 K19 选寒气和电荷，撤去唯一电荷入口后，需要重选合法材料。预览列出全部退回节点、总退点、能力／许可与选项变化；必要选择完成并确认后一次提交。

God 只取消点数预算限制，仍检查路线、前置、模式和配置合法性。战斗期间不改变出征天赋图；已有开发试验场的战斗中换构筑能力不进入正式成长操作。

### 6.3 路线预览

搜索状态包含已分配集合与全部 `choices`，费用是新增节点的实际点数。普通最短路只能作为候选或乐观下界，不能作为合法购买路线：到同一个节点时，此前取得的前置和材料选择可能不同。

用稳定顺序的优先队列搜索，记录每个状态的最低成本；生成器可提高预算，UI 使用可取消的分段搜索。找到但未证明最优时写“找到一条路线”，预算用尽时写“暂未找到路线”，只有穷尽或明确条件冲突才写“无法到达”。结果携带配置修订号；应用前沿正式分配器逐步重放，不能依据过期预览直接花点。

主书和模式明确不兼容的目标不参与该配置的路线承诺；详情直接解释限制。每个适用书根到每个保留节点至少要保存一条合法顺序作为生成验收证据，而非只给一张连通矩阵。

搜索分两步落实，避免第一版直接遍历 206 个节点的全部组合：

1. **先找可用路线。** 从目标的显式前置开始，将 AND 前置全部列入、OR 前置按费用和稳定 ID 尝试；用图上短路径连接这些目标，沿正式分配规则逐步重放。途中遇到新的前置或模式条件，加入本轮候选再检查。开发期生成的各书合法顺序可以作为候选起点，但玩家当前配置可能有冲突，仍需重放。
2. **再按预算改进。** 把已经找到的合法方案作为费用上界，在状态搜索中继续找较便宜的方案。相同已买集合与全部选择去重；只有有证明的下界才能剪掉状态。第一步找不到不能判无解，有限搜索也不承诺总能找到最便宜路线。每帧按时间片推进，初始总上限采用 50,000 次状态扩展，随实际耗时调整，取消或配置变化立即使结果失效。

“从根能否走到目标”和“现在够不够点”分别显示。可预览超过当前已赚点数、但未超过普通成长上限的未来路线；应用时必须满足当前预算，不能自动买一半。生成报告另外记录忽略点数限制的结构可达性；普通模式仍须找到 60 点内的路线见证，超出则暴露具体费用，不能用 God 可达冒充普通可用。这里检查基本可用，不提前规定路线收益或毕业强度。

## 7. 程序生成的具体步骤

### 7.1 先补语义，不从效果文案猜坐标

保留当前 `game/content/build/*.tres` 作为原生效果定义的权威来源。`tools/content/import_m3_catalog.py` 是一次性候选导入工具，会从 Markdown、脚本参数映射和部分旧 Web 内容重写资源；补图数据时不运行它，不顺带重导入遗物。

在 `tools/graphs/` 增加开发期语义整理入口，读取正式目录和一份 `talent_semantics.json`，输出附属的 `TalentNodeProfile`／`TalentSemanticProfile` Resource。JSON 只补概念、系列、少数明确关系和例外说明，不复制名称、费用或战斗数值。操作到语义的映射从现有规则提取对象和输入输出，特殊节点允许明确补充。图生成阶段读取这些附属资源与正式效果定义，不解析玩家说明。

首次补数据前后比较全部效果、费用和前置字段，必须相同；语义资源缺 ID、引用未知 ID 或类型不符就报错。这样后续正常修改 `.tres` 效果不会被图工具覆盖，图工具也不能以“重新生成”为由恢复旧数值。

概念沿用[数据与算法](../build-system-design/06-DATA-AND-ALGORITHMS.md)的受热、保存、回收、路径、词形等注册表。权重归一到整数 0–1024；数值系列继承被修改参数的用途，而不是所有 N 节点都视作通用铺路点。未知概念、没有语义的 ID、重复数值实例在输入边界报错。

相似度仍比较操作、对象、输入输出衔接与代价，但必须记录得分来自哪几项。相似度决定候选，不授予能力，也不能覆盖明确的禁止邻接或购买前置。

### 7.2 把内容组织成局部节点群

1. 以机制节点为初始小组；按亲近度稳定排序合并相关组。一般每组容纳 1–3 个机制节点，总节点目标 4–10 个，初始上限 12；这些是统一布局参数，不是每组必须凑满的数量。
2. 质变节点优先靠近其明确前置。多个前置分散时，先尝试合并相关小组；超过上限或语义不合适，就保留独立的质变分支，不能强行画跨组前置线。
3. 122 个数值实例按具体用途分配到合适小组或连接段。先处理可放位置少的系列，再处理通用系列；每次比较语义、最早可用性、同系列密度和剩余空间，最后按 ID 打破平局。以有限次数的交换修正局部拥挤，分配不完则明确失败。
4. 同系列一般每个小组不超过两份，避免一个小圈堆满同种增益；没有合适位置时回到内容审查，不复制、丢弃或改名充数。
5. 四个书根各自留出向内、向外和侧向的入口。其他节点可以跨书共享，不为每书复制一份相同机制。

节点群只是生成与阅读单位，不是游戏里的第五种资产，不需要玩家先买“整群”，也不自动形成整群奖励。群 ID 由成员集合和规则版本生成，不能参与存档购买身份。

合并小组时，比较成员之间的平均亲近度和明确前置关系，避免只因一条较强关联把两个用途完全不同的大组粘在一起。容量、书籍适用性和模式绕行要求先作硬筛选，再按得分和成员 ID 排序；可单独成组的机制无需为了达到目标大小继续合并。分配失败时先调整归组与数值位置，只有规则本身冲突才进入内容取舍。

### 7.3 生成局部连接与几何图形

先决定这个小组需要哪些真实选择，再选能表达它的图形。第一批只实现四类构造，已经能组合出参考图的大部分阅读层次：

| 构造 | 适用关系 | 实际连接规则 |
| --- | --- | --- |
| 短链／开弧 | 同一机制的逐步改善、通往相邻区域 | 按实际节点排成连续路径，弧线不额外跨过中间节点 |
| 分叉 | 一个入口后有两种不同改善方向 | 分支各有用途；端点可继续连接其他组，不全部是死路 |
| 菱形 | 两条有不同收益的短路线，之后汇合 | 两侧都能合法购买；不是靠强制多花点装出假选择 |
| 圆环／多边形 | 同组多方向出入或两种绕行方式 | 相邻节点构成真实环路；可在内侧或外侧接一个质变终点，不画虚假的完整装饰环 |

质变节点以及相互冲突的模式节点默认作分支或终点，不能成为跨区唯一通道。确需让它们参与穿越时，必须同时存在不依赖该模式的合法绕行路线。主干移除所有互斥模式节点后仍应连通各书根和通用区域，防止选一个模式就截断半张图。

每类构造声明可容纳的节点角色、内部候选边和对外连接位置。对外连接位置只是已有节点上的出口方向，不是新的收费节点。实际节点按前置深度、作用衔接、类型和稳定 ID 分配到位置；只枚举有限的旋转、镜像和等价排列，不对 12 个节点做任意全排列。

局部几何使用统一尺度：正常阅读倍率下，次要节点直径约 18–22 px，机制节点约 32–38 px，质变节点约 48–56 px，书根约 72–88 px；相邻节点中心距以 76–104 px 起步，再按外形和标签占位增大。这些是排版起值，不是战斗平衡参数。

圆环的半径由节点间距和个数计算：相邻等距点数量为 n、目标弦长为 d 时，取 `r >= d / (2 sin(π/n))`，并加上中心质变节点的轮廓与留白要求。分叉按枝长分配角度，菱形按两路各自节点数计算两侧长度；不为图形对称强行要求两边内容数量一样。

实例说明：保存空间、护页和防御折算可以形成有两条路径的小环；护页的质变沿分支放置。玩家可选择先扩空间还是先取防御，而质变仍需满足真实前置。这个例子解释构造用途，不把具体 T／N 节点手工固定为最终路线。

### 7.4 放置节点群，形成整图

1. 书根位置沿用圆盘约 0.4R：火 -140°、雷 -90°、冰 -40°、纸 90°，角度按屏幕坐标向下为正。这四个宏观锚点是设计输入，不是逐节点手绘。
2. 每组按成员概念计算对四书的权重，形成偏好的区域和朝向。专属用途向本书外侧延展，共用用途进入内侧和书间空间；同时考虑与其他组的真实衔接，避免所有共享节点挤到圆心。
3. 将局部图形连同节点、标签和连线间距作为一个整体占位。按根周入口、前置紧密程度、组大小、ID 的固定顺序放置；从偏好位置开始枚举规则化的环带位置和有限朝向，选择无碰撞且语义偏移最小的位置。
4. 对拥挤处只移动／旋转整个组或改换其合法局部构造，保持图形可识别。先处理碰撞和不可连接，再改善紧凑度；不让审美分数抵消硬错误。
5. 半径 R 从实际节点与占位估算，按统一档位扩展；每次重新定位四书及各组。检查书根距中心和实际内容边界的比例，不能加一个空外框假装达到 0.4R。

最终画面允许大小不同的局部图形、疏密变化与空白。既不是四个封闭扇区，也不是所有节点等距贴在几条同心圆上。

### 7.5 生成组间路线

先枚举空间相近且语义允许的出口节点对；距离阈值同时参考两端的局部节点间距和全图半径，初值沿用近邻中位距的 1.8 倍及 0.18R 上限。组较大时也不能给某条跨屏长线开特例。

候选连接优先用直线；局部绕行可以用一条浅弧或短折线，但路径长度不能明显超过端点直线距离，初值为 1.35 倍。不能用贴着整圈外缘的长弧绕过交叉。中途若需要真正的过渡节点，必须安排已有且有用途的数值或机制节点，随后重做该段布局；不能把没有节点的折点当成购买步骤。

连接逐条加入，检查它与已有局部／组间线段、节点外形、标签和光晕辨识间距是否冲突。相交是拒绝条件，不是多付一点寻路代价后仍可通过。共享端点允许，出口夹角过小则改出口方向。普通节点度数目标 2–4、上限 5，书根上限 6；终点允许度数 1，不为满足度数硬凑线。

先连接全部组与四书，再加入能提供真实绕行或跨区选择的环路。不能止于一棵最小生成树；也不能为了增加环数，把所有几何近邻都连起来。对可购买主干检查单点断路，特别排除唯一中央收费枢纽。未连接成功时回到整组位置或局部出口调整，不降级为未经检查的直线。

具体选边顺序：先加入规范中明确要求的成长边；然后从剩余候选中优先连接尚未接通的部分，依次比较早期入口需要、语义亲近、距离和端点 ID。每次都重查实际路径与度数，失败候选不加入。基础连通后，优先补能绕开现有单点通道、明显缩短合法绕行或提供不同沿途收益的连接；既无结构作用、也无内容用途的边不加。相交时不能仅交换线的画法，应回到出口、局部构造或整组位置重新尝试。

### 7.6 几何检查与购买检查一起反馈

完成一个候选图后，按第 6 节的同一分配规则求路线见证。缺某个前置的路径需要调整前置附近的连接或归组；不能直接把这个前置从内容定义删掉。初始 2 点至少应能得到一种当前主书可用的机制。记录相邻／对侧书根实际费用与沿途用途，8–14／14–22 点只作候选观察标尺，不能当作 M6 已完成的平衡结论。

沿合法顺序检查节点当时的用途：它修改的数值、对象或操作是否已有入口，是否需要尚未取得的另一项能力。按现有框架，最多连续两个当前无直接用途的节点，随后须有明确用途；数值大小是否划算留到 M6。用途查询无法可靠判定时列入人工内容审查，不能把“无法证明有用”默认为有用，也不能偷偷升级为新的购买前置。

把失败定位到具体阶段：缺语义、局部图形不适用、空间冲突、无可用近邻、前置无法按顺序取得、模式导致断路、搜索预算耗尽。最后一类只表示本次生成没有找到结果，不宣称数学上不存在解。

每次修改有确定优先级：交换等价出口 → 旋转／镜像局部图形 → 交换相邻组位置 → 改换合法图形 → 扩大局部／全图间距。初始最多 64 轮完整修正；输出每轮改变与冲突数量。若失败集中在内容关系，停止扩大画布，回到语义审查。调参必须作用于一类情况，不写 `if node_id == ...: position += ...`。

### 7.7 发布几何与产物

所有坐标最终量化为 1/16 逻辑像素。开发期将圆弧／曲线采样为实际显示折线，最大偏差控制在 0.25 逻辑像素以内；验证和运行使用同一条采样路径，不能检查直线却绘制另一条曲线。节点外轮廓和线条宽度也参与间距检查。

当前图域坐标限制在 ±32768 逻辑像素，量化后的线段方向判定使用 64 位整数；不做整数范围不明的高次几何计算。交叉、共线重叠、线穿无关节点和显示标签冲突分别记录。第一版不引入 CGAL、Boost 或自制复杂三角剖分：只发布通过实际线段检查的构造结果；不能据此保证任意内容关系都可排成合格图。

产物至少包含：全部节点及边、群与局部构造、每条边的实际路径、标签占位、内容／拓扑／布局哈希、完整诊断、适用书根到目标的合法购买见证和费用摘要。开发命令先写候选目录，验证成功后才一次发布拓扑与布局，不覆盖最后一份可用图。生成器失败时退出失败，不把旧图拿来冒充当前输入的结果。

第一版将拓扑和布局作为同一个 `talent_atlas.tres` 的子资源保存，避免分别替换两个文件造成版本错配；它们在逻辑上仍是两个独立定义。详细诊断与逐步生成记录写入开发证据目录。运行时只读取紧凑产物和必要的合法路线候选，错误检测不触发布局求解。

## 8. 节点分级与 Godot 表现

| 节点层级 | 正常阅读时的表现 | 远看时保留什么 |
| --- | --- | --- |
| 次要数值 | 小圆或简洁切面，单层细金丝，小符号；名字按缩放显示 | 点与已买路线，避免铺满文字 |
| 主要机制 | 较大晶体轮廓、独立机制图标、清晰名称 | 图标轮廓与主要路线 |
| 质变 | 更大的多层轮廓、明确的特殊图标；详情把收益和代价并列 | 独特形状，不能靠亮度与机制节点混淆 |
| 书根 | 沿用法书识别图形，最大轮廓与名称 | 四个空间锚点 |

节点等级和购买状态分开绘制：已经分配、当前可买、缺前置、冲突、点数不足各有可辨的边缘／符号提示，详情写具体原因。正文不发过曝光；常驻特效保持克制，减少动态模式下仍能读懂状态。

不直接把 `GraphEdit` 当成正式游戏页面。它面向可编辑端口和连接，自动排布也不理解本项目的购买及几何要求；这是适用性判断，不是认为它不能画图。采用 `Control` 页面承接鼠标与固定 UI，内部 `Node2D`／CanvasItem 绘制静态路线、节点图形和状态层。常规线段按状态批量绘制，只有数据、缩放显示层级或选中状态变化时请求重绘。Godot 官方接口依据见[第 12 节](#12-研究依据与仍需实施验证的边界)。

字体采用项目正式字体测量。宏观倍率只显示书根与少量重要名称；中间倍率显示机制和质变名；近看显示数值节点名。各档分别检查占位，切换有小幅迟滞避免滚轮临界处闪烁。选中节点始终在固定详情显示全文，不用缩到全图仍显示 206 个名字的方式制造拥挤。

每个显示档内，图中文字、节点和路线使用同一世界坐标缩放，保持已检查的间距；若字体为可读性设置屏幕最小字号，几何检查须使用该档最小缩放时的最大占位。不能只验三张截图，却让两个倍率之间的文字互相压住。页面正文和固定详情始终使用屏幕字号。

屏幕空间固定的标题、预算、搜索和详情不跟随图缩放。拖拽平移，滚轮围绕鼠标缩放；点击与拖拽用屏幕距离阈值区分。检索支持名称、概念和 ID，聚焦时扣除详情覆盖区，不能把目标移到面板下面。命中检测使用同一坐标变换下的节点轮廓与最小点击范围；邻近节点范围重叠时选离中心最近的一个，不同时购买两点。

普通 UI 不建立 Tab／方向键焦点链或悬浮 Tooltip。鼠标悬停只作轻度反馈，单击选中读详情；文本框点击后才接管输入，Esc 按现有页面层级返回。图谱是局外页面，不把字母键传进战斗词会话。

## 9. 实施顺序和每步出口

| 顺序 | 实际要做的事 | 可审查出口 |
| --- | --- | --- |
| 1. 目录与图输入 | 为全部 206 项补类别、系列、语义及关系索引；明确书根成本和适用条件 | 无缺失／重复 ID；运行前置与购买前置分开；给出每项语义来源 |
| 2. 分配基础 | 实现配置、点数政策、购买／撤点预览及提交、整份顺序验证；接现有编译器 | 在小图上正确处理环路、AND／OR 前置、模式、撤点、God 与失败不改状态 |
| 3. 局部生成 | 实现四类图形及稳定归组／数值分配，建立开发观察页 | 用真实保存、防御、热处理等内容生成不同结构；没有手填逐节点坐标，无虚假收费点 |
| 4. 全图生成 | 接四书锚点、整组放置、组间连接、反馈修正、几何与购买报告 | 完整候选图；零交叉且全覆盖；适用目标有合法购买顺序；失败有具体原因 |
| 5. 图谱交互 | 主控实现节点层级、开放式详情、缩放／拖拽／搜索、路径与撤点预览 | 真实窗口可清楚区分三类节点，并能看懂一次购买与连带撤点 |
| 6. 正式配置与保存 | 从出征页进入天赋图，普通／God 独立保存，出征冻结合法配置 | 保存重开一致，取消不改配置，合法天赋进入正式战斗，纯布局更新不退点 |
| 7. M4 后续接入 | 接人工字符成长、正式奖励、许可、资产报价和事件期限；复用既有资产实例与回执 | 获取和成长全流程可用，不另建图规则或资产身份系统 |

第 3 步的小图用于尽早检查算法和阅读方式，不能成为只交少量演示节点的终点。第 4 步必须使用完整候选；第 5 步也不能只给静态图片。遗物图先复用成熟的视口、绘图和检索基础，按演化关系另建业务输入，不要求第一批天赋工作同时完成 171 件遗物的独立完整图。

## 10. 如何判断做对了

**数据与购买：** 同一 ID 只有一份节点；所有候选都被使用或有明确内容变更；补图元数据不改变效果字段，购买判定来自同一服务。覆盖免费根、其他书根、预算不足、AND／OR 前置、撤点后互相支撑却无起点的循环、模式选择、互斥、替代通路、撤点连带、K19 材料失效重选、配置过期和 God 隔离。进入战斗的天赋来自合法配置，不能把开发勾选当作正式购买。

**生成与几何：** 同版本输入重复生成相同哈希；量化和曲线采样后没有交叉、重叠、穿点或对应显示档的文字遮挡。图中真实存在有用途的环路、分支和可辨的局部形状，四书不靠唯一枢纽连接。增加、删除或修改一项内容时，检查哪些组和路线变化，不要求整个图永不移动，但任何版本变化都可解释。

**可购买性：** 在适用书根下记录所有目标的合法顺序与真实点数；无模式节点成为强制跨区关卡。初始预算能拿到可用机制。长路线的用途与代价按现有能力解释，不假定未来随机遗物必然补齐。搜索未完成与明确不可达分开报告。

**实际交互：** 分别查看全图、中等倍率和阅读倍率；测试缩放时的定位、拖动与点击区分、固定详情、长名称、预算不足提示、路线应用、取消及保存重开。检查图形和文字、真实购买各自成立；不能用几何零交叉替代画面审查。

**成本与性能：** 先用 206 节点及实际边数测生成时间、静止绘制、拖动、缩放和检索；打开图不运行布局求解，停留时不反复重建几何。不为未知规模预置多线程、全套缓存或 GPU 计算；路线搜索先分段可取消，只有测到问题再调整。完整运行性能和收益仍在 M6 验收。

## 11. 当前可执行的第一批工作

进入实现时从“完整语义输入＋分配服务＋局部图形生成器”开始，三者共同产生能购买的真实小图，再扩到完整图。先验收这种组织方式能否在实际内容上成立，之后完善材质和装饰；不能先做一张漂亮但没有正式数据和购买规则的展示图。

前两步不需要新的玩法决策。若完整数据出现无法同时满足的硬关系，提交具体节点、前置、路线和冲突图；优先调整归组、连接和统一参数。只有必须改变购买前置、删改内容或放宽零交叉等产品约束时，才向用户列出方案和影响，不能由生成器悄悄决定。

## 12. 研究依据与仍需实施验证的边界

- 当前目录、编译与试验场依据：`game/content/talent_definition.gd`、`game/content/build_catalog.gd`、`game/build/build_selection.gd`、`game/build/build_compiler.gd`、`development/build_lab.gd`，以及候选目录与框架。当前模型没有正式分配服务或图产物，本轮没有假定它们已经存在。
- [Godot GraphEdit](https://docs.godotengine.org/en/stable/classes/class_graphedit.html) 的端口、连接编辑与排列能力用于适用性比较；[自定义 2D 绘制](https://docs.godotengine.org/en/stable/tutorials/2d/custom_drawing_in_2d.html)用于 CanvasItem 绘图选择；[ResourceSaver](https://docs.godotengine.org/en/stable/classes/class_resourcesaver.html)用于开发期保存 Resource 产物。实现时按项目锁定引擎核对具体接口。
- [Boost 平面性检查文档](https://www.boost.org/doc/libs/latest/libs/graph/doc/html/graph/algorithms/planar/boyer_myrvold.html)说明抽象图的平面性可单独验证；这不等于给定书位、近邻距离、字体占位和购买条件下一定有合格布局。本方案不因此引入 Boost 依赖。
- 本轮交付是方案及文档调整，没有运行布局算法、生成正式图、修改游戏源码或进行战斗／平衡测试。具体间距、组规模和生成预算都要在完整候选上验证；报告应区分实现错误、搜索未完成和真正的内容冲突。
