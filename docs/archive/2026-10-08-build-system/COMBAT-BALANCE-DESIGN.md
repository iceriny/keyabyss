# 战斗构筑的统一收益模型

> 历史归档：2026-10-08 调整范围前的设计、计划或证据。正文中的要求与“下一步”不构成当前任务；当前实施见[交接文档](../../migration/AGENT-HANDOFF.md).

定位：整体构筑的收益设计契约。公式、初始标尺和统一评估方法在此维护；内容仅部分接入，当前尚未通过完整收益与难度验收，见[阶段总结](STAGE-SUMMARY.md)。

适用范围是法书、天赋、遗物、事件及其组合，配合[整合设计](build-system-design/07-INTEGRATED-PLAN.md)使用。目标是相近投资具有相近的总体收益，同时保留不同场景中的优势、弱点和组合惊喜。

整体评估在 M5 完整远征完成后的 M6 进行，不作为 M4 天赋图开工前置。M4 先建立真实图模型、路径与配置，再结合战斗观察构筑体验；期间只按改动检查功能、交易和数据正确性，现有数值作为功能起值使用。

## 1. 两层公式：制作时分配预算，完成后测量收益

数值预算用于决定一个节点可以分配多少强化；通用模拟用于确认强化是否真的兑现。二者使用同一收益单位 **BP**，它是内部设计单位，不是游戏货币，也不显示在正常奖励页面。

核心公式为：

```text
U(B)       = exp(Σ_s p_s · G_s(B))
BP(B → B') = 100 · ln(U(B') / U(B))
效率 E      = BP(B → B') / C(B → B')
```

- `B` 是合法构筑，包含法书、天赋、遗物和事件覆盖；`B'` 是完成一次合法投资后的构筑。
- `s` 是场景、输入档位、操作策略与种子的组合，`p_s` 为预先固定的权重，总和为 1。
- `G_s` 同时计算实际推进效率和生存代价，定义见第 2 节；`U` 是跨场景的总体收益指数。
- `C` 是这一投资允许使用的 BP 预算，包含必须追加的路径和获取成本；不是只计算最终关键节点本身。
- `E≈1` 表示实际增量接近制作预算。它不是要求每个场景、每件遗物的收益都相同。

使用对数的意义：在相同条件下，10% 的相对强化都约为 `9.53 BP`；两个各 10% 的独立强化合计约为 `19.06 BP`，不能因把一个强化拆成两个来源而隐瞒乘算收益。

公式用于指导与诊断，不能证明玩法已经有趣。若一个构筑处处领先且没有代价，即使总体平均分合格，仍不通过平衡验收。

## 2. 实际收益：推进效率与生存代价

### 2.1 固定比较条件

同组构筑使用相同场景、难度、词库、人工输入预算 `N_s`、输入时间表、模拟时限 `H_s`、操作策略和随机种子。随机源按遭遇、掉落等用途分流；某构筑多产生一次视觉或法术随机调用，不能改写后续敌人配置。

`N_s` 在开跑前固定，死亡、辅助补全或提前清房不能通过减少分母抬高分数。报告另列实际人工字符消耗及每 100 个实际字符的表现，但不拿不同分母的结果直接判断两个构筑等价。

输入脚本通过正式输入入口操作，材料只来自有效 `InputReceipt`，不能直接调用伤害函数冒充玩家完成一个词。慢、中、快三档输入分别成组；不先把它们平均掉。

### 2.2 推进量 P

每个场景预先声明需要处理的目标或阶段 `j`，分配固定的目标权重 `q_j`，总和为 1：

```text
progress_j(t) = clamp((HP_entry,j - HP_remaining,j(t)) / HP_entry,j, 0, 1)
P_s(B)       = (100 / N_s) · (1 / H_s)
               · ∫[0,H_s] Σ_j q_j · progress_j(t) dt
```

这里测量的是目标处理进度随时间的积累：同样完成一场战斗，完成得早有更高收益；未清房也有连续可比的进展，避免只看胜负造成巨大断层。

- 只计算真实生命或可破坏目标进度。过量伤害、尸体伤害、无效命中、无敌阶段理论伤害均无收益。
- 敌人治疗会降低当前进度，不能靠反复伤害同一段被治疗的血量刷分。死亡目标维持完成状态。
- Boss 阶段按固定目标清单计算；实际出现前进度为 0，不把跳过阶段或召唤数量变化转换为额外免费分数。
- 临时孵化物默认是遭遇压力，不加入可无限扩张的得分目标；处理它们的价值通过推进和生存体现。专门的护塔等目标可在场景中预先赋权。
- 清房后完成进度保持到统一时限；死亡后不再积累新的推进积分。初始条件与终止处理对所有构筑相同。
- 场景分别包含短、中、长窗口与连续房间；不让短时限天然否定持续伤害，也不让无限等待掩盖延迟成本。

进度有上限，因此整组构筑都已接近瞬间完成的场景只能说明当前压力不足以区分上限，不能据此宣称完全平衡。按成长阶段预先设置相称的诊断压力，同阶段对全部构筑一致；保留正常小怪场景用于体验判断，不随被测构筑强弱偷偷抬高敌人。报告标记饱和场景，成长曲线与边际效率主要在仍有分辨率的对应阶段评估。

### 2.3 生存风险 R

用实际生命损失形成风险，不给未使用护盾、满血治疗、未释放控制或未兑现储备虚构收益：

```text
r(t)   = clamp(1 - HP_player(t) / MaxHP_player(t), 0, 1)
R_s(B) = 0.5 · mean_t(r(t)) + 0.5 · max_t(r(t))
d_s(B) = 1 if 玩家死亡 else 0
```

最大生命、护盾、减伤、治疗、控制和走位能力都通过实际承压后的生命轨迹体现。死亡之后 `r(t)=1`；清房之后冻结最后生命比例，不在安全尾段额外治疗。生命上限取该时刻真实上限，事件牺牲最大生命会在后续相同压力下产生风险。

控制减少敌人出手、护封挡住弹幕、回收热量形成后续伤害，都在真实结果里体现，不再分别加一份“控制分”“护盾面值分”或“储备分”。报告可列这些解释指标，但不将其重复加进主收益。

### 2.4 场景收益 G

同阶段使用共同参考构筑 `B_ref`：

```text
ε_s    = max(0.01 · P_s(B_ref), 0.000001)
G_s(B) = ln((ε_s + P_s(B)) / (ε_s + P_s(B_ref)))
         - λ · (R_s(B) - R_s(B_ref))
         - κ · (d_s(B) - d_s(B_ref))
```

初始取 `λ=1`、`κ=ln(4)`：在推进相同的情况下，风险降低 0.1 相当于约 10 BP；死亡有单独的显著惩罚。`ε_s` 只保证零推进可计算；参考构筑接近零推进的场景需要标记为失配，不靠平滑值掩盖不可比较。

这两个系数作为版本化评估配置固定。最终分析同时给出生存权重的敏感性结果，不能为某件遗物临时改变权重使它过关。死亡率、Boss 能力与普通敌人处理能力还有独立门槛，不能用一个高均分抵消全部短板。

## 3. 法书、天赋、遗物和事件如何共用预算

### 3.1 初始制作标尺

| 投资 | 允许的增量预算 C | 使用规则 |
| --- | --- | --- |
| 法书起点 | 四书拥有同等初始总预算 | 对同一个参考构筑比较，不能每本书都用自己作分母后宣称一样强 |
| 1 个实际消耗的天赋点 | 3 BP | 包含路径收益；关键节点不能把必要路径成本排除后单独炫耀效率 |
| 1 次普通遗物奖励机会 | 8 BP | 基础遗物或加层按其实际消耗的奖励机会计算；重复层不免费 |
| 演化或替换 | 继承的旧预算 + 新支付预算 | 被替换的规则移出构筑；不把父节点全部收益和两条分支收益一起保留 |
| 事件交换 | 同成本合法替代方案之间比较 | 最大生命、失去节点、占用后续奖励和借阅期限在模拟中实际执行 |

这是全局初始标尺，后续可统一校准；不是宣称 3 与 8 已经适合全部内容。普通参考配置的数值成长线可先写为：

```text
U_target(T, R) = U_book · exp((3T + 8R) / 100)
```

`T` 为已花天赋点，`R` 为已花标准奖励机会；它指导未饱和诊断场景中的整体成长曲线，不要求有上限的推进积分无限指数增长，也不是运行时强行把角色结果拉到目标值。普通满点上限仍是有限预算，God 无限点不参与普通数值平衡。

更稀有不自动等于可以无成本更强。高级遗物更高的预算应来自多次成长、真实代价或被替代的资产。稀有度主要影响成形概率与探索节奏；不能用“很难拿到”解释一旦拿到就无代价统治所有内容。

### 3.2 路径与代价不能重复入账

对从合法 `B` 到合法 `B'` 的新增投资，`C = 3ΔT + 8ΔR`。两条路线的绝对比较使用相同总点数、奖励次数和章节位置；共享前置只计一次。

失去最大生命等代价已经通过 `G` 扣除，不能又把它折成负成本，在分母中第二次“补偿”。失去一个旧遗物时，比较的是同一已花奖励预算下的替换结果。事件借阅按真实持续范围评估，其到期损耗也必须发生，不能只截取收益最高的借阅期间。

`ΔT=ΔR=0` 的免费替换不使用效率除法，而比较同成本下的 `ΔBP`、场景交换与风险。如果一个无代价事件总是严格更好，说明它是净奖励，应占用路线奖励预算，不能伪装成有取舍的事件。

### 3.3 材料威力与乘区

基本人工供给以字符预算为锚点：某书在长度为 `c` 的真实完词中投入 `k_book · c` 的原始威力额度。四书可用不同的 `k_book`，通过共同场景标尺校准，因为控制、传递与延迟会改变实际收益；不能只令基础伤害数字相等。

结构拆分、转交、聚合保持已支付份额；复写、增幅等额外威力有明确来源和制作预算。多段、链数、持续时间、触发频率与每段威力必须一起计价：把三段各 10 改为六段各 10，不能只记“段数增加”。

纯数值放大可以先用 `100·ln(倍率)` 估价。若一个效果预期仅作用于总有效收益的比例 `a`，其粗估为：

```text
BP_estimate = 100 · ln(1 + a · (m - 1))
```

`m` 为局部倍率；`a` 来自已声明的材料分配与使用条件，不取理论触发次数。该式只是制作时的初估，完整模拟以实际结果为准。机制节点、容量和条件触发不能硬套成恒定倍率。

同一加法池先合并，再进入已声明的乘区；独立乘区须有规则理由，不能因来源分别是天赋、遗物和法书就自动彼此相乘。上限、递减或替换策略写在共享规则中，UI 显示实际增量。不得在测试工具里秘密削减模拟收益。

### 3.4 一个可复核的估价例子

假设某普通遗物允许使用 8 BP，已有法术的 40% 有效输出会经过它影响的载体，且它只改变这部分威力，则初始倍率可取：

```text
m = 1 + (exp(8/100) - 1) / 0.4 ≈ 1.208
```

这约为载体部分增加 20.8%。如果某天赋使 80% 输出经过同类载体，实际增量将增至约 15.4 BP。这是有价值的组合收益，也说明不能仅按遗物面板上的百分比估价：要计入天赋与路径成本，检查集中投入后的机会成本和高端表现。

若有事件把部分载体改作防御，`a` 不再只代表输出比例，最终应由推进与生命轨迹共同计算；不能给同一份载荷既加攻击收益又加完整防御收益。

## 4. 涌现组合的收益分配

对同一个合法基础构筑，天赋 `T` 和遗物 `R` 的交互增益可表示为：

```text
I(T,R) = BP(B → B+T+R) - BP(B → B+T) - BP(B → B+R)
```

三者交互用同样的包含排除计算：

```text
I(T,R,E) = F(T,R,E) - F(T,R) - F(T,E) - F(R,E)
           + F(T) + F(R) + F(E) - F(∅)
F(X)     = 100 · ln(U(B+X))
```

正交互是本次设计的目标之一，不要求将它压到零。要求组合支付了路径、资产或风险成本，优势来自可解释的执行变化；不能兼得覆盖、单体、防御、稳定性和成长速度而没有弱项。

反事实必须合法：撤掉前置导致构筑非法时，报告“该单独组合不成立”，改用同功能来源或同预算合法路线比较，不能非法强行启用，也不能把非法构筑当作零分来制造巨大交互值。

普通增益在相关合法构筑分布中的中位效率初始目标为 `0.8–1.2`；需要专门投入的组合允许明显高于此范围。`p95 > 1.8` 作为审查提示，结合成本、弱项和成形概率判断，不自动削弱。关键改写若在所有相关构筑上平均都接近零收益，也不能仅以“这是机制节点”长期豁免。

法书总体指数初始目标相差不超过约 10%；同阶段、同预算的成熟构筑在主要场景分组中的总体差异以约 15% 为初步观察线。它们是调整线，不是让每场伤害贴合到同一个值。报告必须保留未通过组，不能用重新加权隐藏差异。

## 5. 场景矩阵与总体平衡判断

评估配置显式列出群体密集、群体分散、支援目标、弹幕压力、接近压力、耐久单体、阶段 Boss 和连续房间。各主要组先等权；最终按实际游戏遭遇分布给一份补充权重结果，两份同时保存。

每组包含慢、中、快输入、不同词形及可重复的操作策略。策略只读取玩家可知状态，按公开规则选目标与防御，不能为特定遗物写一个总能触发隐藏优势的专用机器人。策略之间的差异保留为适用性结果。

内容覆盖由完整注册表与合法配置校验器生成：

- 四书无额外投资的基线与相同投入后的比较。
- 有限预算下的单书、十二种有向主副书配对及各自不同执行方向。
- 普通节点的边际增益、跨机制族二元/三元连接、至少十二套贯穿样本。
- 同预算事件前后、演化替换、借阅到期和后续高压力房间。
- 同源叠加、容量接近上限、供给不足与同功能来源替换。

不穷举所有子集，也不允许只测人工挑好的十二套。通用采样器按预算、功能族和图关系分层生成合法构筑，输出每个内容定义参与次数与未覆盖原因。已投放内容不能因采样未遇到而被默认为通过。

整体合格需要同时满足：

1. 主要法书与输入档位没有持续失配，正常玩家不被迫选择唯一主书或短词词库。
2. 同投入的成熟构筑存在场景交换；没有一套在几乎全部场景中同时领先推进与生存。
3. 高交互构筑的成本与弱点实际出现；候选系统没有让其稳定无代价成形。
4. 满容量、停笔、致死和重复回收等资源不变量成立；得分不能掩盖规则错误。
5. 保存死亡率、清房率、完成时间、峰值压力与最差组结果；平均收益不能替代这些门槛。

## 6. 通用评估工具与执行时机

### 6.1 一套工具服务完整内容

沿用仓库的无界面模拟能力，建立一个通用评估入口，按配置读取内容注册表、场景、预算档位、构筑采样策略和随机种子。工具调用正式构筑编译器、输入入口和战斗模拟，不重新实现遗物伤害公式，不硬编码待测遗物 ID。

现有基础为 [模拟 harness](../../../legacy/web/tests/harness.cjs)、[平衡探针](../../../legacy/web/tools/balance.cjs)、[内容入口](../../../legacy/web/src/bootstrap/content.ts) 和 [模拟入口](../../../legacy/web/src/simulation/CombatSimulation.ts)。已有固定 seed、词表、输入节奏与步进流程；现有平衡探针尚不能直接输出统一收益报告。扩展时复用这些入口，补充通用场景目标与采样适配器，以及通过正式获取/编译流程建立固定构筑的能力；不能直接写遗物等级而漏掉获取效果。正式内容入口、预算配置与工具主入口的调整在对应实施阶段完成。

工具分为：合法构筑枚举/采样、固定场景执行、指标采集、统一公式计算、对比报告。场景和采样规则使用版本化配置；新增内容只声明已有的功能、成本和关系，自动进入相应分层，无须为每件遗物增加一个测试脚本。

模拟接口至少输出：内容与构筑快照版本、场景/策略/种子、固定与实际输入量、目标进度时序、生命轨迹、死亡与清房时刻、资源去向摘要、到期与跨房结果。公式层只消费这些事实，不直接读取某个遗物名称后加分。

结果包含机器可读数据与可阅读报告：

- 各场景 `P/R/d/G`、总体 `U/BP`、投入预算与效率；保留逐场原始结果。
- 相同种子的成对比较、输入档位与场景分组、效应范围；样本不足明确标注，不声称统计显著。
- 内容覆盖、合法性失败、未执行项、异常资源、支配关系和高交互组合。
- 版本、配置哈希、机器环境和完整运行命令，使下一版本可复现对比。

错误配置、非法构筑或模拟异常必须令对应案例失败，不能跳过后输出“全体通过”。模型不支持新操作时显式报告适配缺口，不返回零收益。

### 6.2 执行安排

**项目功能、内容与事件实现完成后，在最终整体验收阶段统一运行数值评估。** 不在每次添加遗物、天赋或事件后自动跑，不挂入普通构建、逐文件测试或每次提交钩子。编写工具时可做静态检查；完整数值结论只来自最终实际运行。

开发阶段使用预算公式做内容设计与差异审查。资源归属、图布局、事件事务和存档正确性仍按修改风险做必要的小范围检查，它们不等同于提前反复跑数值平衡。

最终报告暴露的失衡按共享参数、单项代价或机制问题定位；修改后只补跑受影响场景与相关比较，不把每次调值重新变成全矩阵仪式。只有共享公式或基础模拟语义改变，才重新生成全部可比较结果。

未运行的矩阵写明“待最终整体验收”，不以公式合理、静态审查通过或一套漂亮构筑代替实测。
