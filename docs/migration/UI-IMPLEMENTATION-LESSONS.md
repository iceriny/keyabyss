# UI 迁移实践：从旧交互到 Godot 原生表现

本文记录 M1–M2 书库、战斗 HUD 与通用界面迁移中可复用的实施经验，不表示所有页面已经完成。目标外观以[金丝水晶](../ART-DIRECTION.md)和[开放式 UI](../OPEN-UI.md)为准；实际状态与验证结果看[阶段总结](../STAGE-SUMMARY.md)，剩余事项只维护在 [TODO](../TODO.md)。2026-09-28 的早期用户实测确认只属于当时 M1 界面，不能外推到后续 M2 材质与交互。战斗规则、手感和跨领域经验见 [M2 实施经验](M2-IMPLEMENTATION-LESSONS.md)。

## 先恢复行为，再选择 Godot 载体

**已证实的问题。** 只看旧页面截图，容易保留静态外形却丢掉选书路径、准备页展开、前缀词令、焦点、悬停、入场节拍和指南内容。旧实现的行为分散在 React 组件、CSS 动画、输入路由和声音索引中。旧指南并非几段帮助文字：`HelpPanel` 有十篇双栏内容，末尾接十四条构筑学习路线及独立仿真组件。

**合适做法。** 每迁一条流程，先列出旧源码中的触发、状态、过渡、结束、文字和音效，再决定原生节点如何承载。对应关系是语义和节拍，不必逐字模拟浏览器技术：例如旧 `StartupWave` 的 SVG 位移滤镜与双波时间轴，可由 `SubViewport` 取景、CanvasItem 折射和 `AnimationPlayer` 实现；旧尘埃可由 `GPUParticles2D`、`ParticleProcessMaterial` 和渐变贴图实现。把一套流程的绘制和输入所有权同时核对，不能靠一张静态图判定完成。

**证据。** 旧源 `legacy/web/src/ui/{Home,Panels,BuildDemonstrationPanel,StartupWave,ArcaneCursor}.tsx`、`legacy/web/src/ui/{ritual,open-ui,build-demonstration}.css`；原生 `ui/{archive_home,archive_gate,archive_effects,guide_content}.gd`；[体验映射](EXPERIENCE-MAP.md)及本地 `.temp/legacy-ui-review/{restoration-evidence,guide-restoration}.md`。

## 原生控件保留输入语义，主题替换浏览器外观

**已证实的问题。** 未覆盖的 Godot `CheckButton`、`OptionButton`、`SpinBox`、滑条、滚动条与弹出菜单会显露默认灰色皮肤；所有按钮强制统一字号或高度，会覆盖页面已经指定的 14–16px 菜单与表单层级。默认键盘焦点链和 Tooltip 还会绕开游戏自身的词令路由，在弹层开关或文本输入时留下错误焦点。

**合适做法。** 保留原生控件类型和信号，以 `Theme`、轻量 SVG、`OpenButton` 的下划线／光效承接 CSS 表现。普通展示和游戏词令控件设 `FOCUS_NONE`，文本输入只在需要编辑时取得点击焦点；Tooltip 不由默认控件暗中弹出。词令的唯一归属由 `InputRouter` 判定，不能用控件焦点作为第二套事实来源。关闭默认键盘焦点、Tab／方向键遍历与 Enter 隐式确认是用户明确要求，审核不能把它误判为缺陷并恢复；只有用户明确提出时才另行设计。战斗 Tab 切换目标和文本框内的编辑键仍属于各自输入语义。减少动态停装饰旋转、脉冲和位移，但保留可辨的静态选中与操作反馈。

**证据。** `ui/theme/keyabyss.tres`、`ui/open_button.gd`、`app/main.gd` 的 `_apply_control_policy` 与 `game/input/input_router.gd`；旧 `legacy/web/src/ui/components.tsx`、`open-ui.css` 与 `legacy/web/src/style.css`；`.temp/legacy-ui-review/restoration-evidence.md` 的焦点及原生窗口复核。

## 受效层、HDR 与像素密度

**细线采样。** 法阵和拖尾的宽度必须考虑屏幕像素足迹，不能把固定 UV 宽度当作抗锯齿。导数应取自连续有符号距离；透明覆盖率不要在过滤后再做 gamma 幂运算。光芯需要在几何边缘内留出覆盖空间，单纯添加大光晕不会修复断线。缩小的 SVG 纹样需要 mipmap；2D MSAA 负责几何边缘，不能代替 shader 内部过滤。原生场景与主画布关闭 `gui_snap_controls_to_pixels`，否则 Control 承载的光效与移动词牌仍会跳格。复现与原生对照见 `.temp/effect-sampling/review.md`。

**已证实的问题。** 把文字与场景一起送进 glow、折射或大面积柔焦，会使正文和危险信息失去清晰度；把波纹只画在法书控件内部，会被局部矩形裁剪。HDR 2D 的截图从线性高精度图像直接保存，或先量化到 8 bit 再做 sRGB 转换，都会把暗部判断带偏。低分辨率中间纹理若按布局尺寸而不是实际像素密度分配，会使法书和线条变糊。

**合适做法。** 场景与光效进入独立 HDR `SubViewport`，文字和交互放在其后的清晰主 Canvas；入场波纹在全幅场景输出上取样，统一控制波前和发光。`SubViewport.size` 按画布全局缩放取得物理像素尺寸。截图从原高精度 `Image` 逐像素执行 `Color.linear_to_srgb()`，写入新的 `Image.FORMAT_RGBA8` 后保存；不能先 `convert(FORMAT_RGBA8)`。截图显示正确只是视觉取证条件，不等于性能或色彩绝对准确。

**证据。** `ui/archive_stage.gd`、`ui/archive_gate.gd`、`ui/materials/{archive_lens,startup_wave}.gdshader`、`tests/godot/test_application.gd` 的 `_capture`、`tools/godot/godot.ps1` 的预览桥截图转换；`.temp/legacy-ui-review/restoration-evidence.md` 的 glow 开关和入场截图对照。

### 柔光、文字和选中线各自处理

本项目的辉光是一层柔和、平滑衰减的扩散光。场景采用 HDR `WorldEnvironment` glow；按钮采用连续解析细线与低强度光晕。把粗线拆成多段绘制曾产生梳齿状选中条，连续 shader 衰减消除了段接缝。提高亮度、叠硬边或模糊正文都不能代替柔光。

曾用于正文的 `CanvasGroup`／分组柔焦已退出当前实现。它不是不能使用的 Godot 功能，但此处把文字也栅格化、采样和模糊，受效范围不合适。主菜单正文直接在主 Canvas 上绘制；页面背景用明确的 `BackBufferCopy` 与屏幕采样柔化，页内正文保持独立。汇文明朝体用于标题，京華老宋体用于小字和词令；首先检查实际像素密度与受效层，再判断字体是否需要调整。

## 连续背景、无缝噪声与粒子

**已证实的问题。** 书库背景曾出现矩形断层。仅保留 paper 层仍可复现；把连续纸纹的程序噪声换成 Godot `NoiseTexture2D` 并启用 `seamless` 后，分层截图中的断层消失。**尚未证实**底层是否由某一 GPU 精度、导数或驱动行为单独导致，不能把该推测写成根因。旧 Web 的实时生成纹理或滤镜也不应逐项复制为每帧 CPU 图像编码。

**合适做法。** 全幅低频背景使用可重复采样、具有 mipmaps 的原生噪声资源；按完整输出范围检查接缝，而非只观察中心画面。颗粒、尘埃与入场纸屑优先采用原生粒子和资源，按画质及减少动态开关控制数量或停动；保留静态材质，不让随机高频纹理覆盖正文。

**证据。** `ui/materials/archive_paper.gdshader`、`ui/effects/paper_noise.tres`、`ui/effects/archive_dust.tscn`、`ui/archive_effects.gd`；`.temp/legacy-ui-review/{boundary-paper,boundary-noise,boundary-all}.png` 与 `restoration-evidence.md`。

## 绘制前后、鼠标命中和稳定展开

**已证实的问题。** `CanvasItem.z_index` 决定绘制前后，不替代 Godot GUI 对重叠控件的命中顺序。四书只调整 z 值会出现看见前景书却点中后景书。准备页若在两侧另开一层，也会破坏“当前主书留在原位、配置从中央展开”的旧流程。

**合适做法。** 视觉节点设 `MOUSE_FILTER_IGNORE`，真实点击区由同一层明确拥有；书位深度变化时按绘制顺序同步调整命中按钮的树顺序。准备状态沿当前选中法书展开两翼，主法书保持稳定，文字和底部操作有固定基线；长正文在内层滚动，避免内容更新把外壳撑出窗口。由 `PageShell` 统一安排固定标题、返回、正文滚动与页尾，而不是每页再造弹框。

**证据。** `ui/archive_home.gd` 的 `_layout_books`、`book_hits.move_child` 和 `_layout_motion`，`ui/page_shell.gd` 的布局与内部滚动；旧 `legacy/web/src/ui/Home.tsx`、`open-ui.css`；`.temp/legacy-ui-review/restoration-evidence.md` 的点击和准备页原生复核。

## 共享书色和可中断过渡

**已证实的问题。** 法书换色若分别即时写进各个 Label、StyleBox、粒子和 shader，会在同一帧出现局部色不同步；快速连续切书若累积旧 tween，也会向过期目标继续过渡。选中状态若只靠 hover，指针离开后重点消失。

**合适做法。** 从当前插值色发出单一共享 accent，向标题、场景、粒子、页壳与独立 Theme 实例传播；切换时停止上一个 tween，从此刻颜色重新过渡到新目标。当前时长 0.9 秒、Sine Ease In Out，是本机表现参数，不是通用引擎常数。运行时只维护一份独立 Theme，更新其颜色和样式，不逐帧复制整份资源。指南按 `theme_changed` 更新键位、装饰标题和渐隐线，正文颜色保持不变；过渡中打开页面也从当前颜色开始。粒子使用节点 tint 同步所有存活粒子的颜色，不只改变之后新生的粒子。选中线使用持续低幅状态，`reduced_motion` 时保持常亮；柔和的色彩过渡可以保留，不等同于位移或闪烁。

**证据。** `ui/archive_home.gd` 的 `_transition_accent`／`_set_accent`、`ui/archive_theme.gd`、`app/main.gd` 的 `_apply_book_theme`、`ui/open_button.gd` 的 `selected_visual`；`.temp/legacy-ui-review/restoration-evidence.md`。

## 房间法阵与法书图案分层

**已证实的问题。** 原实现让一层背部法阵跟随“当前选中书”的中心与半径。选择从左书换到右书时，选中索引立即改变，装饰锚点便瞬间跳到另一侧，虽然书自身仍在缓动。同时 shader 的 `school_index` 立即改变波形和辐条数量，单张封印贴图也直接替换，形成三种不同的跳变。仅给颜色加 Tween 无法解决这些问题。

**合适做法。** 空间结构和内容身份分别拥有状态：

| 层 | 位置与内容 | 换书响应 |
| --- | --- | --- |
| 纸面、地面与房间法阵骨架 | 锚定书库布局；骨架形状不依赖所选书编号 | 保持位置、尺寸和形状，主题色平滑变化 |
| 流光、微光与尘埃 | 独立环境装饰 | 可保留低幅流动，减少动态时停动 |
| 四枚法书专属封印 | 四个预建 `TextureRect` 共用稳定位置 | 插值各自透明度权重，旧图淡出、新图淡入；中断时从当前四个权重继续 |
| 法书插画与局部装饰 | 跟随各自轨道与深度 | 各书身份色保留，位置、景深和悬浮反馈连续变化 |
| 文字与点击区 | 清晰主 Canvas；点击区与绘制前后同步 | 保持阅读与操作归属，不参与场景模糊 |

封印权重总和保持为 1，避免交接时突然增亮；权重归零后隐藏旧图。房间骨架不因选择而搬动，空间折射仍可作为一次短暂的受控选书反馈作用于场景。尺寸变化允许重新布局，不等于选书时移动背景。

**证据。** `ArchiveHome.seal_layers`／`seal_weights`／`_blend_theme`、`ArchiveEffects.set_anchors`、`archive_ritual.gdshader`；`test_presentation.gd` 覆盖锚点不变、双图权重、中断接续和旧图退出。

## 景深与悬浮使用连续状态

**已证实的问题。** 单纯提高贴图 mip LOD 会降低细节，但不一定形成自然景深，透明边缘也需要处理。`is_hovered()` 直接决定模糊为零、亮度为高值和透明度为一，会同时产生三次突变；鼠标离开时又反向突变。

**合适做法。** mipmaps 负责缩小时的抗锯齿，局部九点 Gaussian 核负责柔化；累加前对 RGB 乘 alpha，完成后再还原，降低透明边缘污染。模糊半径由轨道深度连续计算，前排清楚，后排逐渐柔化，正文不随之变糊。当前后排最大半径 8.5 个布局像素，准备页退后的书可达 12；这些参数需要随实际画面校准。

悬浮使用一个 0–1 权重共同驱动亮度、透明度与模糊，按 `1 - exp(-delta / 0.14)` 接近目标，避免依赖帧率；移开与词令前缀变化也走同一路径。0.14 秒是时间常数，并非总动画时长。不能只把外发光渐变，却仍让书体清晰度硬切。连续快速输入应从当前状态继续，不排队执行旧动画。

**证据。** `ArchiveHome.hover_amount`、`_layout_books`、`archive_book.gdshader` 的 `depth_blur`；`test_presentation.gd` 验证悬浮中间态、最终清晰和移开恢复，原生截图另用于判断实际质感。

## 音效按事件语义分配声部

**已证实的问题。** `ui.book` 的原两个 WAV 分别约 2.69 秒和 2.82 秒。沿用 0.16 秒 cooldown 与两声并发上限时，快速切书会漏掉有效选择：前者拒绝紧邻事件，后者让旧长音占满声部。原生窗口复核确认快速换书后只保留最新书声；声部断言与用户整体实测反馈分别记录，不将其扩写为独立混音评审。

**合适做法。** 只在选中法书实际改变时发书声；新选择立即取得声部，旧书声在 50ms 内淡出。给声部复用加序列号，防止旧淡出回调停止新声音。可能被 `kill()` 的 Tween 不应以 `await tween.finished` 作为唯一收尾路径；声音淡出采用带序列号校验的回调。首次进入首页也不能无条件播放“返回／关闭”声。其他 cue 保留各自优先级、并发和音量语义，不把书声专例扩散到全部音效。

**证据。** `audio/archive_audio.gd`、旧音效索引、`.temp/legacy-ui-review/audio-switch-fix.md` 与 `restoration-evidence.md`。

## 设置即时生效，保存按操作收束

**已证实的问题。** 滑条每次 `value_changed` 都保存文件、备份并重新应用整个窗口和主题，会把一次拖动变成大量同步 I/O。程序修改 `OptionButton.selected` 不等于用户选择，不会自动触发 `item_selected`；恢复默认依赖这些信号时，仅缩放或画质不同就可能漏保存。逐个恢复其他控件又可能反复保存半成品配置。

**合适做法。** 音量实时更新对应总线或播放器，拖动结束或 350ms 无新值后保存，离开设置与退出时处理尚未保存的值；不要为调音量重建视觉状态。恢复默认时屏蔽这批控件的信号，统一赋值、更新显示，最后显式保存一次。页面装饰和正文同属布局，窗口／缩放重排时同步定位印记，不能只在 `_ready()` 定位。

**证据。** `app/main.gd` 的 `_volume_setting`、`_persist_audio_settings`、`_defaults`，`PageShell._layout_panel`；应用回归覆盖暂停时音量防抖、仅下拉值变化的默认恢复及缩放后印记位置。

## 按变化更新，不把所有状态放进每帧重建

书本点击节点只有顺序改变时才 `move_child`。按钮尺寸与主题分别由 `resized`／`theme_changed` 更新，动画数值改变时才写光效参数；没有持续材质动画的节点在收束后停更，布局和主题变化显式请求绘制。页面晶面仍有流光时保留必要的时钟更新，不能机械地在入场结束后关闭。入场背景的静态几何只在参数改变时重绘，避免等待输入期间重复绘制数百个装饰点。隐藏首页同时暂停处理与离屏绘制，返回再恢复；隐藏不等于自动停止所有子视口工作。

减少动态下，尺寸、主题、悬浮和纹理就绪变化会请求一帧 HDR 绘制，`RenderingServer.frame_post_draw` 后显式切到 `SubViewport.UPDATE_DISABLED`；正常动态场景继续 `UPDATE_ALWAYS`。本机 4.7.2 中 `UPDATE_ONCE` 未在实际窗口自动切到停更，不能只靠枚举说明判断。窗口应用检查已确认收束后停更；它不等同于帧率或功耗收益测量。

## 验证和预览副本的边界

**编辑器嵌入与最终显示。** 本机实测同一根工程从编辑器启动，带 `--wid` 的嵌入窗口在 2548×1305 区域显示设置为 2560×1440 的游戏，出现明显细线锯齿；关闭嵌入后用户确认锯齿明显消失，新进程不再带 `--wid`。这将差异定位到嵌入显示链路，不能解释成资源保存被覆盖，也不能据此断言具体使用了哪种缩放滤波。检查 shader、MSAA 和渲染缓冲区之外，还需核对实际显示区域；最终观感以独立窗口为准。浮动 Game 窗口不等于关闭嵌入。

**已证实的问题。** `--check-only` 能确认脚本可解析，却不能判断焦点、点击命中、波纹裁剪、暗部、读字和音效交接；截图能判断画面，不证明声音或性能。MCP 是生成预览，不是根工程的权威文件，运行时调参也不会成为源代码交付。

**合适做法。** 先用最小脚本检查和针对性 headless 回归确认结构，再用同一源码状态的原生窗口走真实输入与关键页面；视觉取证保留截图、画质与窗口条件，音效另记声部或听感口径。完整导出只在阶段出口需要时进行。`tools/godot/godot.ps1 preview` 生成独立项目副本、注入 MCP 桥并使用独立用户目录，旧副本移入 `.delete/`；不要在根工程直接注入桥，也不把副本的导入或运行时值当成根工程修改。证据记录必须写明对应代码状态和仍未覆盖的玩法。

**证据。** [工具链](TOOLCHAIN.md)、[验证范围](../TESTING.md)、`tools/godot/godot.ps1`、`.temp/legacy-ui-review/restoration-evidence.md`。用户实测、脚本断言、截图、导出启动和性能测量分别记录；前一轮全绿结果不能替代后一轮检查，也不能把用户确认界面无问题扩写成完整性能或发行验收。

## 词令覆盖与编辑归属必须同时成立

M2 复查发现，关闭默认焦点后仍会漏掉旧版“打出词令即可操作”的核心交互；种子框即使可见，也可能沿用准备态之前的不可编辑属性。词令不能只覆盖返回与少数按钮，开关、下拉、滑条、种子、词库字段和指南条目都应调用同一个真实控件入口。进入页面时同步可编辑状态，不以新增隐式焦点链补救。

文本框可由点击或其词令显式进入编辑，编辑中的字符不得被页面命令截走；Esc 退出编辑，再恢复词令。滑条由词令进入调整，方向键只在该上下文生效。下拉展开、原生点击与词令动作共用状态和材质响应。按键标记共用 `KeyHint` 场景，避免页面各自使用不同格式的裸文字。

**入口。** `InputRouter`、`app/main.gd` 的词令绑定、`ui/command_tag.gd`、`ui/key_hint.gd`、`tests/godot/test_ui_refinement.gd`。

## 留白、光效边界与文字组一起测量

准备出征和难度按钮曾出现柔光被切割、视觉中心偏移。标题、图标和词令需要作为同一个文字组测量，换字与尺寸变化同步更新柔光中心；光效画布留出衰减边距，父级不误裁剪。需要延长的是金丝主脉，不能再叠加一条独立的分段下划线。

页面壳把标题下的间隔、正文与滚动条的间隔、页尾余量分别交给具名布局节点，避免用一圈巨大的内边距挤窄整个页面。当前 `BodyRegion` 顶部 16、`ContentMargin` 右侧 24／底部 20、按钮左右 12 个设计像素是现有版面值，不要求所有新组件机械照搬。固定头尾与内部滚动必须在不同桌面比例下同时成立。

平滑滚动保留浮点当前位置，连续滚轮累积目标；拖动滚动条立即接管，末尾准确收敛而不抖动，减少动态直接到位。开关点、百分数、词令与底脉分别组织，圆点需要平滑覆盖率，但不能把正文一起模糊。施法区的字号、字重、字距、进度细芯与输入高亮都要在实际输出下看，不用统一加亮替代层级。

## 程序化金丝与晶面光晕分层调节

**纠偏经验。** 同一 SVG 铺满每个按钮会产生重复贴花；仅把 SVG 放在文字旁不构成材质嵌入。随后又曾把“光晕太淡、缺少流光”误改成“金丝更亮、分叉更长”，产生整页长枝和集中的白亮点。正确做法是先明确主脉、短淡分叉、金丝流光、晶面反射与透光分别来自哪个节点／shader，再调整对应层。

`GoldFilaments` 以词令稳定种子生成贝塞尔主脉与短分叉，尺寸／种子不变时不重建网格；分叉继承接点累计弧长，只承担弱细节。`gold_filament.gdshader` 用宽而缓慢的亮带照亮路径，各控件速度与相位错开；悬停增强局部受光而不重置为空间同步的亮点扫射。减少动态停止流动，保留静态金属层与即时操作反馈。

`CrystalInlay` 在金丝上合成轻微折射、透射和柔和光晕；`open_wash.gdshader` 管页面阅读层与两侧弧面受光。光晕本身要看得出缓慢流转，不应淡到消失，也不做两根均匀粗柱。改 `gold_inlay.tres` 之前先追踪实际材质链，连同引用 shader 和运行时参数核对，避免资源名看似正确而真正受效层没有变化。

用户 SVG 保留在 `assets/art/ui/goldwork/`，用于顺应布局的标题、页脚与侧翼纹样；纹样通过局部明暗、虚实和折射融入晶面。通用金丝保留中性金属色，法书主题色不覆盖全部装饰。阅读页在柔焦之外压暗背景，以保住前景整体性；透光不等于提高整页背景透过率。

**当前接口与证据边界。** 参数和接入方式维护在 [UI 材质](../../ui/materials/README.md)，本轮原生连续帧在 `.temp/ui-refinement/run-26260-2364635/`。这证明当前保存代码的局部画面和动态，不能替代用户的最终审美确认。测试可记录相位、时钟和输入归属，但不能用断言判定优雅、自然或好看。
