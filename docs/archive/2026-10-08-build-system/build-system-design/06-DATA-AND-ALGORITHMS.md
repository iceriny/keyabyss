# 数据语义、执行与图谱算法

> 历史归档：2026-10-08 调整范围前的设计、计划或证据。正文中的要求与“下一步”不构成当前任务；当前实施见[交接文档](../../../migration/AGENT-HANDOFF.md).

定位：依据[框架](04-SYSTEM-FRAMEWORK.md)与[候选内容](05-CONTENT-CATALOG.md)维护的语义契约和算法参考。资源、阶段和部分规则已实施；资产、完整配置与平面图仍有缺口，见[阶段总结](../STAGE-SUMMARY.md)。类型示例、固定点单位、tick 字段和已有文件名描述当前方案，不要求后续复制其运行循环或模块边界。来源、所有权、顺序、权限与几何要求属于需要保持的业务语义。

## 1. 数据边界

| 模型 | 包含 | 不包含 |
| --- | --- | --- |
| ContentDefinition | 稳定 ID、名字、效果规则、条件、成本 | 当前账号状态、世界坐标、任意执行函数 |
| TalentDefinition | 购买成本、天赋前置、模式选择、许可、规则引用 | 本局随机遗物作为购买前置 |
| TalentNodeProfile | 引用内容 ID、节点类别、数值系列、语义 profile | 重复的效果、费用或账号分配；补图数据不重写原生效果资源 |
| RelicDefinition | 最大层数、获得条件、许可、实例效果、演化来源 | 靠名字推断的家族前置 |
| EventDefinition | 出现条件、合法行动模板、范围、交易成本、覆盖模板 | 临时构造的不受检查脚本 |
| BuildSnapshot | 本局主书、天赋、许可、资产、覆盖、版本、可编译规则 | 可随 UI 悬停改变的战斗数据 |
| RuntimeState | 唯一资源账、对象实例、回执、期限、事件队列 | 用显示标签代替资源数量 |
| SemanticGraph | 概念权重、前置语义、允许邻接、关联索引 | 必须全部画出来的玩法关系线 |
| AtlasArtifact | 坐标、可见路径、标签占位、空间索引、布局证书 | 账号购买状态、临时事件结果 |

源内容是单一事实来源。界面、掉落、事件、模拟和通用数值评估共同读取定义；不分别维护一份“能组合的内容表”。正式内容使用稳定 ID，旧 ID 只保留为设计追踪，不建设浏览器存档映射。

## 2. 条件与效果契约

下列为接口示意，不是逐字复制的源码。对应契约已有部分实现，字段的业务含义与错误意义应明确；具体类型结构和模块拆分可根据实现调整。

```ts
type DefinitionId = string;
type RuleId = string;
type PermitId = `permit:talent:${DefinitionId}`;
type Scope = 'room' | 'chapter' | 'run';

type Condition =
  | { all: readonly Condition[] }
  | { any: readonly Condition[] }
  | { not: Condition }
  | { allocated: DefinitionId }
  | { permit: PermitId }
  | { owned: DefinitionId; minLevel: number }
  | { capability: string; source: 'build' | 'talent' }
  | { mode: string; value: string }
  | { objectProperty: string; comparison: 'eq' | 'gte'; value: string | number }
  | { counter: string; comparison: 'gte' | 'lte'; value: number };

interface RuleDefinition {
  id: RuleId;
  stage: 'income' | 'assemble' | 'dispatch' | 'prepareHit' |
         'commitHit' | 'afterHit' | 'finish';
  event: string;                    // 受类型约束的事件名
  targetKind: string;               // 与操作输入类型匹配
  when: Condition;
  operation: OperationDefinition;   // 有限的类型化操作联合
  resourceCost: readonly ResourceCost[];
  modeSlot?: string;
  inherit: 'never' | 'shape' | 'paidProcessing';
  repeat: { unit: 'receipt' | 'lot' | 'object' | 'enemyProjectile'; limit: number };
}

interface TalentDefinition {
  id: DefinitionId;
  cost: number;
  purchaseRequires: Condition;      // 只允许天赋、主书与配置条件
  rules: readonly RuleId[];
  permits: readonly PermitId[];
  selectableModes?: readonly string[];
  semantic: SemanticProfile;
  appearance: 'ordinary' | 'mechanic' | 'keystone' | 'book';
}

interface RelicDefinition {
  id: DefinitionId;
  maxLevel: number;
  eligibility: Condition;           // 能力、资产、词库条件
  permitsAll: readonly PermitId[];  // 所有永久获取渠道共同检查
  evolutionFrom?: readonly DefinitionId[];
  rules: readonly RuleId[];
  acquisitionEffects: readonly AcquisitionEffect[];
  semantic: SemanticProfile;
  budget: { perOpportunity: number; inherited: boolean };
}
```

规则语言不支持 `eval`、任意脚本、按书名动态拼接执行器或自由访问全局对象。新的操作类型需要先补充操作契约、继承与收束证明，再允许内容使用。

所有条件有上下文白名单。购买条件不能读取临时遗物或战场对象；掉落条件不能假定将来能借到一个事件；运行条件不能伪造许可。未知属性、单位错误、未实现操作和条件越权都是编译错误，不是默认 false 或忽略。

数值字段各自声明单位、加法池、乘区、上限、负值含义与作用阶段。比如秒数不能写入比例池，材料数量不能写成伤害倍率；缩短等待只修改等待参数，不修改对象已经获得的来源权限。

### 操作数据必须完整表达的字段

所有操作共有 `op`、类型化输入选择器、数量表达式、费用、输出所有者、次数单位和来源保留策略。数量表达式只允许常量、已登记统计、余额比例、上下限和四则运算；不允许读取不属于该事务的可变全局状态。

| 操作 | 专有字段与含义 |
| --- | --- |
| Supply | `incomeKind` 主术／制作；`receiptKind` 只能为真实人工回执；`amountPerHumanCharacter`；`distributionWeights` |
| Attach | `lotSelector`、`targetSelector`、`resource`、`amount`；储备选择器可声明 `reserveShare` 取用比例及 `reserveLimit` 全材料共享的每词上限，后者以 power 单位计；可选 `reserveBurst` 冻结耐久门槛、集中比例、共同集中上限与停用词数 |
| Allocate | `sourceLot`、`shares`、`maxChildren`、`remainderPolicy`；可选 `resourceShares` 逐资源覆盖份额，可选 `shape` 与 `applications` 定义子项形状和有限次数；余数只能留父、给固定子项或损耗 |
| Store | `shellArchetype`、`capacityUnits`、`releaseDelayTicks`、`lifeTicks`、`onNoCapacity`；可选 `share` 与 `retention`，分别表示选取份额和该份额的加工保留 |
| Transfer | `targetPolicy`、`maxDistance`、`hopCost`、`maxHops`、`onNoTarget` |
| Heat | `thermalLot`、`shellSelector`、`amount`、`threshold`、`heatMode`；数量为 heat 单位，模式为开启、存热或破裂 |
| Fracture | `integrityCost`、`allocationPattern`、`maxPieces`、`trigger`；碎片来自原内部份额 |
| Release | `unspentLotSelector`、`targetPolicy`、`exitClaim`、`onNoTarget`；消费关闭事务中的剩余托管份额 |
| Copy | `templateSelector`、`workCost`（类型为 work 的数量）、`fundedPowerFactor`、`inheritMask`、`maxCopies`；可选 `storage` 声明保存形态、容量、等待与寿命，占位和支付原子完成 |
| Merge | `compatibilityKey`、`sameRoot`、`maxInputs`、`waitTicks`；`outputPolicy: preserveShape` 保留原形状并采用各份最少作用次数，`concentrate` 将同形状的原总额集中至一次作用 |
| Recover | `remainingSelector`、`retention`、`capacityKey`、`reuseAfter`；可选 `resource`（默认 power）及 `share`（默认全份），仅回收 power／cold／heat／charge，不回收制作量或字符机会 |
| Guard | `projectileClass`、`selectionOrder`、`powerPerBlockedUnit`、`reserveShare`、`projectileClaim`；`powerPerBlockedUnit` 为防御消耗／来袭威力的 ratio，可表达小于 1 的成本 |
| Convert | `fromComponent`、`toComponent`、`share`、`rate`、`conversionStage`；不产生对应材料许可 |
| Mark | `positionSelector`、`matchPolicy`、`maxPositions`、`rewardAllocation`、`humanReceiptClaim`；可选 `rewardPlan` 固定分给主术、制作和保存的比例、两种加工保留率、空间、等待、寿命及形状继承，可选 `opportunityCost` 与 `maxPerWord` 限制每位置费用和同词标记数 |
| Field | `shape`、`radius`、`lifeTicks`、`maxApplications`、`lotAllocation`、`onFinish`；可选 `share` 与逐材料 `resourceShares`，未选中的资源留在原对象 |
| Ongoing | `action: advance` 与 `applications` 表示提前消费现有作用次数；`action: delay` 与 `coldCost`、`extraTicks`、`maxDelayTicks` 表示付费延后，分别使用 cold／ticks 单位 |

`onNoTarget` 只允许继续一次已付等待、交给既有回收规则、或明确损耗；`onNoCapacity` 只允许保留原所有者或损耗，不能生成隐形额外空间。等待和回退都受剩余次数与期限约束。

回收与再投入各消耗被移动份额的一次加工次数，保留原人工来源与加成领取记录。`status.death` 处理目标死亡时尚未造成的持续伤害；`status.extract` 在下一次人工完词时读取上次人工目标的存活状态，抽取会同步扣除其后续伤害。新储备只对之后的人工主术开放，不能用于完成抽取的当前词或复写。`spell.finish` 与 `room.finish` 分开，`endReason` 提供真实结束原因；普通释放与已付等待先占用外壳的唯一剩余份额，回收不能再取得它。

储备空间和每词取用额度使用共同权重：每个固定点单位的 power／cold／heat／charge 分别占 16／1／64／16 个空间刻度，一个 power 单位等于 16 刻度。运算使用整数，四种材料不会各自多获得一个容量。正式入口按 power、heat、charge、cold 的固定次序取用；以后新增偏好模式仍须共用这一额度。当前权重随统一收益评估校准，不能随意改动已存档材料的计量口径。

清房先结清在场对象，再按本次配置对储备执行一次归档，追加损耗并裁至共同容量。`archiveReserves` 保留来源、历史和剩余加工次数，只改变下一房可用性；重复参数返回原结果，修改参数重放拒绝。归档后不再接受本房收入或进口，导出清除原份额；无停用期时，新房第一词可按取用上限投入。没有跨房许可的普通储备不导出。

### 集中取用与真实完词停用

`targetPowerRatio` 由正式输入适配器记录：人工选中目标的剩余生命，除以本次未经过保存、转换、散字兑现或储备投入的主术威力。其值仅用于后续阶段；Supply 仍确认原人工输入事实，不把这个世界事实追加进原收入回执。主目标之外另有耐久敌人，不构成集中取用条件；派生法术没有新的取用权。

`reserveBurst` 声明 `minimumTargetRatio`、`share`、`totalLimit`、`cooldownManuals`，依次使用 ratio／ratio／power／count 单位，且必须保留普通取用的共同上限。首次成功取用冻结本主术的政策和各材料可取总量；目标满足门槛、本房该目标未成功触发过集中投入时，使用集中比例与上限，否则使用普通比例与上限。不同材料分别从真实合格份额按比例取用，分次调用扣除同一材料的既定额度，不能重复按剩余量取比例；所有材料依旧竞争同一权重额度。电荷优先只改变排序，不多开一份额度。空账户、不足支付或取整为零不记录机会和停用期。

同一主术可按被冻结政策完成各类材料的取用，之后指定数量的真实人工完词不能取用任何储备。停用期间仍可回收、积累和正常施法；自动效果、菜单等待与派生法术不减少词数，切换目标或构筑不能绕过限制。同一目标在停用结束后只按普通政策取用，新的合格目标可再次集中投入。计数与一次性机会仅在资源交易成功后发布。

运行中的跨房票据可携带 `cooldownManuals`；空仓同样必须交接剩余停用词数，新房的真实完词继续扣减。重复进口不重置已经前进的计数，修改票据停用词数的重放拒绝；原目标 ID 的一次性机会仅在原房有效，不污染下一房的新敌人。正常不带集中政策的既有取用 API 保持原参数行为，但服从已存在的停用期。

倾墨与长夜储卷占同一个 `reserve.mode` 槽，互斥；默认 steady。当前倾墨门槛为三倍，比例 75%，集中上限 48 power 空间，之后两词停用；倾墨阀将比例提高至 90%、上限增加 16、停用增加一词。匀墨与隔页阀调整普通取用；宽口热匣同时增加普通和集中上限，但降低回收保留率。这些起值由最终通用收益评估统一校准。

### 纸灵攻击与实体运输

`summon` 表示用共享制作力量补充纸灵攻击的能力，纸灵主书、折纸伴行、折纸使魔与共命书线共用这个入口。主术先完成已登记的保存和复写加工，原生纸灵再从真实剩余 work 制作有限攻击；它发生在主术正式派发前，瞬时电弧也不会提前销毁复写模板。完成一组攻击制作才唤醒一只纸灵并延长存在时间，输入节点、重复收入回执和纯自动施法不能得到额外攻击。每份攻击保持原人工来源、冻结配置、形状规则和期限；存在时间尚未结束不意味着还有攻击可用。

基础纸灵攻击花费 2 work，威力为当次主术的 22%；复写费用与威力修正继续作用于同一制造流程，纸灵维持效率降低真实 work 费用，费用向上取整。基础攻击队列最多 12 份，每个有效补充词维持 5 秒，累计上限 18 秒；主书最多三只，其它入口基础一只，折纸使魔按层数增加数量上限。这些是功能起值，实际输入效率与构筑收益仍在最终统一评估范围内。

运输读取已存法术的冻结能力和参数。纸灵到自己的出击时机，从附近保存对象中按实际距离、对象 ID 选择一份；成功领取时，纸灵的一份已付攻击全部作为运输代价消费，不合入货物，也不再造成一次纸灵伤害。货物每个资源来源分别保留并支付一次加工，状态改为 `carried`，绑定实际纸灵 `actorId`。同一纸灵不能同时领取两份；没有合格货物或领取失败时仍可进行原本的攻击。

`carried` 不占保存空位，也不能被保存选择器、受热、护页或合页当作静止保存对象。`storedCount(tick)` 为普通保存、复写、散字兑现和返程提供同一容量口径，只计算尚未到期的 stored shell。飞行期间继续受原到期时间约束，但不会由保存计时器在起点自动释放。若先抵达敌人，纸灵保持占用，等原准备时间完成；送达使用实际目标与位置，将同一份资源恢复为原法术形状，再交给正式派发与命中流程，不重新运行人工收入或主术组装。

目标消失后，空程留位可让货物实际返航一次。返程抵达时再检查空位、剩余期限和加工次数；成功后扣除返程损耗，准备时间为 `max(原准备时间, 抵达时间 + 额外等待)`，原出生和到期时间不变。`transportReturned` 沿原有份额的拆分、保存和合并保留；已返程与未返程的页面不能合页抹去这个限制。新的 work 复写仍是另行付费的新法术。

返程失败、运输到期、纸灵被移除和清房均结束真实货物。`transport.finish` 与普通 `shell.finish` 分开，遗响不能让丢失货物在原地额外发射；只有冻结的落空回收等合法规则能取得余量。清房仍禁止发射，旧房引用不能解开新房对象。基础送出保留 90%，空程返回保留 80% 并至少多等 0.5 秒；回航纸绳将返回保留提高到 90%，四个转交保留节点逐个减少 3 个百分点的送出损耗，最高保留全部原量。

`transport.mode` 默认为 ordinary；行间编队使用 fleet，孤页信使使用 solo，两者互斥。每份保存法术沿用生成时的模式，不因后来取得或移除天赋改变。

行间编队将并卷从保存生成阶段移到真实领取时。纸灵从近处选择至多四份兼容法术，同原人工根、冻结配置、位置、外壳、形状、目标及返程／中继历史；合页使用现有等待修正，齐页夹同时提高普通与运输合页上限。`RuntimeTransportAssembly` 将合页与领取放在同一个原子事务中：每份原资源分别取整、支付一次合页和一次运输加工，一份纸灵攻击支付运输代价并关闭。输出保留最早出生和到期时间、最少作用次数，准备时间为全部原准备时间的最大值再加等待。输入关闭、资源迁移和新货物发布同时成功；失败不会留下半次合页。无法形成合格组时仍可运送一份。已合页份额的 `native.transport.merge` claim 沿拆分、保存和返回继承，不能反复合页。

孤页信使只让实际编号为 0 的首只纸灵领取该模式的货物，优先选择附近威力最高者；其它纸灵继续用自己的有限攻击。送出保留提高到 100%，不提高原货物威力、不改变运输范围，也不减少返程损耗。普通保存合页仍有效，因此可以通过实际聚合得到较强货物，再交给这一只纸灵。不能把“运送更大份额”实现成无来源的伤害倍增。

浮页路标令运送中的带电法术成为一次性接力点。正式 Transfer 没有直达目标时，世界适配器读取实际纸灵的位置、房间引用、当前目标和货物绑定，只考虑尚未返回、未过期、未接力且能支付电荷与加工的货物。目标仍按原有耐久、近威胁、新目标等偏好选择，再在可抵达该目标的纸灵之间选最短路线；相同长度按货物 ID 决定。选择器只缓存有限纸灵的位置，不创建“纸灵 × 敌人”的路径对象列表。

`transferVia` 是单次中转入口，统一交给 `transferAlong` 验证各段距离及各自电荷费用。双方付款和加工在同一事务中提交，电弧的威力、命中次数与期限不增加，货物的威力和期限也不改变。`relayed` 与逐来源 `native.routing.relay` claim 防止返回、改所有者或重新保存后再接力；新 work 复写是另付费用的新法术，继承的旧材料仍保留其已有 claim。渲染收到已付款的 `from → via[] → target`，沿实际路径逐段画电弧，纸灵位置不额外产生一次伤害。有直达目标时优先直达，避免不必要的第二份电荷费用。

### 静止页桥与连续路径

T14 页桥和 R111 银墨接点开放同一个静止中转入口，合并后仍只有一次机会。候选必须是真正的 stored shell，具有冻结的页桥能力、足够电荷及剩余加工次数，并且尚未中转、未到期。尚在等待释放的法术可以中转，原准备时间与到期时间不变；不替它生成电荷，也不把尚未兑现的字母、持续状态或区域混入。静止点使用对象的权威位置；运输点使用实际纸灵位置，二者共享一次中转历史。

源电弧冻结的 `routing.relayLimit` 决定一条路径最多经过几份法术，普通和密网为一份，远枝连廊为四份。每个点使用自己的冻结距离和电荷费用。页桥钉只提高静止外壳的电荷使用效率，不减免源电弧或运输货物的费用。后获得／移除天赋、遗物不会改写已保存对象。

寻路只在没有直达敌人时运行。对当前有资格的静止／运输／区域点执行有限 Dijkstra，优先更少中转，再比较实际路径长度，最后按对象 ID 稳定排序；不枚举所有路径。每个点的出边使用它自己的范围。先求可达敌人集合，再用共用的目标偏好选择敌人，最后从合法路径中择优；寻路不覆盖耐久、近敌、未命中等原有偏好。当前候选由保存、纸灵与区域容量限制，不扫描已关闭对象历史。路径中的区域需要源电弧额外付款，因此对每个点分别保留不同区域费用下的合法路径，费用维度最多五档；较短但昂贵的路径不能遮蔽能够付款的绕行路径。没有区域时不扩展费用维度。

`transferAlong` 一次核验源、所有中转点、目标、独立电荷余额和逐来源加工额度；静止点不接受伪造的位置。重复对象、缺失中间段、返回货物、过期、后一份付款不足等情况全部原子拒绝。源电弧付第一段电荷和一次加工；每份中转法术付自己下一段电荷和一次加工，并领取不可刷新的单次记录。任何份额都不捐出或复制威力，命中次数不变；所谓“每段付费”不等于在中转位置附赠伤害。规则层的加工费用与所有真实参与者一起提交。

远枝连廊通过减少攻击目标数换取多段连通；近页密网缩短范围、增加目标数，二者互斥。单路电桥进一步减少目标数。实际法术生成时至少保留一次作用，电书沿用原生普通／强化次数后再计算增减，其它来源的电弧沿用公共次数；命中仍按同一份总威力分配，因此集中只改变分配，不增加收入。

### 区域中转的电荷、作用份额与时序

T47 地脉接点让已有的有限区域成为被动中转点。区域本身不需要额外生成电荷，不新建地面单位；原电弧为第一段及每个区域的下一段分别支付同额电荷，按原电弧冻结的效率计算。静止护页和运输货物仍自行支付各自的下一段，两种付款可以出现在同一条有限路径中。R120 地纹银线与 T47 共用一次入口，并把区域向外的传导距离提高 20%；该修正属于区域的冻结配置。

每个区域消耗一次原有作用及每来源对应份额：`ceil(lot.quantityQ / remainingApplications)`，与一次正常区域作用的取份方式相同，但记录为加工支出，不对敌人造成伤害。区域的剩余伤害、寒气等同步减少，不能把减少次数解释为把全部原量免费集中到更少次数。最后一次或全部资源用尽时在同一事务中关闭；不能再回收这次已花掉的份额。尚未开始、已到期、已经中转、没有剩余作用／资源的区域不能参与。

`RuntimeSpellRelay.sourceCharge` 只允许指向真实区域，必须使用区域实际位置且不能绑定纸灵，费用必须等于源电弧单段费用。原语逐段核验后，把源电荷、每份中转对象的加工、区域份额和关闭放入同一个事务。费用不足时整条路径保持原状。寻路以源余额计算最多可支付的区域数，在 `(对象, 已付区域数)` 状态上择优，排除重复节点及被更低费用、更优路径覆盖的状态。最多四个中转对象，费用维度 B 不超过 4；当前扫描实现上界为 O(((B+1)S)² + (B+1)S×E)，S 为候选数，E 为敌人数。该上界用于约束实现，不能替代最终性能实测。

区域的 `intervalTicks` 在创建时按原寿命与原作用次数固定，不能在第一次更新时根据已减少的次数重新推算。中转不移动原有作用时刻、不延长到期；剩余正常作用更少。正式阶段为真实中转发出 `field.relay`，最后一次随后发出 `field.finish`；不冒充敌人承受了 `field.apply`。显示层移除已关闭区域。

纸灵终式和其它原生／防御来源仍需继续接入。

### 保存后的合页阶段

`shell.assemble` 在一组保存输出全部生成后分派，先于受热、挡弹和自动释放。正常复写、晶存与散字存页进入同一阶段，使用各自生成时冻结的规则；后来的遗物不会给旧页补上一遍加工。新合页继续经过该阶段，但已合并份额的逐 lot 领取记录阻止再次并卷。页面不足、剩余加工次数不足、期限不够或不存在相容对象时，保留原页。

`mergeCompatible` 是选择器和原语共用的兼容判定：仅未发出的 spell 或 stored shell，要求同人工根、同冻结配置、同类型状态、同位置、同形状与继承方式、同目标和目标策略，以及相同外壳属性与已用等待标记。不接收带字母绑定、区域、持续时间表或结束托管身份的对象；不能靠合并吞掉另一个系统的独立时间与绑定状态。

分组按稳定对象 ID，单次最多取 `maxInputs` 份。合并保留每个 lot 的 ID、原来源、既有领取记录与剩余加工次数；每份再支付一次加工。总额不增加，作用次数不相加。输出保留最早出生时间和最早到期时间，准备时间为 `max(当前 tick, 各份原准备时间) + waitTicks`，必须严格早于每个输入的到期时间。合页只腾出实际关闭输入后释放的空间；不重新执行本次已因满仓失败的复制，也不制造额外收入。

并卷与归并绳共用一条 `storage.merge`，每来源限一次。基础两份合一，额外等待 30 ticks；齐页夹将最多份数增加二、等待增加 6 ticks；普通等待节点各减 6 ticks，当前下限 6 ticks。行间编队模式不在此阶段合页，改由上节的实际领取事务完成。合页后的威力可用于一次较强挡弹，遗响只释放实际未消耗部分。

R176 共页缝在拦截时允许最多两份兼容存留法术共同付款。先按护页自身冻结的先旧／先新偏好选择；第一份足以支付时仍普通挡弹，不触碰第二份。不足时，寻找同人工根、配置、位置、形状、目标、属性及历史的另一份，分别计算 `floor(power × reserveShare)`，不能把小数余量集中取整。正常合页和共页拦截可以连续发生，后者不再次生成合页对象、不刷新准备或到期。

`guardTogether` 核验所有实际参与者，在同一事务中支付真实挡伤威力与每份的一次加工，并只领取一次敌弹记录。费用不足、对象不相容或过期时不抢占敌弹。只返回真正出力的对象；正式拦截流程将它们逐个走原有结束规则。遗响、回收等只处理各自付款后剩余的资源，没用到的法术不扣次数、不结束。传入两份但只有一份实际出力的请求不作为聚合成功，普通挡弹由原单份入口处理。

### 有限区域与持续作用

`hit.prepare` 携带实际命中目标和位置，区域不会误留在施法起点。原生准备先从当前剩余威力中制作持续伤害，再为每份已支付的状态发出 `status.start`；该事件允许 Field 分走一部分持续伤害。分到地面的威力同步从附着伤害扣除，寒气、电荷等不因附着灼烧而被一起截走。热量先按既有规则转为威力，持续加工的损耗只发生在选中的份额上。原生火书和灼文共享保留率数值池，后取得的天赋不会改写已生成的状态。

`SpellField` 冻结形状、半径、分配方式与结束策略。圆形以固定位置为中心；路径形为 `from` 到固定位置的胶囊区域。生成时拒绝不匹配或非法元数据。字段只是几何，所有伤害和材料仍在资源账里。单目标 `commitHit` 不接受区域，区域只能经 `applyField` 原子提交。

调度间隔来自生成时的总时长与次数，不因敌人反复进入、后来增加天赋或重复推进同一 tick 而刷新。每次作用从每个来源取 `ceil(剩余量 / 剩余次数)`，末次取尽；区域内的合格敌人共分这一份，取整余数按稳定 ID 顺序分配。多人进入不会把整份伤害逐人复制。半径查询最多交付 64 个目标，区域数量上限 64；没有嵌套生成或无界逐目标递归。

`equal` 每个时间点都会使用一份，无人在场时计为损耗；`onContact` 只在有人时使用，空场不减少次数，但期限照常流逝。两者到期都结束，不能通过等待补满已经错过的作用。所有已提交效果先结清，目标死亡后才处理其未发生的持续伤害。结束策略 `lose` 直接损耗；`recover` 只允许本份对象已冻结的回收规则处理余量，本身不赠送回收能力。清房走同一余量交接，再参与原有跨房归档；材料回收仍受分格储备、共用空间与后续人工词限制。

正式基础冰书将一部分寒气留成区域；热区、寒区和余场回收使用共同的 Field／Recover 操作。封场蜡同时增加时长与作用次数，使原份额分得更细。绘制只读取投影，复用冰晶、火焰与路径形态，余量减少时降低亮度；不把投影放回旧区域列表参与额外伤害、减速或合并续命。旧位移与终式的区域仍在其迁移范围内，不能将本节当作全部区域来源已完成。

### 字母兑现、保存与制作

Mark 仍只使用已赚到的 opportunity，不因目标死亡补发人工收入。产生标记时把实际奖励比例、费用、同词上限和散开偏好求值为冻结的 `SpellLetterPlan`；目标词消失后再次转移，沿用这份偏好、剩余次数和原到期时间。新取得遗物不会把旧散字改成更高收益，程序也不能仅取目录里第一条 Mark 规则猜测其原始用途。

每个匹配位置必须属于同一词会话，且出现在本次人工输入位置里；在完词时统一兑现，自动补全的后缀不能兑换。每来源 lot 先划出 `floor(q × workShare)` 和 `floor(q × storedShare)`，余量进入主术；两比例都是对原 opportunity 的绝对比例，编译阶段证明其和不超过一。制作方向按 1:1 折算 work 后扣除加工损耗；保存方向按 power 汇率向下取整，再应用保存保留率；主术方向不增加制造损耗。原来源、规则领取与剩余加工次数随真正的 funded creation 保留，不出现一份收益同时进入两处。

制作方向消耗源份额一次加工机会。没有加工次数时，这部分回到主术；保存空间满时，保存部分同样完整回到主术。空间包含已有未过期外壳、同次兑现的护盾及本次已预留纸页，最多 64 份。只有实际有非零产出的纸页才占对象编号；取整到零的制造产出计损耗，不创建空页。

同次兑现、相同原主术模板、相同冻结配置、形状、原始作用次数与等价计划可以合成一张纸页。判断不依赖字段书写顺序；不同模板或不同计划分别保存，仍共用空间。纸页的位置与目标取自当前实际主术，规则与原生形状来自原模板。默认是一次普通飞行法术；同形字模允许保留原形状和原始作用次数，并提高保存损耗。寒气、热量和电荷不会凭形状继承而新增。生成的纸页参与普通护页、受热、结束释放与回收，保留旧来源，不能再被当作字母兑换一次。

兑现的 `matchedCount` 来自真实关闭的字母数。生命周期先以原始事实确认已经支付的 Supply，再分派当前主术的 `letter.match`（income／assemble），此时才加入 `matchedCharacters`，之后继续普通装配。收入确认不会因为后来匹配了字母而改变原回执，也不会在匹配事件重新发钱。该事件使用完词主术的冻结配置；已生成字母和纸页各自已有的配置不因此改变。

`Condition.mode` 仅用于运行上下文，并校验模式槽及取值已登记；缺失模式在取反时也不能变成生效条件。分字方式和奖励用途分别占用 `letters.distribution`、`letters.reward`。T33／K15 可与 K14 组合；事件以后也能通过已有覆盖协议只改一槽。`letterStorage` 是获取条件使用的内部能力，表示真的能把字母收益存页，不把仅有普通保存空间误当作同形字模已经可用。

兑现是一笔资源事务。保存加工使用逐来源的精确净转换率表达两次取整后的正产出，资金与净额可审计；零产出显式记录原机会损耗。没有额外的中间 power 损耗事务，也不扩展账本为可任意执行的流水线。完整数值评估仍需把机会、制作与后续复制的共同预算一起计入，不能仅凭资源分账通过就认定收益已平衡。

### 持续时序与寒气控制

`SpellStatusTiming` 保存生成时确定的间隔、下一次作用时间和累计延后量。自然推进直接读取对象时间表，使用一份额度后只前进固定间隔；不会用当前剩余次数重新推算频率。`Ongoing` 是独立的类型化操作，不能借材料转换率修改时间或凭空复制持续伤害。

真实主术命中时，先结清同目标已经到时的持续作用，再对仍存活的既有状态分派 `status.contact`。状态读取自己的冻结配置，之后获得剥层刀或冷却墨片不能改写旧灼烧；派生攻击不触发这一接触入口。正式碰撞的去重在进入生命周期之前完成。每份状态最多各提前、延后一次，失败支付不领取次数。

- 提前操作逐来源计算并消耗接下来若干次的额度，在同一次事务交付伤害。剩余次数与余额真实减少，下一次自然作用时间保持不变；不足两次时只交付现有次数，耗尽即结束。
- 延后操作从命中的主术支付寒气，同时检查持续状态和主术的剩余加工次数；把下一次时间及结束时间一起后移，间隔、目标、威力和次数不变。费用不足或达到累计延后上限时不改状态、不扣费。
- 两者并存时先准备提前，再准备延后，之后交付已经付费的效果。若提前伤害致死，已准备的延后费用仍已支付；主术不再向尸体提交伤害，其未用力量按落空规则回收或损耗，目标剩余灼烧按死亡规则处理。准备后的同一份资源不会改判回滚。
- 松脂印章只在生成时增加寿命和次数。原生火书与跨书灼烧都读取这一修正，同样的总份额分得更细；不会通过增加次数新增伤害。腐蚀墨迹开放同一种灼烧加工，余烬墨水改善同一个加工保留池，不另建免费固定伤害系统。

寒墨与零度批注共用 `cold.convert`，把主术现存威力的一部分转成寒气；多个入口只转换一次，普通节点和遗物层数叠入 `cold.efficiency`。转换明确先于复写与保存，使留式取用已经存在的寒气，原主术同步失去这一份。正式命中传入已编译的冻结时长，旧遗物层数不会再旁路追加另一份冻结时长。

普通敌人积寒达到 100 后冻结并打断冲锋。守页者每次受控后增加抗性，上限三次：后续积寒效率和冻结时长按 `1 / (1 + 0.5 × 抗性)` 缩减，基础冻结不超过 0.8 秒。冻结期间及解冻后 2 秒不再积累寒气，已花出的材料不暂存、不返还；冻结保留其攻击准备，不能廉价重置攻击。数值是统一难度验收前的起值；旧终式中绕过寒气入口的效果仍须迁移，不能据此认定所有控制来源已完成。

### 付费路径与目标选择

原生电弧和分配得到的电弧使用同一条 `Transfer` 规则。每次命中后读取当前位置，在距离内寻找该路径尚未命中的目标，支付电荷和剩余加工次数，再交给下一次真实命中。电荷保留为跳转费用，不在普通命中中按伤害比例消耗。最后一次伤害后若仍有电荷，对象暂留供 `route.finish` 结束处理；没有后续目标、没有费用或达到次数上限也在本边界结束，不等待下一帧循环补发。

`Allocate.resourceShares` 各数组长度必须匹配共用子项列表，单项允许零、总和不得超过一；非法键、非对象、稀疏数组和超量在提交前拒绝。传导入口将一部分威力及全部可用电荷交给一条路径，其他材料按共用份额分配，原主术相应减少。显式改形只变更子项的形状与已声明次数，不重新展开原主书的次生形状；`Copy` 声明材料继承时从模板的真实材料中分走对应份额，不复制另一套材料供给。

一次命中最多提交一条成功的后续路径。生命周期使用迭代交付队列执行同步电弧，后续命中可以追加队列，但不递归调用完整交付流程。每条已支付跳转携带前一位置，绘制据此连接真实落点。结束时只保护**本次结束事件**里已经支付的释放或等待；先前释放的法术再次到期或断路时，其剩余份额仍可回收并关闭，不因它曾经是释放结果而成为常驻对象。

目标搜索先排除已死、当前不可作用、该路径已命中及距离外的敌人。之后用一次线性遍历选择最低优先级元组：附近威胁、同次人工来源尚未命中、原人工目标的有限照顾机会、剩余生命或距离、稳定敌人 ID。具体项由冻结配置开启；两项未开启就不参与排序，不按天赋 ID 在战斗里分支。

- 主术第一次选敌保留玩家选择。择重按剩余生命排序，给该人工来源的自动法术保留一次原目标偏好；偏好在成功提交目标时记账，排队中的多份复写不能全部重复使用这一次机会。
- 择近先在玩家附近选择，同时有择重时选择附近生命最多的敌人；附近没有可选目标才退回其他合格目标。它不会越过单跳距离限制。
- 空隙尺优先尚未被本次人工施法及其派生法术命中的敌人；盲页放弃原目标偏好，优先近处的新目标。终页铃仅对外壳结束释放启用附近威胁优先。
- 自动命中与后续电弧不更换正在输入的词条，也不生成新的完词记录。目标偏好、已命中集合和材料账均在房间结束后清理。

储电入口不要求额外分配分格储备；它只开放未用电荷的回收和后续取用，不因此开放其他材料的回收。回线环将电荷排在本词储备投入的前面，其余储备共用剩余额度。新获得的电荷供给不因该偏好增减。

原生法书、位移、治疗、生命上限、复活和终式通过登记的类型化效果适配器产生同一套事实与费用。保留旧代码的物理计算不等于允许它旁路供给、死亡回执和资产使用记录。获取效果分成可撤销的持续修正与仅首次取得执行的一次性效果，借还、演化分别处理。

T22 的结束释放示例：护页关闭事务先扣除挡伤份额，将尚未使用的 lot 转交到该结束事务的托管所有者；`shell.finish` 事实引用这些 lot。Release 消费该结束权和托管余额，之后其他热启、到期或防御处理均无法再取同份资源。

正式普通弹碰撞按真实 Bullet 对象去重，一颗弹只选择一张仍有效的护页。挡住部分伤害时，未挡部分继续进入原伤害流程；完全挡住不产生受伤回调。防御后该壳结束，其余按结束规则处理。字母兑换护盾不参与这类选壳，也不借此变成可攻击法术。

Heat 在施放位置和实际命中位置接触附近外壳；每个法术—外壳组合只能成功加热一次。转交者和外壳都参加同一次费用、加工次数与所有者版本校验；容量不足、耗尽或过期不扣款。存热有独立上限；达到开启门槛的非耐热外壳在同一事务内扣热并关闭，执行结果携带原壳与剩余托管对象交给生命周期处理。`shell.fracture` 先于 `shell.finish`，破裂消费完的份额不能再被 Release 发射。

碎片由同一原份额分割，使用一次基础命中，结构耗尽，不重新展开主书完整的多段形状。分配结果记录有限半径内的实际目标；没有目标的碎片消散，不在生命周期里重新搜索远处目标。目标在发射前消失也不暗中更换成远处敌人。上述位置约定不表示沿整个飞行线段持续加热。

## 3. 构筑编译

编译输入是版本化 BuildSnapshot，输出不可变 CompiledBuild：

1. 校验主书、天赋配置和资产合法性，生成出征许可；许可源只来自实际分配的定义。
2. 收集主书原生规则、已分配天赋、持有遗物与有效覆盖。相同规则许可按 ID 去重，层数仅作用于声明可叠参数。
3. 按数值池合并参数，检查模式槽。普通常驻冲突返回 `MODE_CONFLICT`；临时覆盖只遮蔽其声明的槽。
4. 将规则编译成按阶段和事件类型索引的定长操作序列，预计算选择器、参数和资源费用。
5. 对同阶段依赖进行拓扑排序。依赖环或没有严格有限支出的循环返回 `UNBOUNDED_RULE_CYCLE`。
6. 输出能力摘要、许可摘要、资源分配策略、目标索引需求、解释来源和工作上界。

辅助供给方向通过 `BuildContribution.supplyDirections` 声明 `resource`、正权重及可选模式条件。每种资源取有效来源的最大入口权重，再与原有辅助分配归一；层数和重复入口不扩大总收入。共享效率参数单独进入数值池。运行时对唯一辅助额度做固定点加权分配，整数余量按最大余数及固定资源顺序分配，总量严格等于本次已赚额度。

`RuleRegistry.modeDefaults` 只补充尚未选择的槽。天赋的常驻选择仍须互斥校验，事件遮蔽在选择之后执行；到期重编译恢复选择或默认值。默认值不作为另一个常驻来源参与冲突。护页默认先用旧壳，守旧与护新各提供少量防御效率并固定顺序，避免花点购买默认行为而没有收益。

火书的原生热量和余烬墨使用同一辅助方向；共同拥有不会得到第二份热量。施放与命中附近的加热先使用这份材料，命中时余下热量由原生适配器按已登记的折算率转为威力，再进入实际命中、灼烧及溅射的同一分配。该率是待统一校准的内容参数，不能用转化后的总威力反推新人工收入。

正式输入调用 `ManualSpellIncome.accept`，先计算全部有效 Supply，再通过同一账本回执给主术及辅助账户原子入账。之后收入阶段的 Supply 只核对既有支付事实，不能再次发放收入。收费、重复触发的 Supply 在定义阶段拒绝。

编译不运行战斗，也不根据伤害模拟结果临时调整数值。正式模拟与评估工具使用同一个编译结果。配置在战斗中改变时只在事务边界替换快照；已创建对象持有旧快照编号完成本房合法过程。

### 重复来源

T19 与 R070 都提供 Copy 操作时只有一个复制入口；各自声明的数值参数按注册池计算，不能各执行一次完整制作。只有同一入口已经完全无增量且没有后续资产作用时，才可排除重复掉落；不能以“当前没有强协同”为理由排除新的基础供给。

### 模式示例

防御消耗顺序由 `guard.consumeOrder` 控制，T23 和 T24 冲突；防御预留比例由 `guard.reserveShare` 控制，K10 与顺序模式可组合。字母机会分配与奖励用途也是两个槽，K14、K15 不应被同一个粗糙互斥组锁死。

## 4. 资源账与事务

```ts
interface ResourceLot {
  lotId: number;
  origin: { kind: 'manual' | 'enemyProjectile' | 'acquisition'; receiptId: string };
  parentLot?: number;
  resource: string;
  quantityQ: number;                // 固定点整数
  ownerId: number;
  appliedBonuses: readonly RuleId[];
  ruleClaims: Readonly<Record<RuleId, number>>;
  remainingUses: number;
}
interface RuntimeObject {
  instanceId: number;
  kind: 'spell' | 'shell' | 'status' | 'field' | 'reserve';
  programVersion: number;
  properties: Readonly<Record<string, number | string>>;
  lotIds: readonly number[];
  expiresAtTick?: number;
  closed: boolean;
}
interface ResourceTransaction {
  id: string;
  expects: readonly OwnershipVersion[];
  spends: readonly Spend[];
  transfers: readonly Transfer[];
  creates: readonly FundedCreation[];
  claims: readonly { lotId: number; key: RuleId; limit: number; uses: number }[];
  facts: readonly CombatFact[];
}
```

资源量使用固定点整数，初始量级拟用 1/1024 单位。分裂先按确定规则分配整数余数，最后核对父减量等于子增量与损耗；不能每个子对象分别四舍五入向上。不同材料单位不相加成一个模糊“能量”。

来源由正式输入、敌弹事件或资产事务创建；内容规则只能保留来源，不能把敌弹或获取效果改成 manual。每种资源声明整数范围，编译和交易都检查安全整数与非负余额，越界报错而非溢出或静默截断。

交易先检查所有权和版本，再一次提交。重复事务返回既有结果，失效所有者返回 `STALE_RESOURCE_OWNER`，不足返回 `INSUFFICIENT_RESOURCE`；失败不部分扣费。防御、热开和到期在同一 tick 竞争时，按照固定阶段与事件序号，仅一个出口取得结束权。

持续伤害按未来作用份额记账。抽取、死亡回收会减少尚未结算的次数或额度；下一 tick 不再使用旧副本。攻击已提交的过量数值不回流，只有还未提交的剩余份额可以转交。

合并保留 lot 列表，不生成一个没有历史的新来源。首批 Merge 限同根、同作用阶段、兼容形状与目标策略；不同来源的未来扩展无需改账模型，但当前不开放跨根聚合内容。

规则费用和次数领取与效果提交在同一个资源事务内完成。先验证领取上限，再扣费用、生成或转移剩余；子份额继承领取次数与减少后的加工次数。合并取各来源已经使用次数的最大值，不能把它们相加成新奖励，也不能清零。事件回执另做幂等处理，同一事件重放不重复执行，内容改变则明确拒绝。

### 收束判据

每个重复执行环必须有严格下降量：有限工作额度、剩余机会、未结束对象或固定点可用资源。回收不能返还制作工作额度；复制消耗新的已赚工作量；转换对同一 lot 同规则只发生一次；纯 Transfer 环必须消费跳数与电荷。

寿命是最后的时间边界，但不能只靠寿命掩盖一个 tick 内的无限循环。引擎的工作上限从合法规则和输入上界推导，达到上限按错误上报；不可把某个漂亮连锁默默截断后当成有效结果。

## 5. 获取与事件接口

```ts
type Decision<T> =
  | { ok: true; value: T }
  | { ok: false; code: string; reasons: readonly string[] };

// 无副作用；用于奖励、商店、赠礼、事件与图鉴解释。
evaluateAcquisition(definitionId, acquisitionContext): Decision<AcquisitionPlan>;
quoteEvent(eventId, boundAssetIds, eventContext): Decision<FrozenOffer>;
commitEvent(offerId, choiceId, expectedRevision): Decision<EventCommit>;
```

AcquisitionContext 包含不可变出征许可、实际资产与使用记录、当前能力、词库范围、模式和获取渠道。渠道只能改变机会成本与是否临时租借，不能让永久特殊遗物绕过许可。

掉落相关性判断使用当前构筑能否产生所需对象或事件，不要求菜单打开瞬间恰好有一只燃烧敌人或正好缺少护盾。例如持续工具需要已有持续伤害入口，而不是当前必须存在未结算的灼烧。临时能力若构成唯一使用来源，报价要明确到期后的条件变化。

FrozenOffer 保存内容版本、构筑修订号、战役房章位置、具体实例、许可版本、每项数字、资产去向、恢复方式与到期时机。不能只比生命和持有遗物，漏掉临时能力或模式变化。过期报价返回 `STALE_OFFER`，不扣费，并重新展示当前有效报价。

租借与抵押使用实例状态：`owned / leased / pledged / returned / replaced`。返还恢复原实例及使用回执，不重新执行一次性治疗、复活或获取奖励。章界按“清理旧房对象 → 处理归档 → 到期覆盖 → 返还／移除借物 → 重新编译 → 准备新房”顺序进行。

随机数分为遭遇、奖励、事件和纯视觉流。新增一件视觉效果或多发一个弹道不能改变下一次奖励。事件筛选不按玩家成绩暗中调整，同种子和同一合法状态得到相同报价。

## 6. 根据节点关系自动生成平面图

### 6.1 先定义问题，而不是先选弹簧参数

输入不是一份必须全部绘制的多对多连线表。输入包含节点的概念权重、规则输入输出、学习前置、互斥、允许的邻接倾向与可达目标。输出同时包含位置与真正的成长边。

“玩法关联强”增加语义接近的要求，但不要求直接相邻；指定的成长必经关系才是硬约束。发现具体冲突时列出条件；搜索预算耗尽时报告尚未找到布局，不能冒充无解证明。禁止悄悄删前置、画跨屏弧线或加入付费空节点。

### 6.2 比较与选择

| 方法 | 优点 | 选择依据 |
| --- | --- | --- |
| 无约束力导向后减少交叉 | 易接入旧图 | 交叉是惩罚项，无法直接保证归零；同一语义可能漂散 |
| 手绘分区、每族固定数量的环 | 容易做出整齐局部 | 不采用；固定内容数量和坐标会反过来限制关系 |
| 先冻结任意图，再求平面画法 | 可处理已经适合平面表示的拓扑 | 不能把非平面关系、固定书位与近邻约束都凭空满足 |
| 语义散点 + 平面候选边 | 可以建立不交叉的近邻候选 | 仅作算法参考；不会自动形成可辨的节点群、圆环和分支，也不能证明购买顺序合理 |
| 语义归组 + 可变局部图形 + 整图连接与购买检查 | 内容决定组与用途，程序形成清楚的几何层次 | M4 采用；具体步骤与失败处理见[天赋图方案](../migration/M4-TALENT-GRAPH-PLAN.md)，完整候选可行性仍须实施验证 |

局部图形不是手绘模板：节点数量、角色和连接由内容决定，短链、弧线、分叉、菱形、圆环只是可复用的构造规则。首版不要求引入三角剖分库；逐条检查真实显示路径，拒绝交叉的候选连接。生成失败不得以未经验证的直线或旧图替代。

### 6.3 语义向量

```ts
interface SemanticProfile {
  concepts: Readonly<Record<string, number>>;
  objectKinds: readonly string[];
  operationKinds: readonly string[];
  inputProperties: readonly string[];
  outputProperties: readonly string[];
  tradeoffKinds: readonly string[];
}
```

概念词汇是版本化注册表，包含稳定 ID、中文别名与书籍亲近权重。候选卡中的中文概念先规范化，未知词报错；不能因新遗物随手写了一个“流派标签”就自动进入图和执行器。首轮完整词汇归并如下，权重顺序为火、雷、冰、纸，每行和为 1：

| 概念 ID | 对应候选概念与别名 | 书籍亲近权重 |
| --- | --- | --- |
| base | 主术、命中、数值、全图基础连接、目标 | .25 / .25 / .25 / .25 |
| cold | 寒气 | 0 / 0 / .85 / .15 |
| heat | 热性、受热、热加工 | .70 / .10 / .20 / 0 |
| structure | 结构、碎裂 | .20 / .10 / .60 / .10 |
| storage | 保存、空间、时间 | .10 / .10 / .40 / .40 |
| recovery | 回收、储备、跨房 | .40 / .15 / .20 / .25 |
| routing | 电性、路径、距离、转交 | .10 / .60 / .15 / .15 |
| replication | 复制、继承 | .05 / .15 / .25 / .55 |
| shaping | 分配、集中、形状、聚合 | .15 / .30 / .35 / .20 |
| literacy | 词形、输入、准确、辅助、延续、节律 | .15 / .20 / .10 / .55 |
| protection | 防御、弹反、生命 | .15 / .25 / .25 / .35 |
| risk | 风险 | .50 / .10 / .10 / .30 |
| transport | 运输、纸灵 | .05 / .20 / .10 / .65 |
| field | 区域、位置、移动 | .25 / .30 / .25 / .20 |
| supply | 供给、材料、加工、转换 | .25 / .25 / .25 / .25 |
| study | 专精、兼修、终式、共鸣、成长、机会 | .25 / .25 / .25 / .25 |
| duration | 持续、持续伤害 | .70 / .10 / .15 / .05 |
| release | 释放 | .40 / .10 / .20 / .30 |

这是宏观倾向的候选版本，不会把“时间”和“保存”强制变成同一种操作；对象、操作和输入输出四组特征继续区分它们。未来星空扩展这一注册表的书籍维度，不为每个节点补写新坐标。

每个节点声明少量概念权重，例如保存 0.5、热加工 0.3、时间 0.2；权重来自实际规则的对象和操作，并允许设计审查后的显式补充。材料、操作、对象、代价四组分别归一化，避免堆标签增加相似度。

候选亲近度为版本化组合：

```text
A(i,j) = 0.40·操作相似 + 0.25·对象相似
       + 0.20·输入输出可衔接 + 0.15·代价与时间相似
```

每个术语另有对各书基础概念的权重。不是按名字含“冰”就归冰；数值节点从其影响的统计用途取得向量。全书通用的数值节点在共享邻域，不能成为横跨全图的万能捷径。

### 6.4 位置生成

1. 将图域定义为圆盘，半径 R 根据节点数量、节点外形与文字占位确定。书位使用宏观锚点：火 -140°、雷 -90°、冰 -40°、纸 90°，半径 0.4R。角度采用屏幕坐标，向下为正。这是用户指定的整体布局参数，不是逐节点坐标。
2. 根据操作、前置和概念把机制与质变节点归组，再把每个数值实例安排到有用途的位置；群本身不花点，也不提供额外奖励。
3. 从内容所需的路径选择局部构造，按节点、文字和路线间距计算形状尺寸。普通、机制、质变与书根使用不同占位，不在生成后才把文字盖在线上。
4. 按概念对书位的权重安排整组位置。专属用途向外延伸，共享用途进入内侧与书间空间；固定顺序选择位置、旋转和镜像，不使用随机扰动，不手填单点坐标。
5. 从相近且语义允许的出口选组间连接，逐条拒绝交叉、穿点及过长绕行。完成候选后按正式分配规则检查购买顺序、前置和模式，失败反馈给归组及几何调整。
6. 初始最多 64 轮固定次序的整体修正。搜索用尽只说明本轮未找到结果，不能冒充无解证明。输出具体冲突、变化与路线见证，不发布“交叉较少”的图。

R 在生成中定义为圆盘设计半径，不以某一孤立节点把包围盒突然撑大；完成后检查实际节点轮廓的最大半径落在 0.95R–R，书节点中心为 0.4R。若最外层过空则整体重新求 R 与布局，不靠看不见的外框凑半径。

### 6.5 近邻与成长边选择

设 d(i) 为节点最近五个可用邻居距离的中位数。候选边需同时满足：距离不超过 `1.8·min(d(i),d(j))`，且不超过 `0.18R`；还要有足够语义关联或明确的过渡关系。系数是候选设计参数，调整要整图一致，不能给某条长线开特例。

先把各局部群与书根连通，再增加有用的绕行和跨区环路。普通节点度数目标 2–4，硬上限 5；书位上限 6；允许有意义的终点，但不通过唯一中央节点接通所有区域。互斥模式节点不能成为唯一跨区通道；数值系列不能为了凑几何形状被复制或丢弃。

选择过程包含购买规则：某条图上可走的路，如果要求沿途依赖尚未取得的自身能力，就不算可达。检查四书初始 2 点的可玩入口、长路径的沿途用途，以及互斥造成的断路；相邻／对侧书根成本先记录，候选 8–14／14–22 点不是 M4 的平衡通过线。失败时调整连接或位置，报告具体冲突或搜索未完成，不创建免费传送边。

### 6.6 零交叉与标签保证

局部圆弧和组间轻微曲线先按显示精度采样、量化，再检查其实际路径；运行时使用同一份采样。不能检查直线却绘制另一条曲线。粗高光也需要边界间距，不能让中心线无交叉但实际发光混成一团。

标签在节点周围有限候选位置中选择，各缩放显示档分别检查。宏观只保留少量重要名字，近看才显示普通名字。可见标签不得与无关节点、线段安全带、其他标签相交；找不到位置先扩大局部间距重新布局，不能发布被遮挡文字。

横穿、共线重叠、无关节点在线上都算失败；共享端点不算交叉，但出口角度须可辨。量化后在已限定坐标范围内使用 64 位整数检查线段方向，具体范围和精度见 M4 方案。浮点近零风险可参考 [Shewchuk 的稳健几何判定资料](https://www.cs.cmu.edu/~quake/robust.html)；不据此引入额外几何库或要求运行时重复布局检查。

### 6.7 遗物图与关系显示

先完成天赋图，再让遗物图复用局部构造、排布、标签、检索和视口模块。遗物节点不使用天赋购买规则，而把实际演化边作为约束；普通玩法关联仅参与位置与详情。共享的是绘图基础，不是两图完全相同的拓扑或节点数量。

默认不把许可、所有前置、互斥和事件引用画成线网。选中节点时高亮已有的合法路径，远处关系通过详情中的名称与定位操作查看。若某类额外关系无法在当前平面图内表达，就不额外画线，不能用虚线交叉来规避零交叉要求。

第五本书加入时扩展书籍锚点和概念权重：纸与星分别位于下方两侧，保留上方三书。概念与内容 ID 不编码“四个象限”。拓扑变化时重新检查配置，只有坐标变化不退点；当前不增加星空占位节点。

## 7. 购买闭包与路线搜索

配置验证从免费主书起点开始，按可购买顺序逐步加入指定节点，保留一个合法顺序见证；不能因为最终集合互相引用，就接受实际上无法买出第一点的前置环。

撤点也从免费根正向重建剩余配置，没有加入的候选作为连带撤点，不能只向后删除最终条件不满足的节点。后者会遗漏撤点后互相支撑的 OR 前置环。副书、独卷形状、具名模式和 K19 校准材料属于同一选择契约；失去供给的材料要求在预览中重选，不自动删除仍满足前置的 K19。

自动规划路线使用状态搜索：状态包含已分配节点位集、全部模式／材料等选择、相关前置和实际费用。只按当前节点 ID 做 visited 会错误合并能力不同的路径，因此禁止复用这种简化。先找可重放的候选，再用有限状态搜索改进；可使用启发式优先队列、同状态最低费用去重和保守支配剪枝。

UI 路线搜索不能阻塞交互，应支持预算、取消和旧结果失效；50,000 次扩展是现有方案的候选交互预算，不规定执行线程。达到预算若已找到合法路线，显示“找到可用路线”，不宣称最短；未找到时显示“尚未找到”，不冒充不可达。正式确认沿正式分配器重放整条路线，旧快照搜索结果不能直接扣点。

生成器审查可用更高预算并保存见证，无法穷尽的组合单列未证结论。打开图谱只读取布局产物，不重跑整个优化算法。

## 8. 展示与执行边界

布局产物带内容哈希、拓扑版本、布局版本、算法版本、字体测量版本、节点／边／标签包围盒及空间索引。相同输入必须得到相同量化结果；配置或悬停不改变布局坐标。显示状态作为独立 projection 叠加。

图谱按视口裁剪节点、边与文字；宏观尺度显示区域和关键形状，近看才显示普通节点名称。固定详情覆盖的空间从搜索聚焦安全区域扣除。节点材质、金丝、高光与光效遵循[金丝水晶](../ART-DIRECTION.md)，长时间停留不依靠全屏常驻动画。

规则检索应与相关事件及活动对象数量相称，避免反复扫描全部内容和关闭历史；构筑快照在配置变化时更新。渲染消费已提交事实，不能为了显示再执行一次玩法规则。具体索引、对象管理与更新机制由实现选择。

并发与异步实现也必须保持单份资源唯一结算、输入顺序、原子提交和快照边界；不得由多个执行者重复领取同份资源。这里不指定线程组织、平台包装或发布格式，现有实现方式见[实现快照](../../../TECHNICAL-SNAPSHOT.md)。

## 9. 新游戏存档与自身版本更新

Godot 按新游戏建立账号，不导入或导出旧浏览器进度。配置版本、规则版本、成长拓扑版本与布局版本分开。本游戏后续版本使已有配置失效时，保留累计字符、去重结算和已赚预算并提供重配；只改坐标和表现不退点。

出征配置冻结内容版本，不在正在进行的战斗中半途替换规则。本游戏的历史报告保存当时名称与效果快照，即使后续合并定义也能阅读；任意时刻战局续玩不属于当前承诺。

God 使用独立进度、配置、局状态和历史目录。清理只操作该模式的明确文件清单，不能清空普通数据。God 无限的是点数预算，仍遵守路径、模式冲突、权限来源、规则收束和合法操作。

存档模型不保存可反向修改运行规则的任意字符串脚本。本游戏存档中的失效 ID 标记为待重配并留下诊断，不默认激活某个同名新节点。
