# 原项目体验与原生落点

玩法基线为 Git 提交 `b713c6e`；取证入口见[数据映射](DATA-AND-ASSETS.md)。当前 legacy 中后加的天赋、加工网络和交易不能当作必须迁移的原体验。当前产品规则见[产品设计](../PRODUCT-DESIGN.md)，实际完成范围见[阶段总结](../STAGE-SUMMARY.md)。

## 保留体验

| 体验 | 原生落点 | 对照重点 |
| --- | --- | --- |
| 四书轨道、选书、出征仪式 | `ui/archive_home.gd`、`departure_ritual.gd`、书籍 Resource | 原插画、元素色、切换声音和可中断过渡；出征配置保持简洁 |
| 词库、设置、习字 | `game/vocabulary/`、输入路由、页面壳 | 字体就绪、输入归属、导入预览、词长、释义、暂停与保存 |
| 打字施法与四书节律 | `BattleSession`、`SpellRuntime`、词咒表现 | 一词的投入和结果清楚，普通／强化／终式有身份，输入不被过长表现阻断 |
| 弹反、闪避与受击 | 接触几何、战斗动作、轨迹与音效 | 真实反射、近战推离、落点和免伤；反馈帮助判断输入窗口 |
| 局内遗物三选一 | 奖励组件、正式获取与说明 | 选择居中、效果可比较，拿到后能感知；不能只恢复名字 |
| 路线 | RunSession、路线页面 | 恢复／挑战／付血换奖励的直接选择，减少阅读与多层确认 |
| 敌人与 Boss | 遭遇资源与固定步行为 | 逼近、支援、预警、转火、阶段与词咒可读性 |
| 结果与连续挑战 | 战报、RunSession、保存 | 实际输入记录、胜败反馈；明确下一难度并保留遗物，正常重开清空本局资产 |

既有天赋图的 UI 和几何证据只作为历史资料保留，不继续复刻。图鉴采用检索和固定详情；独立遗物图案、开放材质与稳定滚动继续有效。

## 如何做对照

先读对应的旧定义、调用链、动态时序和声音触发，再选择 Godot 原生场景、Resource、AnimationPlayer、粒子或 shader。需要确认节拍和手感时运行独立的基线检出，不覆盖根工程，也不把浏览器逐帧轨迹作为引擎契约。

实际观察起止、连续输入、打断、暂停、目标死亡和结束清理。截图只帮助检查阅读层级与关键帧，不能证明动态过程或实际效果正确。

既有 M1／M2 已获用户验收，但 M3 后的规则变化和本次恢复均需按受影响范围重新观察。完整旧对照与截图位置见[归档快照](../archive/2026-10-08-build-system/migration/EXPERIENCE-MAP.md)，不能把其中天赋流程或旧测试数量当作当前验收。

## 原生表现约束

保留 1920×1080 设计空间、HDR 2D、正文清晰层、金丝水晶、开放排版与减少动态。不因为玩法收缩更换已确认的视觉方向，也不将浏览器 CSS／SVG 滤镜直接照搬。

Godot HDR 视口抓图需在高精度线性像素上转 sRGB 再保存，避免用偏暗截图调整曝光。正式画面以独立游戏窗口为准；具体工具见[工具链](TOOLCHAIN.md)、[验证说明](../TESTING.md)与[UI 实践](UI-IMPLEMENTATION-LESSONS.md)。
