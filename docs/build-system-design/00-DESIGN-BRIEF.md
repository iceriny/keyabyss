# 天赋—遗物—事件：设计总纲

本目录维护有效玩法设计、候选内容与语义契约，不再作为按步骤推进的工作日志。实际接入范围见[阶段总结](../STAGE-SUMMARY.md)，未完成工作见[TODO](../TODO.md)；原研讨过程和旧内容事实见[历史归档](../archive/README.md)。

## 构筑的目标

玩家构筑一套相互作用的规则：法书提供起点与鲜明手感，天赋提供长期能力和部分特殊遗物许可，遗物提供本局零件，事件改变规则、机会和取舍。

内容的价值来自通用性质、操作与代价的碰撞，不来自我们预先写好的毕业路线。保存、防御、受热、转交和回收应能接受不同兼容来源；同一种属性变化在不同构筑中可以产生相反价值。组合示例用于检验这些关系，不能成为奖励系统必须补齐的配方。

节点数量、旧位置、旧连线和现有模块边界不是必须保留的前提。宏伟图景来自丰富且可理解的构筑空间，节点与路径必须有实际用途。

## 操作直接，规则丰富

战斗主要是选目标、打字、闪避和弹反。打字始终是主要进攻来源；防御争取输入时间，强反击主要消耗打字积累的力量。内部保存、分裂、接力与回收自动执行，不增加逐份调度资源或召唤物的操作负担。

一词可以驱动完整后续过程，不能要求多数小怪存活多轮才使联动启动。目标当场死亡后，已经取得的有限后效有合法结果；耐久目标与 Boss 则检验持续、控制和储备的另一面。

人工输入、实际资源来源和天赋许可是不可伪造的事实。派生和自动效果不能重新领取完词收入；防御、攻击、释放与回收竞争同一份尚未使用的力量。允许强放大与长连锁，但新增收益必须有清楚预算，停笔后必须收束。

## 图谱空间与成长

把图看作大致圆盘，书位距圆心约为半径的五分之二：纸灵下方，火左上，雷上方，冰右上。各书都可向内、向外和向侧面发展，不能形成四张独立树。

沿书位方向偏向本书核心概念，书间空间偏向共有机制与融合。空间接近应有可解释的概念联系；远处协同不必直接画成成长边。火与冰也可以通过内侧结构、热处理和保存概念自然靠近。

成长线的硬约束：

- 零交叉、不穿无关节点或文字，只连接位置较近的节点。
- 可见成长线对应真实可走路径；不使用隐形交叉点、无意义收费节点或跨屏长线掩盖冲突。
- 位置和连接由关系与约束共同程序生成，不手填逐节点坐标、不随机排布。
- 长路径通过连续且逐步有用的节点跨区，路径费用、预算与成长节奏一起设计。

天赋图先把相关节点组织成可辨认的分支、圆环、菱形等局部结构，再生成整图位置和真实成长连线。局部结构大小随内容变化，不要求每族固定数量；次要数值、主要机制和质变有明确的尺寸、轮廓与图标层级。

天赋图和遗物图共用视口、绘图、检索与固定悬浮详情基础；成长、关联、许可和演化分别解释，不能混成一种线或强迫共用拓扑。M4 优先完成天赋图数据、正式分配与程序生成，具体见[基础建设方案](../migration/M4-TALENT-GRAPH-PLAN.md)。全屏与节点层级遵循[开放式 UI](../OPEN-UI.md)，材质遵循[金丝水晶](../ART-DIRECTION.md)。

未来星空可能在纸灵附近形成下方两书、上方三书的结构。当前考虑概念和布局的可扩展性，不提前增加星空或占位内容。

## 成长与许可

跨局赚取点数、出征前重配、God 无限点数与独立清理是确定的产品要求。Godot 按新游戏建立进度，不建设旧浏览器档案转换。后续本游戏的规则或拓扑变化重新验证配置，失效时保留已赚进度并重配；纯布局变化不退点，God 清理不影响普通数据。

特殊遗物许可来自本次出征实际分配的天赋。普通遗物仍提供基础方向，临时借能力不发专属许可；开池不保证掉落。能力是否存在、内容是否可使用、是否具有特殊资格分别检查。

候选成长上限、曲线、节点成本和资源倍率尚待统一校准。具体契约在[系统框架](04-SYSTEM-FRAMEWORK.md)，候选数值不能被写成已经实测的结论。

## 收益与难度

共用[收益模型](../COMBAT-BALANCE-DESIGN.md)，同时考虑法书、天赋、遗物、事件和路径机会成本。整体平衡在 M5 完成后的 M6 统一评估，不阻塞 M4 图数据、购买和生成，不为每件遗物另建平衡脚本。

最后两档必须体现足够成长与合理构筑的价值：初始高手不能直接打穿，中等水平在不错构筑和较好运气下有机会通关。工程检查、局部账务正确与历史机器人样本都不能代替该目标的最终验收。
