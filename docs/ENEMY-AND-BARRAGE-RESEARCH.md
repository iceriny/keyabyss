## 1. 建议方向

优先增加能改变玩家决策的敌人，同时让已有敌人的攻击和组合更容易被感知。研究起点有 **17 种普通敌人、3 个 Boss**，但多种敌人共用攻击形状，普通页按小池随机抽取，三位 Boss 也共享较多攻击骨架。因此，“种类较少”的体感不能只用资源文件数量解释。

建议首批增加 **狙笔手、复诵者、护卷使**，普通敌人由 17 种增至 20 种；分别增加精确威胁、双段节奏和保护关系。随后根据实际体验筛选折页师、裂墨蚌、留印师，全部采用时达到 23 种。数量是候选内容规模，不是必须凑满的验收指标。

同时推进两项直接收益：

- 把常规弹、弧线弹、重弹、区域攻击的视觉语义分清，让玩家在读词咒时也能辨识防御方式、攻击来源和下一拍。
- 用少量有意设计的组合与错峰出手替代部分纯随机堆叠，让同一种敌人在不同搭配中承担不同作用。

首批不增加 Boss 数量，不改四书与遗物规则，不新增普通移动。性能工作从现有敌弹绘制链的重复采样、线段提交和透明覆盖开始，是否采用批量网格由实际测量决定。

## 2. 现有实现盘点

### 2.1 敌人已有的差异

以下以资源 ID 为准，避免把研究命名混入现有内容。定义见 [enemies](../game/content/enemies/)，行为见 [BattleSession](../game/session/battle_session.gd) 的 `_advance_enemy_motion()`、`_advance_enemies()`、`_resolve_attack()` 和 `commit_damage()`。

| 普通敌人 ID | 实际机制 | 已有辨识点与扩充空间 |
| --- | --- | --- |
| `nib` | 追近后预警扇区近战 | 基础近身教学角色，保留简单性 |
| `leech` | 更快的摆动近战，贴近时消耗闪避次数 | 资源压力已经存在；无需再造一个同类吸取怪 |
| `split` | 近战，死亡生成两个小型 `nib` | 死后分裂已实现，新候选应避免重复 |
| `ram` | 锁定位置后冲锋，普通／完美御术可打断 | 直线冲锋与接触压力 |
| `reaper` | 更快、间隔更短并摆动接近的冲锋 | 与 `ram` 主要是速度、节奏差异 |
| `quill` | 瞄准扇形弹 | 缺少精确单发的普通敌人角色 |
| `guard` | 扇形弹，正面直接命中减伤，优先长词 | 耐久与正面承伤角色，不是保护同伴的护卫 |
| `mirror` | 扇形弹；护镜周期恢复，受直接命中时减伤并回射扇形 | 已有反击时机；冻结能绕过护镜 |
| `wisp` | 摆动移动，单发弧线加速弹 | 弹道在发射时确定，不持续追踪玩家 |
| `sentinel` | 留缺口的环形弹，优先长词 | 移动型环弹来源 |
| `tower` | 入场后驻留并发环弹；存活时为 Boss 减伤 | 固定威胁源与优先击破目标 |
| `binder` | 弯曲环弹，同伴移动加速光环 | 光环当前增加移动速度，不是全面加快所有攻击 |
| `scribe` | 预警后的横／竖贯场射线 | 区域攻击，不能御术 |
| `mortar` | 锁定位置爆区，生效时附加向外弹体 | 定点迫使换位，与普通来弹防御不同 |
| `priest` | 为范围内至多三个低血量同伴恢复生命 | 已有治疗优先级，不必再加普通治疗怪 |
| `brood` | 扇形弹，交替召唤小型 `leech`／`wisp`，每只最多五次 | 召唤有生命周期上限，不是无限增殖 |
| `vortex` | 牵引玩家与环境，爆区加弯曲环弹，死亡产生牵引及局部伤害 | 已有空间干扰与死亡联动，组合时风险较高 |

三个 Boss 为 `ink-colossus`（吞墨巨像）、`echo-archivist`（镜页织者）、`final-editor`（大校对官）。均按约 67%／34% 血量进入三个阶段，复用环弹、射线、扇形和爆区；差别主要在曲率、延迟组合、援军与最终阶段召塔。现有差异有效，但“主招是什么”仍可进一步强化。

普通敌人和 Boss 都已有独立 SVG，见 [BattleActorVisual.ENEMIES](../ui/battle_actor_visual.gd)。不能把体感问题归因于“所有敌人用同一张图”；需要在正式尺寸下验证轮廓、起手动作和攻击来源能否被快速分辨。本轮没有观察运行画面，外形辨识不足仍是待验证假设。

### 2.2 遭遇曝光与组合

正式页资源位于 [encounters](../game/content/encounters/)，六个普通页的池子如下：

| 页 | 普通池 |
| --- | --- |
| 失落书库·入口 | `nib / quill / wisp` |
| 失落书库·深处 | `guard / wisp / ram` |
| 镜页回廊·入口 | `split / scribe / mirror / leech` |
| 镜页回廊·深处 | `mortar / priest / sentinel / brood` |
| 终稿法庭·入口 | `binder / vortex / reaper / sentinel` |
| 终稿法庭·深处 | `brood / priest / mirror / mortar / scribe` |

`_advance_encounter()` 从未达到 `spawn_limit` 的候选中等概率抽取，控制批次、页配额和存活数量；`binder / brood / priest / vortex` 的同种上限为 2。当前没有按“支援、封路、精确射击”等职责分组的预算，也没有保证某种敌人首次展示的编排。后两章内容较多，但单个页只见到部分池子，某些职责还可能同时叠加。

当前自然刷怪上限最多 24，只限制这条生成路径；召唤、死亡分裂和 Boss 援军另有入口。未来若引入角色或实体预算，必须明确是否包含这些来源，不能把自然刷怪上限误当全局上限。

### 2.3 弹幕、预警与性能事实

| 入口 | 当前事实 | 对方案的影响 |
| --- | --- | --- |
| [EnemyCombatDefinition](../game/content/enemy_combat_definition.gd) | 配置行为、数值、光环、死亡效果等；没有通用攻击序列或独立弹体视觉配置 | 新增行为不能仅复制 `.tres` 改名；也不必先搭庞大技能框架 |
| `BattleSession._emit_pattern()` | 主要为 `single / fan / ring`；环形每次留两个相邻空位；多个敌人共享发射数量与速度公式 | 可复用几何，但需要拉开节奏、预警与来源身份 |
| [BattleThreat](../game/combat/battle_threat.gd) | 固定步弹体，含曲率、加速、半径、反射与轨迹；弧线使用解析积分 | 保留已修正的发射起点、弧线命中和碰撞链 |
| [BattleHazard](../game/combat/battle_hazard.gd) | 圆形与线段范围，预警／生效共用几何 | 首批区域候选优先复用这两种判定 |
| `BattleSession._advance_hazards()` | 来源死亡或离开有效战场会取消区域攻击；已发射弹体独立飞行 | 清场与来源消失的语义必须按对象分别保留 |
| [BattleThreatOverlay](../ui/battle_threat_overlay.gd) | 危险信息在清晰层逐帧绘制；常规敌弹共用暖色光球，反射后转浅绿；弧线弹增加暗心与细环 | 已有基础分层；可增加形状差异，不必把整个弹幕移入辉光层 |
| 同上 `_draw()` | 每弹每帧转换轨迹、调用 `MotionTrail.build()`，再逐段绘制两至三层线；每弹另有柔光与亮核 | CPU 绘制准备和透明覆盖值得定向测量，尚不能判定为实际瓶颈 |
| [MotionTrail](../ui/effects/motion_trail.gd) | 去重、接插值头、按长度裁切；`max_points` 只在启用平滑时参与细分 | 敌弹调用传入 `smooth=false`，只减小 `max_points` 参数不会实现降采样 |
| `BattleSession._advance_threats()` | 曲线弹保留约 32 个物理样本，直线弹约 12 个；尾迹无伤害判定 | 视觉优化必须保留真实弹头与扫掠碰撞 |
| `BattleThreatOverlay` 的质量选项 | 弧线外层柔光受画质／减少动态控制，但核心尾迹构建和不少线段仍执行 | 画质成本梯度可改善，不等于低画质可以漏画弹头 |
| `BattleSession._safe_direction()` | 预测当前弹体未来 1.4 秒，24 个候选方向，经 .NET 批量评分；同时考虑已有危险区 | 分裂、变轨等新运动若加入，实际飞行与自动闪避预测必须一起更新 |

历史性能证据见[战斗算法实施记录](migration/COMBAT-ALGORITHM-IMPLEMENTATION.md)：本机环形 256 弹的自动闪避评分 p95 为约 4.53ms，仍超过当时 4ms 目标。这是既有 CPU 微基准，不是本轮测量、整帧耗时或 P620 GPU 性能。因此不建议用大幅增加弹数作为首批内容扩充手段。

归档 [ENEMY-VARIETY](archive/ENEMY-VARIETY.md) 曾讨论旧 Web 攻击轮换、夹击和精英词形。它只说明历史探索；当前原生代码没有直接沿用其中的 `attackSequence`，本文也不恢复其词库偏好与旧输入规则。

## 4. 针对打字战斗的设计约束

### 4.1 丰富的是决策，不是手部负担

每个新敌人应能用一句话回答“它改变了哪一个决定”：先打谁、是否继续当前词咒、何时御术、何时使用闪避、闪到哪里。依靠额外快捷键、临时更换词咒、打乱输入顺序或隐藏字母制造差异，不适合首批。

玩家没有普通移动。环形缺口即使几何上存在，也未必位于一次闪避可达的位置；狭窄弹缝和需要连续走位的旋转墙不能直接作为必过路径。需要同时考虑玩家半径、240 单位闪避距离、场地边缘、已有危险区、闪避余量和恢复节奏。

保留基础防御语义：普通敌弹、近战和冲锋可以御术；圆形／条带区域攻击需要闪避。首批不增加“外观近似的不可御术弹体”。装饰、重弹与弧线形状不改变此规则。

### 4.2 预告可承诺，攻击可理解

预警一旦呈现，瞄准位置、范围和本次序列保持一致。除明确的控制中断外，不在最后一刻重新瞄准或更换安全区。双段攻击在起手时就显示两拍提示，不把第二拍当作隐藏惩罚。

首见展示采用“单一特殊敌人＋少量已学会的基础敌人”，后续再混编。初次遭遇不同时叠加长词、突然近身、高速弹和支援保护。词咒继续服从玩家词库、首字母分配及当前输入进度规则；等待词位的特殊敌人不应成为必须立即打掉的唯一解。

数值候选统一按战斗世界时间与 1920×1080 逻辑单位描述。真人防御窗口还受真实时钟和慢时影响，不能只比较两个冷却数字推断“一次防御恰好挡住几发”。攻击强度最终接入[收益与难度评估](COMBAT-BALANCE-DESIGN.md)，不单独建立敌人的第二套平衡标准。

## 5. 敌人候选与内容分批

所有名称和 ID 均为候选。首批数值用于灰盒原型比较，不是已校准终值。血量先与同章既有敌人相近，不以大幅加血证明新机制存在。

### 5.1 首批：三个新职责

| 候选 | 狙笔手 `pin_archer` | 复诵者 `refrain` | 护卷使 `folio_warden` |
| --- | --- | --- | --- |
| 一句话机制 | 长预告后向锁定位置发出一枚较快墨针 | 一次蓄力后向同一锁定位置连发两拍 | 用清晰连线保护一个普通同伴，自己暴露 |
| 与旧敌人的差异 | `quill` 是扇形覆盖；它是低弹数、精确时机压力 | 不是 Boss 才有延迟攻击；主要考察完整节奏而非数量 | `guard` 保护自己，`tower` 保护 Boss；它建立局部可拆关系 |
| 原型参数起点 | 约 `quill` 的 0.85 倍血量；间隔约 4.8s；预告 1.2s；1 弹 | 约 `quill` 血量；每轮约 5.2s；起手 1.1s；2＋2 弹，间隔约 0.75s | 约 `priest` 血量；单目标减伤 25%；连接约 2.5s，随后至少 2s 空窗 |
| 玩家选择 | 先击杀，或保留当前词咒并准备御术／闪避 | 识别第二拍后继续输入，或通过一次换位避开整组固定瞄准 | 拆支援、控制支援，或利用空窗处理被护同伴 |
| 第一出现位置 | 失落书库·深处，以低占比替换部分远程名额 | 镜页回廊·入口，先独立展示 | 镜页回廊·深处，首次只保护一只普通基础敌人 |
| 首轮同场限制 | 至多 1 只，后续验证后考虑 2 只 | 至多 1 只 | 至多 1 只，首次不与治疗／加速支援共存 |
| 外形与动作 | 单枚长笔尖，两侧收束短羽；瞄准时笔轴固定，发射有短促后坐 | 对开的两页书片，两枚实心刻点依次熄灭；第二拍仍来自同一实体 | 半卷书页托住小晶核，向受护者伸出一条低亮叶脉状连接 |
| 成本与依赖 | 低：普通直线弹，新增明确起手配置 | 中：普通敌人的有限攻击序列及取消／冻结语义 | 中：单目标关系、统一伤害入口减伤和连接表现 |

**狙笔手的细则：** 发射后不追踪。靠近玩家时应延后攻击或降低初始速度，保留预告后的可反应飞行时间；这在发射入口确定，不能靠扩大视觉弹头补救。伤害先不高于同章常规敌弹。不能使用瞬发射线冒充“可御术墨针”。

**复诵者的细则：** 两拍共用起手时的瞄准位置，序列期间保持发射站位；不在第二拍读取玩家最新位置。两拍都有可见提示，允许一次合适的换位避开整组，不强制消耗两次闪避。死亡／明确打断取消尚未发射部分；冻结暂停进度，解冻继续；已发弹体沿自己的时间运行。首轮不叠加分裂、追踪或额外环弹。

**护卷使的细则：** 只保护一个有效战场内的普通敌人，不保护自身、同类、Boss 或塔；同目标减伤不叠乘。距离断开、受护者死亡、施术者死亡／冻结／打断时连接失效；新目标到下一轮再选择。护卫期不同时输出弹幕。四书的直接、持续与派生伤害应按明确的同一减伤规则结算，不要求某一种元素才能破盾。连线无伤害，外观不能与危险激光混淆。

### 5.2 后续候选：先证明新增决策

| 候选 | 机制与反制 | 首轮边界 | 不先实施的原因 |
| --- | --- | --- | --- |
| 折页师 `fold_caster` | 两条预告清楚、先后生效的有限条带，要求选择能避开整组的落点；击杀可取消来源危险区 | 同场 1 只；条带端点与间隔在起手时确定；先沿用线段危险判定，不做持续旋转激光 | 需要把双条带一并纳入自动闪避与边缘可达性检查，不能仅画出好看的夹击 |
| 裂墨蚌 `ink_shell` | 慢弹在预示的中途节点裂成至多 4 枚小弹；提前御术／清弹可终止后续分裂 | 每母弹只裂一次；靠近玩家不突然分裂；反射后取消敌方分裂；子弹不再派生 | 当前闪避预测不知道未来子弹，需要共享分裂计划；同时涉及扫掠、事件顺序与收益去重 |
| 留印师 `seal_keeper` | 留下一个短时持续墨印，使部分闪避落点暂时危险，促使提前选位置或击杀来源 | 同场至多 1 个该类印；可先试预告 1.6s、生效 1.2s、半径 75–90、间隔至少 6s；不附带环弹；整印只结算一次攻击伤害 | 与 `mortar` 的区别须来自持续落点约束；若实玩仍只是延长爆区，则合并为旧敌变体，不新增物种 |

三个候选均不引入新输入键，也不使词咒成为临时机关密码。复杂弹幕首先作为单敌原型验证，通过后才进入正式池。

### 5.3 已有敌人与 Boss 的小幅强化

不同时重做全部 17 种敌人。先让 `ram / reaper` 的蓄力姿态、冲锋后恢复，以及 `sentinel / tower` 的移动／驻留身份更明显；已有机制不变的视觉强化不另算新敌人。

Boss 可以在新弹幕语法成熟后各突出一项主招：

| Boss | 建议主身份 | 组合方向 |
| --- | --- | --- |
| 吞墨巨像 | 沉重、间隔清楚的压迫 | 重弹环与单次落印分拍释放，保留接近和反击空窗 |
| 镜页织者 | 镜像、复诵与弧线节奏 | 左右弧线形成两拍，再给完整恢复段；不用继续堆射线补难度 |
| 大校对官 | 裁切战场与拆除保护来源 | 有限条带与护塔阶段交替，护塔不同时承担所有封路和射击压力 |

这些是攻击编排方向，实施时保留既有阶段伤害地板、援军与真实目标流程。先改变主次和时序，再判断是否仍需要新增形状；三位 Boss 不必各自实现一套独立弹幕引擎。

## 6. 遭遇编排方案

第一步采用少量页组合模板，继续复用现有行程、入场扇区与配额。只有模板不能表达实际内容时才增加更通用的生成规则。

| 组合模板 | 组成示例 | 玩家决策与约束 |
| --- | --- | --- |
| 点名与逼近 | 狙笔手＋`nib` | 在近身压力中识别单发；二者的首个威胁落点错开，不同时教学两种陌生攻击 |
| 两拍与转火 | 复诵者＋`split` | 先避开一组锁定弹，再利用输入空窗处理分裂；小型子体纳入实体与词位压力 |
| 拆除护卫 | 护卷使＋`quill`，后续才加入 `guard` | 先学会连线关系，再体验耐久目标；首次不叠加 `priest`，不制造互相保护链 |
| 弧线与直线 | `wisp`＋少量 `quill` | 通过弹头和尾迹分辨运动；减少总数量以补偿角度复杂度 |
| 定点与爆区 | `tower`＋`mortar` | 明确击杀来源可以解除部分场面；连续区域攻击间留下恢复空间 |
| 终章优先级 | 支援、封路、冲锋中选两类，再配基础敌人 | 不默认三类齐全，不把每一种“丰富”都叠在同一段 |

建议第一轮模板预算为：支援角色至多 1，区域攻击施术者至多 1，特殊时序远程至多 1；三者不强制同时出现。先替换原有名额，再观察是否需要增加数量。只限同种不足以阻止治疗＋护卫＋加速叠加，因此限制需按职责表达。

压力检查在模板选择、生成和特殊攻击开始前进行，不逐帧遍历所有攻击求最优排列。区域攻击的并发约束在预警出现前生效；预警显示后不悄悄延时或改变范围。双段序列按完整未来威胁安排，不能只预算第一拍。

首批为每个新职责安排一次保证出现的低压展示，后续才进入页变体池；这种保证不等于每局固定全部出场。重复游玩比较“遭遇过哪些机制、组合和时间结构”，不只统计资源种类。

## 7. 弹幕特效与辨识方案

### 7.1 统一的攻击视觉语法

保留[BattleStage](../ui/battle_stage.gd)已有的世界 HDR 与清晰信息层分离。弹头和真实危险轮廓留在清晰层；来源蓄力、命中碎屑和少量环境受光可以在世界层表现。新增装饰不能把弹头遮住，也不允许折射改变危险边界的位置。

| 对象 | 轮廓与运动 | 发光和材质 | 必须表达的规则 |
| --- | --- | --- | --- |
| 常规可御术弹 | 小而实的圆形墨珠，清楚亮核与窄边 | 一层柔和外晕 | 弹头可碰撞，尾迹无伤害 |
| 狙笔手来弹 | 圆形危险核外带短笔尖和定向尾羽 | 紧凑亮核，短尾，不拖出贯场亮线 | 保留真实圆形碰撞范围；笔尖装饰不能暗示整条线都伤人 |
| 弧线弹 | 暗心细环，顺真实路径的细长弧尾 | 金丝只做低亮结构，方向由移动的头部说明 | 弧线不是激光，不持续追踪，已走过的尾迹安全 |
| 重弹 | 更大的实核与双层短弧／厚轮廓 | 亮度适度增加，不能只用更大的模糊光团 | 半径与真实重弹匹配，仍可御术 |
| 双段攻击 | 来源上两枚可数刻点，按发射顺序消耗 | 同一配色和轮廓语系 | 第二拍提前可知，不能只用短促闪烁传递次数 |
| 区域危险 | 固定外边界＋低密度内部标记，预警阶段展示进度 | 暖红风险色，生效时短亮、随后退场 | 不可御术；填充圆盘不能画成中心安全的圆环 |
| 护卫连接 | 细、缓弯的叶脉线与受护端局部晶片 | 低亮中性色，不使用危险条带的实心形态 | 表示减伤来源，无接触伤害 |
| 反射弹 | 保留原类别形状，改变核心色并加简短反向反馈 | 沿用现有浅绿识别 | 来源已改变，仍沿真实路径命中；不能只靠颜色区别 |

各敌人主要通过形状、蓄力部位、节奏和运动区分。危险色保持稳定，不为每种敌人增加一种饱和颜色，尤其避免与四书效果混在一起。金丝用于结构，辉光保持柔和衰减；词咒周围不堆射线、粒子和循环装饰。

### 7.2 四阶段与减少动态

所有新攻击按“准备→锁定预告→释放／生效→恢复”制作连续反馈；冻结、打断、死亡也要有对应状态。预告进度读取规则时钟，不让 shader 自己计时后提前爆发。

减少动态设置停用装饰摆动、闪烁、额外流光和震动，保留真实弹体移动、固定边界、两拍刻点与必要进度。低画质保留同样的危险信息，优先削减柔光面积、装饰尾段与碎屑。

声音只强化“锁定、发射、第二拍、取消”的节奏，复用现有音频事件和素材库；同一时刻限流，视觉信息必须独立成立。首批无需给每颗普通子弹单独播放音效。

## 8. 性能优化的选择顺序

以下均为待测方案，不承诺未经测量的提速。优化中固定敌人、弹数、伤害、速度、寿命、碰撞与防御参数，避免将玩法减压混称为渲染优化。

| 顺序 | 方案 | 成本收益与采用条件 |
| --- | --- | --- |
| A | 区分直线／曲线尾迹需求；直线用少量端点，曲线按屏幕误差与长度重采样；复用每帧所需缓冲 | 对准当前逐弹数组和逐段计算；先核对插值头、反射拐点、暂停和缩放，不能让尾迹超前于弹头 |
| B | 把同一尾迹的逐段多层线改为连续条带，或减少重复几何提交 | 先比较 CPU 准备与渲染提交，保留连续性和柔和衰减；GDScript `draw_line()` 次数不等于 GPU draw call 数 |
| C | 按样式／混合层批量绘制同形弹头，共享纹理和材质；对比原生绘制与 `MultiMeshInstance2D` | 只有在密集弹场的实际提交成本有收益时采用；缓冲上传、透明排序和层级仍要测，不能只看节点减少 |
| D | 缩小无效透明面积、控制柔光半径与同时覆盖；命中碎屑按事件合并 | 针对填充成本。减少透明空白不代表硬裁软边，必须检查真实边缘和密集叠加 |
| E | 仅在发现生命周期分配峰值时，为短促装饰使用有限复用池 | 现有敌弹本身为 `RefCounted`，不是逐弹实例化重场景；不预先建设全局对象池 |

初始质量目标可设为：低档保留弹核、边界和短方向尾；中档增加一层柔光与必要弧线；高档补来源碎屑和少量局部受光。若采用曲线降采样，应以转弯处形状误差验证，而非统一跳过每隔几个点。三档的弹头位置、碰撞范围和预警时序完全一致。

首批不为每颗弹配置 `PointLight2D`、独立流体求解或屏幕折射。不把有伤害弹体改成不可逐个管理的装饰粒子；GPU 粒子只用于不参与碰撞的碎屑和烟尘。有限的复杂效果优先留给攻击来源和关键释放时刻。

### 性能比较方法

在需要实现优化时，先用现有窗口检查入口增加受控配置，比较 32／128／256 弹的直线、曲线与混合场景。256 弹用于压力对照，不是普通页的内容目标。固定随机种子、分辨率、画质、敌人位置与采样时长，预热后比较多段采样，排除截图回读及窗口失焦暂停。

分别记录 CPU 战斗步、敌弹绘制准备、渲染提交、可获得的 GPU 时间、整帧 p95／p99与峰值；自动闪避按键峰值单独列出。不要把嵌套区间直接相加，也不要用 headless 结果说明 GPU 提速。

采用门槛：在重复样本中改善目标瓶颈，幅度超出本机采样波动；稀疏场景无明显回退，画面与危险语义不退化。主机先做方向判断，P620 再做正式遭遇和长时验收。既有周期卡顿调查与本方案分开，不声称弹幕批量化能解决尚未定因的系统等待。

修改 GDScript 后，在批次边界使用锁定引擎 `--debug --check-only --script res://受影响脚本.gd` 检查警告与错误。静态通过、规则通过、窗口效果、真人体验和目标机性能分别报告；不因为写了候选资源或跑通机器人就宣称敌人体验完成。

真人验收重点是：看一轮后能否说清新敌人的特点；第二拍是否看得懂；打字被打断的原因是否明确；是否存在继续输入／转火／防御的合理取舍；是否经常被迫连续闪避而无法恢复；四书的优势是否来自机制而非某一书独占反制资格。记录失败场景与输入背景，不先设没有依据的统一识别率或通关率。

## 12. 敌人与飞行物开发通用经验

### 12.1 来源、状态和表现各有明确归属

实体交互要区分来源身份、当前归属与受效资格。引力、反射、连锁和范围效果不宜仅按空间距离决定作用对象；同来源豁免也不等于全阵营豁免。判断条件应放在拥有该规则的入口，避免通过提高速度、缩小范围等数值补偿掩盖交互错误。

行为切换应共享连续的表现状态。移动、锁定、释放与恢复使用同一朝向语义，目标角与显示角分开处理；冻结保持姿态，恢复后从当前姿态继续。减少动态可以关闭摆动和装饰闪烁，但应保留表达实际攻击方向的必要变化。

飞行物生成时保存足以独立存续的表现身份，来源销毁后仍能正确绘制。类型识别优先依靠轮廓、结构和运动，配色承担辅助作用；反射、强化与状态覆盖应保留原类别特征。

### 12.2 先定位合成层，再调整光效

| 表现职责 | 适合的处理 | 判断方法 |
| --- | --- | --- |
| 弹头、预警与危险边界 | 清晰的信息层，保持位置和轮廓准确 | 在复杂背景、状态覆盖与低画质下检查辨识度 |
| 发光核心、柔和外晕与光学尾迹 | 参与HDR合成的世界层，控制增益、宽度与衰减 | 同时检查世界纹理数值、最终软边和密集重叠 |
| 空气运动、尾雾与环境受光 | 共享流体场及有预算的原生灯 | 独立开关光学层与流体层，检查运动、注入、照明和消散 |

HDR颜色、后处理辉光与原生照明是不同机制。局部效果缺少光感时，应先核对所属视口、材质混合、输出链和受光关系，再调整亮度；不要直接提高全场辉光影响无关内容。像素超过显示白只证明存在HDR数值，不证明柔光质量或周围物体正确受光。

增强轮廓时要保留原有材质层次，增强发光时要保留识别边界。新加的丝带或粒子不能悄然替代已有流体过程。通过单独隐藏各层做对照，可以区分光学变化、模拟变化与遮挡问题。

画质、流体质量和减少动态分别按各自职责降级，不能从某个组合测试配置推导出它们应在产品中绑定。降级优先减少装饰成本和额外运动，保留真实飞行、攻击方向与危险信息。

### 12.3 尾迹由空间历史构成，网格连接要明确

尾迹长度需求先区分按距离还是按时间表达。需要稳定空间长度时，按真实位移采样并按弧长裁剪；需要表达残留寿命时，保留时间信息。固定帧数会把表现与速度、帧率绑定，单独增大绘制上限也无法补回缺失的历史。

规则步保存真实轨迹，渲染层接入唯一的插值头；曲线平滑和收尖仅处理显示，不改碰撞路径。连续运动保留历史，瞬移、对象复用或反射转折按实际语义处理，避免出现超前、折返或跨场连接。

对沿路径生成的带状几何，明确建立左右截面并连接相邻截面，横向UV跨宽度、纵向UV沿路径。整条边界交给自动三角化前，应考虑短段、急弯、自交和退化几何；不能忽略绘制错误来维持画面。几何连接、UV连续性和柔化采样需要在实际运动中观察，脚本静态检查不能覆盖这些问题。

核心、外晕和尾段的亮度应分开调节。以轮廓保留、柔和衰减和重叠可读性判断结果，不设跨素材通用的HDR峰值目标。批量网格只描述提交方式；是否更快，要在相同规则、输出和内容下测量CPU准备、GPU绘制及整帧成本。

### 12.4 造型细节服务于实际尺寸下的身份

先确定剪影、主结构与明暗体积，再增加切面、装饰和细线。不同敌人的细节应围绕各自功能组织，避免所有对象共用同一外轮廓、只替换颜色或中心图案。放大图中的精细程度不能替代实战尺寸下的辨识度。

在正式材质、背景与缩放下查看造型，检查状态覆盖是否保留本体特征，以及与头顶信息、周围弹体的视觉竞争。视觉边界变化时同步核对碰撞暗示和词咒避让；不要通过放大所有模型补偿结构薄弱。

### 12.5 验证覆盖因果与生命周期

检查应针对尚未确认的问题：规则测试确认作用对象与运动事实，实际窗口确认合成和连续形态，真人体验确认读懂与操作感受。静态帧不能证明持续流动，节点存在不能证明模拟推进，成功加载不能证明材质管线已准备。

观察动态效果应覆盖起手、持续、转折、退场与中断，按改动补充暂停、质量切换、来源销毁和场景退出。检查回收时先确认负责更新的节点已执行；帧开始信号不等于本帧所有处理完成。模拟源停止、残留物继续消散和资源最终释放是不同生命周期。

夹具应保证目标能到达待验证状态，隔离词条供给、提前死亡等无关干扰，并说明隔离条件。夹具参数不作为正式数值，替代入口通过也不代表原失败入口通过。优先复用最小相关检查，已有证据充分后停止扩展。

修复交互错误可能改变实际难度，即使没有调整数值。平衡评估需基于明确的源码版本，区分行为恢复、参数调整和渲染变化。共享工作区中应在补丁前重读上下文、局部修改并明确归因，避免将并行任务的变化混入结论。
