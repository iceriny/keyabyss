## 二、天赋现状

### 内容分布

四书各 22 个节点：1 个起点、12 个普通强化、6 个机制节点、3 个关键节点，共 88 个。另有八组共用内容，每组 4 个普通强化、2 个机制节点、1 个关键节点，共 56 个。

八组共用内容为合订、独卷、储备回收、分合、护持、词形、运输、易形。它们目前使用类似的内容生成模板；同样的模板数量不代表每组已经具有同样丰富的玩法。

### 实际分配规则

- 选中主书的起点自动取得，实际费用为 0；其他法书起点的登记价格是 2 点。
- 普通节点 1 点，机制节点 2 点，关键节点 3 点。
- 节点必须通过已取得的相邻节点接入，并满足能力前置、指定节点前置、互斥和预算。
- 关键节点最多 2 个，God Mode 也保留这项限制。God Mode 只取消预算上限，不取消图和前置条件。
- 撤点后，失去连接或前置条件的节点被重新剔除，花费返还。
- 合订开放一本副书；独卷与合订互斥。副书用于提供材料与能力，不开启第二套人工操作循环。

入口：[talents.ts](../../../legacy/web/src/content/talents.ts)、[分配规则](../../../legacy/web/src/shared/talents.ts)。

### 跨局与存档

普通进度从 2 点开始，每累计完成 120 个有效人工字符增加 1 点，最多 24 点。未完成的输入不计入该项成长；辅助完成部分不冒充手工字符。结算保留每局累计量和回执，防止重复发点。

当前图版本为 3。旧图配置返还为可分配点数，累计字符和结算记录保留。普通与 God Mode 分开存储；God Mode 清理不应清除普通进度。入口：[talentProgression.ts](../../../legacy/web/src/application/talentProgression.ts)。

以上是现有规则，不意味着 24 点、每 120 字一点、最多两个关键节点已经适合下一版长路径构筑。

### 当前成长连接

上一轮把每书组织为三条分支，并把八条跨书路线接到以下机制：

| --- | --- | --- |
| 合订 | 晶构 crystal | 蓄热 heat-payload |
| 独卷 | 短路分枝 storm-near | 复文 paper-inherit |
| 储备回收 | 余热回收 recovery | 回路 storm-return |
| 分合 | 析晶 frost-division | 导流 conduction-payload |

全图当前有 156 条成长路径。附录列出每个节点的实际双向邻接，而不仅是单侧声明的 `links`。

这是一份现状表，不是后续必须采用的八条流派路线。诸如“为什么独卷只挂在雷纸之间”“同一种保存法术机制为何分散在多条桥上”等问题，需要在后续步骤讨论。

## 三、遗物现状

### 内容分布与能力

稀有度为普通 92、稀有 39、诅咒 2、觉醒 7。36 件具有 `evolution` 替换关系，其中 12 件为仅事件获取的变体。

68 件独立定义覆盖直接伤害、连锁、冰冻、灼烧、纸灵、复写、防御、治疗、移动、词长、无错字、连笔、散字、共鸣、经验和觉醒。它们并不全部属于新组合系统；部分通过原有统计、伤害修正和施法钩子生效。

72 件扩展遗物分属：复写、装订、晶体、热量、电荷、几何、储备、碎片、运输、字母、防御、独卷。每族结构都是五件常规奖励候选加一件事件变体，包含基础件、强化件、两种互斥演化、连接件和事件变体；常规奖励候选中也有稀有遗物。

这种模板有完整的登记结构，但是否造成同质化，需要下一步审视；本步不将“12 族”直接等同于“12 套独立玩法”。

### 普通掉落资格

[eligibleRelic](../../../legacy/web/src/shared/relic-eligibility.ts) 当前检查：

1. 不是仅事件获取的遗物，且未达到最大层数。
2. 满足主书限制、持有遗物与层数前置、能力需求、词长条件。
3. 不与已持有遗物发生任一方向的互斥。
4. 若它只重复开启已有的某些布尔开关、且不再开启后续遗物路径，则过滤掉这件重复候选。

当前没有单独的“必须点亮某个天赋才能刷到此特殊遗物”字段。天赋可以通过提供能力间接影响候选池，但同类能力可能来自法书或遗物；这个机制无法完整表达用户新要求中的天赋专属解锁资格。

### 当前抽取方式

合格候选采用带种子的加权不放回抽取，通常展示三件。基础权重为 1：已有但未满层 +0.35，与当前能力有连接 +0.35，主书倾向 +0.15，觉醒 +0.35。同次选出一件后，其同族剩余候选权重乘 0.55，以增加展示差异。

这属于软倾向，不保证补齐某种构筑。现有软关联主要来自 `needs`、`modifies` 与当前能力集合，不是通用操作之间的深入组合分析。入口：[RewardSystem.ts](../../../legacy/web/src/simulation/progression/RewardSystem.ts)。

### 演化与公式

普通奖励演化会移除父遗物，再获得新遗物；互斥分支不能同时持有。事件变体则由事件选择当前持有的同族可替换内容，具体处理见下节。

遗物的 `grants`、伤害修正、获取/施法钩子以及部分动态数值公式共同决定行为。附录分别保留这些字段；不能只读取 `desc` 就认定数值或执行顺序完全准确。

## 四、事件现状

### 八类定义

| 类别 | 数量 | 当前主要作用 |
| --- | ---: | --- |
| revision 修订 | 3 | 替换同族遗物并附加规则 |
| loan 借阅 | 3 | 临时授予部分规则或数值 |
| bridge 连接 | 3 | 打开联动开关或加工方式 |
| smelt 熔炼 | 3 | 替换同族遗物，改变数值或规则 |
| archive 归档 | 3 | 替换与保留能力，部分预支后续奖励 |
| proofread 校勘 | 3 | 修改字母标记、分散与保存关系 |
| contract 契约 | 3 | 以生命上限、容量或后续压力换取效果 |
| trial 试炼 | 3 | 先承受下一房压力，完成后获得收益 |

这些类别名称不是八套完全不同的执行器。当前大部分都通过同一个事务系统施加 `grants`、扣除代价或替换遗物。

### 出现与选择

未使用过的事件，在满足能力、生命底线、部分天赋统计条件以及可替换遗物条件后，才进入候选池；在合格事件间随机抽取。

每个事件通常提供：

- 事件本身的“修订构筑”或“接受试炼”。
- 若生命上限至少 28，则提供“校订本卷”：本局最大生命 -3、法术威力 +2%。
- “保留原稿”：不改变构筑。

因此 24 个事件不是 72 套独立设计过的选择效果。绝大多数第二、第三选项相同；在生命条件不满足时，选项数也可能少于三项。

### 天赋与遗物如何影响事件

- `needs` 检查现有能力，可能由不同来源满足。
- `talentStats` 检查出征天赋本身是否提供指定统计之一，不能简单由遗物替代。
- `evolve + family` 寻找该族的事件专属变体；从当前持有、属于同一演化族的候选中，按预算优先、ID 次序选择替换来源。
- `nodeIds` 保存有关天赋和遗物的带命名空间引用，用于展示关联；这些引用不会变成实际天赋成长连线。

入口：[事件定义](../../../legacy/web/src/content/build-events.ts)、[BuildEventSystem.ts](../../../legacy/web/src/simulation/progression/BuildEventSystem.ts)。

### 生命周期与代价

选项在展示时冻结，提交检查报价、当前状态和是否已经提交；无效提交不应扣费或重复获得收益。事件可减少最大生命、占用未来奖励、提高下一房压力、替换遗物或提供限定期限的规则。

非试炼效果提交后写入活动记录；房间记录指向下一房。房级与章级效果在推进时到期；试炼先记录为等待，完成对应房间后才激活。事件不直接写入跨局天赋进度。

当前“借阅”授予的是事件规则覆盖，不是临时点亮某条天赋路线；不能在新方案中未经定义就把二者视为同一种权限。

## 五、三者目前通过什么组合

### 共享的七种能力

现有能力集合固定为 `cold / heat / conduction / carrier / guard / release / recovery`。它们用于能力收集、候选资格与关联展示，分别对应寒气、热量、电荷、保存法术、防御、释放剩余法术、回收。

法书与遗物提供声明能力；天赋提供自己的能力集合；有效副书也能提供能力。运行时还从部分天赋/事件数值推导保存、防御、释放和回收能力。详见 [能力收集](../../../legacy/web/src/shared/combat-capabilities.ts) 与 [CombatSimulation.ts](../../../legacy/web/src/simulation/CombatSimulation.ts)。

### 共享统计与固定执行步骤

天赋授予、遗物叠层和活动事件共同形成战斗统计；`compileBuild` 将其中一部分编译成固定结构的 `BuildProgram`。它包含复制、保存、提前释放、防御、接力、分裂、聚合、运输、回收等参数和开关。

人工有效字符在完词施法时贡献资源。当前很多材料按基础 12 字积累，并有领取和容量限制；复写成本、保存数量和时间等会被构筑修改。

片段持有来源与资源，拆分转移父份额，保存对象的主要出口只能领取一次；运行过程另有深度、执行次数、生命期和房间边界。这些是已有的有限性基础，而不是本次提出的新功能。

注意：当前机制不是“给任何对象添加任意标签就自然生成行为”。例如 `WeaveSystem.cast` 明确使用 `cold && heat` 判定组合碎片资格，`compileBuild` 根据元素选择固定主术形态；普通伤害、法书原生效果和组合系统也有不同的执行入口。

主要入口：[combat-build.ts](../../../legacy/web/src/shared/combat-build.ts)、[WeaveSystem.ts](../../../legacy/web/src/simulation/systems/WeaveSystem.ts)、[packets.ts](../../../legacy/web/src/simulation/spells/packets.ts)、[RelicRules.ts](../../../legacy/web/src/simulation/RelicRules.ts)。
